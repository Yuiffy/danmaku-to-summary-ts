# 可复用精剪流程

用于自动切片中的精选精剪，以及用户反馈后的按编号重渲染。代码入口是
`src/scripts/clipping/creative_runner.js`；配置、数据协议和具体参数见
[精剪流程](../../../../docs/clip-precision-experiment.md)。当前自动化只在配置允许的房间运行，
不是让所有普通切片都加密集特效。

## 如何判断与剪辑

1. **普通底版先完成。** 使用已有原字幕、人物审核、发布文案和 GPU 压制路径。
   全批结束后，AI 从完整候选中选最多一条值得精剪的内容。没有合适的可以不选。
2. **先定内容策略。** 用完整片内字幕和可追溯引用判断 `editorialProfile`：游戏、聊天、
   故事、教程、连续表演或混合；再定语气和效果密度。中性／严肃内容不套罐头笑声和轻快 BGM。
   连续表演保留乐句与段落；教程保留必要步骤。
3. **先剪内容，再排效果。** AI 选择按原顺序保留的完整字幕句组，并逐组解释用途。
   去掉重复、空转和无关支线，保留因果、指代、提问接话、反转和收尾。标题、简介、封面依赖的
   已验证事实和人物引用必须全部保留。不要为了固定时长或删减比例破坏内容。
4. **独立审核新时间轴。** 把原全文、保留内容和裁剪区间一起审核。机械校验不准断句、
   重排、越界或丢失受保护引用；模型审核内容是否仍完整。失败给具体问题并有限修订。
5. **按新时间轴找表达节点。** AI 根据保留下来的原话选择具体时刻和引用 ID：表情反应、
   反问、自我修正、关键操作、文字细节等。密集喜剧可多些节点；其他内容按收益选择，允许不加。
6. **看三帧再决定怎么加。** 每个节点看原画面开始／中间／结束，才能确认主体的位置。
   字幕只能说明说了什么，不能证明脸、弹幕或游戏物体在哪里。所有坐标相对单个源帧。
7. **先预检再渲染。** 用实际视频尺寸和生产 ASS 字幕检查所有节点的圆窗倍率与字幕空间，
   汇总问题后最多两轮定点修复。居中大头像聊天不强制转圆窗；放不下时依据原三帧换效果，
   不能靠缩小真实脸框或字号放行。相邻保留句组仅余量重叠时合并区间，不当作选材顺序错误。

## 如何摆放与混音

- **主体原位。** 放大头像留在原头像区域；放大弹幕或画面细节也尽量原地进行。不要把右侧
  头像移去左侧盖住弹幕。问号和反应贴纸围绕相关主体排放，空间不足时减少或省略。
- **主画面仍重要时用圆窗。** 游戏找路、解谜、操作是主要信息时，圆形面部特写保留主画面。
  圆窗要有实际放大收益；贴边大圆允许边框出屏，但眼睛、嘴和下巴须可见，人工补边只能在画外。
- **放大细节时保留表情。** 全屏关键点放大裁掉了人脸，就从原画面单独取脸，以原大小小圆窗保留，
  不把人脸再放大。若取景边缘残留半张放大脸，只在关键物体仍完整的条件下微调取景。
- **字幕最后烧入。** 已确认字幕的字词不变，重建新时间轴；布局冲突只调整烧录 ASS 的换行和位置，
  不缩小统一大字幕字号。滤镜、头像、贴图先合成，字幕最后叠上。
- **笑声按笑点轮换。** 只用素材库中来源和摘要已登记的片段；优先未用过的素材、避免相邻重复。
  小反应用短笑，明显回扣才用较强笑声或掌声。不同 ID 指向同一音频区间不算不同素材。
  笑声归一化后放在句尾或自然停顿，不靠压低原对白换可听度。
- **音乐按语气决定。** 喜剧可以用已登记／原创轻快 BGM 铺底，给对白留空间；表演原曲、中性
  解释和严肃内容不自动加喜剧音乐。音效和 BGM 的存在不能代替剪辑本身。

## 怎样确认真的完成

- 实际 MP4 时长和音画起点正确，完整解码通过。
- 对比解码音轨，确认原声保留、音效可测且不被掩盖、叠加没有削波；听感仍需实际查看。
  可选 BGM 导致原声保护或音乐能量检查失败时，程序最多自动去掉 BGM 重渲染一次；
  第二版必须重新通过完整音轨检查，不能通过调低检查门槛接受第一版。
- 独立模型查看原画与成片三帧对照、保留字幕及封面；核对主体、遮挡、字幕、内容含义和表达收益。
  可选滤镜/贴纸造成拒绝时最多定点移除一次，保持对白、时间轴和取景；重做预检、渲染及独立审核，
  不能直接改写失败的审核结果。两轮图片各自保存，第二轮仍失败则回退。
- 生产配置 `creative.allowCoverFaceOverlap` 保存用户允许封面文案遮脸的偏好，并写入版本历史；
  该项不阻断精切，正文画面遮挡、封面字词与可读性等其他 QA 继续检查。
- 保存计划、原始响应、失败原因、实际素材区间、原文件／成片摘要及审核结果。
  AI 请求返回成功或 FFmpeg 退出成功，均不等于精剪成功；失败回退应明确标为普通版。
- 每次用户反馈先定位具体问题，再修改可复用工具与针对性测试。旧已审核时间轴和原素材一致时
  可以复用选材／坐标，实际渲染与最终 QA 必须重新执行。

## 操作入口

```powershell
python src/scripts/clip_upload_registry.py precision --id 123 --note "按反馈优化精剪"
python src/scripts/clip_upload_registry.py precision --id 123 --resume-from "D:\clips\precision_revisions\123\r-example" --note "保持内容，仅改构图或混音"
```

结果是独立本地版本，原视频、注册表原始媒体和已投稿 BV 保留。用户明确认可成片并要求替换后：

```powershell
python src/scripts/clip_upload_registry.py replace-precision --id 123 --revision "D:\clips\precision_revisions\123\r-example" --review-note "用户已确认成片并要求替换原稿" --dry-run
python src/scripts/clip_upload_registry.py replace-precision --id 123 --revision "D:\clips\precision_revisions\123\r-example" --review-note "用户已确认成片并要求替换原稿"
```

替换验证编号、原素材、版本和 QA 摘要，编辑原 BV，保留原标题、简介、标签、封面及其他分 P。
`PUBLICATION_APPROVAL.json` 保存本次授权，`REPLACEMENT_RECEIPT.json` 保存文件上传和编辑回执。
提交成功后读取创作中心确认新 CID／文件；“修改内容待审核”不是已公开生效。
编辑响应超时留下 unknown 时先检查线上状态，不自动重发。未投稿 ID 继续走正常审核和上传队列，
不要用新投稿规避已有 BV 的编辑流程。
