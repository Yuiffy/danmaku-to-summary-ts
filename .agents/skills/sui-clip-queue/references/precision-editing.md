# 可复用精剪流程

用于自动切片中的精选精剪，以及用户反馈后的按编号重渲染。代码入口是
`src/scripts/clipping/creative_runner.js`；配置、数据协议和具体参数见
[精剪流程](../../../../docs/clip-precision-experiment.md)。当前自动化只在配置允许的房间运行，
不是让所有普通切片都加密集特效。

## 如何判断与剪辑

1. **普通底版先完成。** 使用已有原字幕、人物审核、发布文案和 GPU 压制路径。
   全批结束后，AI 从完整候选中选最多一条值得精剪的内容。没有合适的可以不选。
2. **先定内容策略。** 用完整片内字幕和可追溯引用判断 `editorialProfile`：游戏、聊天、
   故事、教程、连续表演或混合；再定语气和效果密度。中性／严肃内容不套罐头笑声和轻快 BGM。
   连续表演保留乐句与段落；教程保留必要步骤。
   普通直播的搞笑聊天、怪话与互动同样可以做精切，不能因不是游戏就只做普通截取。
   从具体原话和真实表情选择放大、罐头笑声或其他音效；先保留铺垫、接话与反转，
   再用效果突出笑点。用户认可这种表达方式不等于要求每条加特效，也不改变自动全批选片上限。
3. **先剪内容，再排效果。** AI 选择按原顺序保留的完整字幕句组，并逐组解释用途。
   去掉重复、空转和无关支线，保留因果、指代、提问接话、反转和收尾。标题、简介、封面依赖的
   已验证事实和人物引用必须全部保留。不要为了固定时长或删减比例破坏内容。
   新详细选材的 `topicEditPlan` 已标出完整话题外窗及 keep/drop 段；精切继承并校验这份计划，
   keep段（含后续例子、回应与收束）全部必留，drop段不得偷偷恢复。计划与原字幕摘要、实际素材窗口绑定。
   普通版先保留完整素材窗，是否加入特效仍由现有全批精切选择决定。
4. **独立审核新时间轴。** 把原全文、保留内容和裁剪区间一起审核。机械校验不准断句、
   重排、越界或丢失受保护引用；模型审核内容是否仍完整。失败给具体问题并有限修订。
   审核同时读取素材窗外的前后文，不能只看已经截短的底版。旧底版若截掉同题后续，
   应触发自动扩窗重切：从真实单条源字幕 R-ID 选边界，重新取字幕、烧底版、编号 C-ID 并重新审核，
   每片最多两次。原 keep/drop 与文案引用按原绝对范围保持保护，旧结尾保护不得延长到整个新窗；
   重切前独立复核新外窗；审核给出真实 R-ID 时直接扩大再核对，不能把第一个回答当话题结束。
   “需扩窗”标记须定位到真实 R-ID；已在素材窗内的缺句走 keep 修复，并给出对应 C-ID。
   成片审核指出片内漏剪时允许一次完整故事修复，再执行所有后续 QA。
   新增必要原话也必须保留。原已确认字词按时间绑定继承，无法唯一绑定时停止。
   每轮完整证据写入 `source-N/`；窗口变化使旧故事草案、审核、节点和坐标失效。
   最终人物绑定验证原始审核与整个扩窗证据链，不能单改审核起止冒充新批准。
   只有上下文不足、达到重试上限或新 QA 仍不通过时才回退，并保留原问题及修复失败原因。
5. **按新时间轴找表达节点。** AI 根据保留下来的原话选择具体时刻和引用 ID：表情反应、
   反问、自我修正、关键操作、文字细节等。密集喜剧可多些节点；其他内容按收益选择，允许不加。
6. **看三帧再决定怎么加。** 每个节点看原画面开始／中间／结束，才能确认主体的位置。
   字幕只能说明说了什么，不能证明脸、弹幕或游戏物体在哪里。所有坐标相对单个源帧。
7. **先预检再渲染。** 用实际视频尺寸和生产 ASS 字幕检查所有节点的圆窗倍率与字幕空间，
   汇总问题后最多两轮定点修复。居中大头像聊天不强制转圆窗；放不下时依据原三帧换效果，
   不能靠缩小真实脸框或字号放行。相邻保留句组仅余量重叠时合并区间，不当作选材顺序错误。

## 如何摆放与混音

### 对白节奏、动作与反应的切点复核

- 先确认观众能听懂“发生了什么、为什么继续、结果如何”，再删重复尝试。完整问题、否定、
  回答和指代可以横跨多条字幕；同义的完整铺垫允许择一，不能用 cue 数量代替理解判断。
- 对新跳切分别检查出点和入点附近的原音、原画。字幕结束不等于说话结束，字幕空档也可能有
  关键操作、吸气或表情。原音波形可帮助定位，游戏音乐或音效能量不等于语音，不能仅凭静音阈值自动切。
- 动作发生、结果显现、人物意识到结果可能处于不同时间。先确认这一组事实与反应，再决定是否缩短等待；
  不把后来的惊讶移到前面的操作上。对操作教程保留关键动作和必要解释，对连续表演保留乐句。
- J/L cut 用音画不同切点改善衔接，但单机位直播中的口型、游戏操作声与人物归属需要同步。
  先将其用于切点诊断；只有存在可验证的同一事件多视角或覆盖画面时，再单独设计音画轨道及审核。
  不把全片自动交叉淡化、固定节拍或配笑声当成精剪质量提升。
- 上游 topic keep 覆盖整段时，精剪阶段不能自行放松保护。若重复信息来自上游选择，回到选材与
  句组标注做独立对照；保留硬约束，明确记录当前阶段没有优化空间。

方法依据：Blackmagic Design 的 [DaVinci Resolve 官方培训](https://www.blackmagicdesign.com/products/davinciresolve/training)
与《The Editor's Guide to DaVinci Resolve 20》书页 88–90、154–155、185–195
（PDF 页 111–113、177–178、208–218），分别示范音画分切、按波形定位对白及反应镜头节奏。
实验入口与边界见 [开发指南](../../../../docs/development.md#精剪技能对照实验)。

- **主体原位。** 放大头像留在原头像区域；放大画面细节也尽量原地进行。不要把右侧
  头像移去左侧盖住弹幕。问号和反应贴纸围绕相关主体排放，空间不足时减少或省略。
- **弹幕逐条引用，不放大聊天列。** 观众反应用 `danmaku` 呈现：`scroll` 横穿画面、
  `bubble` 停在画面上方的圆角气泡；一次只讲一条，`text` 逐字取自真实聊天。
  放大聊天列默认关闭（会挡住战斗画面，框住三条也看不出重点），只有运营点名才开。
  放大只给岁己的表情/头像和画面细节。
- **符号贴纸不当填充。** 打怪、赶路、重复操作这类过程画面不要贴问号/叹号凑效果，
  这段优先用一条弹幕或人物表情。汗滴只在人物被拆穿、说不出话的那一刻贴。
  黑白/单色滤镜不默认使用，用户没点名就不加，情绪靠放大和贴图而不是调色。
- **形象贴纸用现成素材，不手绘。** 表情、汗滴、实物这类画面元素从 `config/clip-creative-assets.json`
  里挑已登记并校验过的透明 PNG（いらすとや 等免费素材），需要新素材就登记一条（含来源页、
  许可、sha256）再 `fetch`。不要用 ASS 矢量路径画图形，也不要用字符拼形状：手绘细节和风格
  都和成片不搭，改起来还慢。
- **主画面仍重要时用圆窗。** 游戏找路、解谜、操作是主要信息时，圆形面部特写保留主画面。
  圆窗要有实际放大收益；贴边大圆允许边框出屏，但眼睛、嘴和下巴须可见，人工补边只能在画外。
- **放大细节时保留表情。** 全屏关键点放大裁掉了人脸，就从原画面单独取脸，以原大小小圆窗保留，
  不把人脸再放大。若取景边缘残留半张放大脸，只在关键物体仍完整的条件下微调取景。
- **字幕最后烧入。** 已确认字幕的字词不变，重建新时间轴；布局冲突只调整烧录 ASS 的换行和位置，
  不缩小统一大字幕字号。滤镜、头像、贴图先合成，字幕最后叠上。
- **笑声按笑点轮换。** 只用素材库中来源和摘要已登记的片段；优先未用过的素材、避免相邻重复。
  小反应用短笑，明显回扣才用较强笑声或掌声。不同 ID 指向同一音频区间不算不同素材。
  笑声归一化后放在句尾或自然停顿，不靠压低原对白换可听度。
  完整读完笑点及末尾短词、致谢再开笑；程序最多与末字重合40毫秒。保留笑声完整自然的起音与衰减，
  不任意截成短促半声；素材截取点必须对应真实完整的一次笑声。原停顿不足时换较短但完整的素材、
  移到合适空隙或省略，不靠定格、暂停画面或截掉笑声尾部腾地方，不循环或改写原声。
  用户点名要笑声时只加这一次，放在整句说完之后、后面有至少 1.2 秒空档的位置，
  可以盖住紧随的反应停顿，不能压到下一句对白。
- **音乐按语气决定。** 喜剧可以用已登记／原创轻快 BGM 铺底，给对白留空间；表演原曲、中性
  解释和严肃内容不自动加喜剧音乐。音效和 BGM 的存在不能代替剪辑本身。
- **原片自带 BGM 时可以不叠 BGM。** 素材本身已有音乐（游戏配乐、直播伴奏）时，叠加会让听感变乱，
  此时用 `--no-bgm` 关掉后期 BGM，只保留原声与已选音效。关掉 BGM 不等于放弃音轨检查：
  原声保留、音效可测、无削波仍需实测。
- **过程段加速，铺垫与笑点原速。** 找路、重复刷怪、往返移动、读条等待这类没有新信息的段落，
  可以用 1.2–3 倍速压缩；需要"一闪而过"的快进感时可以到 3–10 倍，让观众看到动作但不陪着等待。
  setup、笑点（payoff）、反应、收尾和连续表演必须原速：加速会吃掉笑点的停顿与表情。加速按
  **绝对录播秒**窗口声明，程序吸附到字幕边界、按倍速重算成片时间。2.5 倍以下每条被加速的字幕
  仍须有 ≥0.75 秒可读时间；2.5 倍及以上该段原字幕不上屏，改由画面右上角的倍率角标
  （如「6× 快进 7s」，同时给出倍率与持续时长）标注，观众因此能看出这是剪辑快进而非卡顿。
  同样要求窗口内至少一半素材真的被保留，且不得覆盖受保护角色。
  倍速是剪辑决定，不是特效，不要用它替代必要的删减。

## 怎样确认真的完成

- 实际 MP4 时长和音画起点正确，完整解码通过。
- 加速段单独核对：抽加速段首／中／尾三帧确认画面仍有信息；角标在整段加速期间可见、倍率与时长正确，
  且不挡主体；2.5 倍以下段落成片时间里字幕能读完；音调没有明显失真（高倍速仍由 atempo 链保调）；
  铺垫和笑点回到原速，笑点的停顿与表情没有被倍速吃掉。
- 对比解码音轨，确认原声保留、音效可测且不被掩盖、叠加没有削波；听感仍需实际查看。
  可选 BGM 导致原声保护或音乐能量检查失败时，程序最多自动去掉 BGM 重渲染一次；
  第二版必须重新通过完整音轨检查，不能通过调低检查门槛接受第一版。
- 独立模型查看原画与成片三帧对照、保留字幕及封面；核对主体、遮挡、字幕、内容含义和表达收益。
  可选滤镜/贴纸造成拒绝时最多定点移除一次；可选放大框错位或裁切错误时可撤销该放大，恢复原画面。
  不改对白、时间轴或音效，不猜新坐标或改安全标记；重做预检、渲染及独立审核，
  不能直接改写失败的审核结果。两轮图片各自保存，第二轮仍失败则回退。
- 生产配置 `creative.allowCoverFaceOverlap` 保存用户允许封面文案遮脸的偏好，并写入版本历史；
  该项不阻断精切，正文画面遮挡、封面字词与可读性等其他 QA 继续检查。
- 保存计划、原始响应、失败原因、实际素材区间、原文件／成片摘要及审核结果。
  AI 请求返回成功或 FFmpeg 退出成功，均不等于精剪成功；失败回退应明确标为普通版。
- 每次用户反馈先定位具体问题，再修改可复用工具与针对性测试。旧已审核时间轴和原素材一致时
  可以复用选材／坐标，实际渲染与最终 QA 必须重新执行。

## 操作入口

```powershell
python src/scripts/clip_upload_registry.py precision --id 123 --note "按反馈优化精剪"
python src/scripts/clip_upload_registry.py precision --id 123 --resume-from "D:\clips\precision_revisions\123\r-example" --note "保持内容，仅改构图或混音"
# 过程段加速 + 不叠 BGM（窗口是绝对录播秒，须绑定本片编号）
python src/scripts/clip_upload_registry.py precision --id 123 --note "找路段加速" --speed-plan speed-plan.json --no-bgm
# 用户点名的本地片段（手工队列底片）必须先声明来由
python src/scripts/clip_upload_registry.py precision --id 123 --local-clip-note "用户点名这一段" --no-bgm --speed-plan speed-plan.json
```

`speed-plan.json` 形如
`{"version":1,"clipId":123,"windows":[{"start":11262.2,"end":11305.4,"rate":6,"reason":"找路无新信息"}]}`；
`clipId` 必须等于 `--id`，可选 `baselineMediaSha256` 锁住底片，底片变了就拒绝复用旧方案。
每段可写 `reason`，审核与成片说明会引用它。倍速段不接受 1 倍以下、超过 10 倍或没有理由的窗口；
2.5 倍以上会自动撤下该段原字幕，并在画面右上角叠加「倍率× 快进 时长」角标。

还可选运营指定字段（均为录播绝对秒或显式开关，程序兜底执行，模型改不回来）：

- `cutAfter`：硬切收尾时间戳，其后素材整段删除，成片精确停在该点（`endingHoldSeconds=0`）。
- `keepBeats`：`[{start,end,reason}]` 无台词表演保护区间（尴尬笑、叹气等），强制保留。
- `laughId`：指定罐头笑声素材 ID，替换模型自选；两个落点路径都会校验，未落实直接报错。
- `noDanmaku`：`[[start,end]]` 区间内节点不给弹幕卡候选。
- `noSticker: true`：全片禁用贴图效果（含汗滴），草稿强制剥离，提示词同步禁止。
- `radioDanmaku: true`：全部观众弹幕改由通用滚动弹幕层（`clipping/radioDanmaku`）按真实时间轴
  自动烧录，不再逐节点挑弹幕卡；底片旁必须有同名 `.xml` 弹幕文件。加速段内弹幕随倍速压缩
  时间与滚动时长，与画面节奏一致。QA 提示词会声明该层是运营要求，不按计划外效果驳回。
- `subtitleFixes`：`[{from,to}]` 运营核对的 ASR 校对，替换后同时写入烧录字幕与交付 srt。

结果是独立本地版本，原视频、注册表原始媒体和已投稿 BV 保留。用户明确认可成片并要求替换后：

未投稿编号在已有用户投稿授权且完成复核后，先运行 `select-precision --id ... --revision ... --review-note ...`，
再 `enqueue --ids ...`。它绑定同一编号的已审精切媒体，不新建编号、不覆盖普通底版；已投稿编号才用下列替换流程。

```powershell
python src/scripts/clip_upload_registry.py replace-precision --id 123 --revision "D:\clips\precision_revisions\123\r-example" --review-note "用户已确认成片并要求替换原稿" --dry-run
python src/scripts/clip_upload_registry.py replace-precision --id 123 --revision "D:\clips\precision_revisions\123\r-example" --review-note "用户已确认成片并要求替换原稿"
```

替换验证编号、原素材、版本和 QA 摘要，编辑原 BV。线上原标题追加 `（AI精切）`，简介正文后附
程序从最终渲染计划与音轨记录生成的精切说明，列出成片时间下的 BGM、放大、贴图、滤镜和后期笑声。
不额外请求 AI 写说明，不列出已取消的效果；标签、封面及其他分 P 保留。
`PUBLICATION_APPROVAL.json` 保存本次授权，`REPLACEMENT_RECEIPT.json` 保存文件上传和编辑回执。
提交成功后读取创作中心确认新 CID／文件；“修改内容待审核”不是已公开生效。
编辑响应超时留下 unknown 时先检查线上状态，不自动重发。未投稿 ID 继续走正常审核和上传队列，

### 罐头笑声的语义边界

罐头笑声默认不用，没有数量下限。它用于岁己本人说出反常识观点、并仍认真确信正确时的特定梗，须有原话和说话人依据。仅提到岁己不满足条件；瑞娅等其他主播的自嘲、嘴硬、榜单定语和普通反转不套用。全片零笑声是正常结果，不为效果密度或素材轮换凑数。素材须经实际试听认可自然起落与喜剧听感；登记来源、响度合格或轮换不代表好笑，未认可时宁可省略。
