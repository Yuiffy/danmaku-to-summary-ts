# 直播结束自动选材方案

## 目标

自动流程的目标是提高召回率并生成可审查的候选，不是把模型第一轮结果直接投稿。每一场直播结束后应留下三类证据：自动 `REVIEW.md`、残余 `RESIDUAL_REVIEW.md`、以及最终通过 `manual_clip_queue` 处理的任务。

## 分层流程

1. **数据就绪**：等待最终合并视频、可信 SRT、XML 弹幕和可用的情绪/声音事件 sidecar。文件缺失时保留诊断，不用空字幕猜选材。
2. **高召回候选**：并行收集全量上下文模型候选、字幕关键词候选、弹幕密度/反应词候选、情绪转折候选。候选生成阶段只负责召回，不能因为标题暂时不好就丢掉窗口。
3. **全局排序和去重**：结合故事完整性、弹幕热度、观点/反差信号、情绪事件和字幕完整度排序。对真正重叠的窗口去重；时间覆盖和同一主题的名额限制只有在本次任务策略明确要求时才启用。
4. **边界校准**：先用快速 copy 两段式粗剪和字幕边界校准，保留起因、反应和收束。只有旧 SRT 明显错位时，对候选窗口重新 ASR；不要把全场自动流程改成精剪模式。
5. **自动 REVIEW**：生成 MP4、SRT、封面、JSON 和 `REVIEW.md`，默认只登记短 ID，不自动上传。
6. **可选残余召回**：只有本次任务需要扩大人工复核范围时，才启用 `own_stream_residual_audit.js`；它排除已切窗口，以 90 秒窗口/45 秒步长综合字幕密度、弹幕数量、主题词和反应词，输出 `RESIDUAL_REVIEW.md`。它不是自动投稿器。
7. **人工确认入队**：确认任意候选后调用 `manual_clip_queue.js add`，选择 `small_sui` 或 `old_sui`，让统一 worker 负责烧录和封面。需要立即上传时才使用 `--auto-upload`。

## 建议评分

将评分拆成可解释分项，便于回看漏选原因：

- 故事完整度：是否存在起因、冲突/误会、反应和收束；
- 观众反应：30 秒密度、重复刷屏、反应词和弹幕持续时间；
- 内容看点：独特观点、口误、操作事故、可爱/离谱行为、明显反差；
- 情绪证据：惊讶、笑声、哭声等只作辅助，不可单凭情绪标签陈述事实；
- 字幕可信度：时间轴连续、实体词可辨、没有大段空白或明显漂移；
- 降权项：没有独立看点、相邻重复窗口、没有主播内容支撑的纯弹幕热闹。电影、感谢、歌曲和普通聊天不默认排除。

保留每个候选的分项和来源（模型全量、模型分块、弹幕热度、本地规则），在 REVIEW/通知中汇总来源计数。

## 防漏选和防重复

- 自动 `maxClips` 只限制首轮成片数量，当前默认 24；残余 `maxCandidates` 独立维护并且只在审计启用时生效。
- 不强制时间覆盖；如果本次任务要求覆盖不同时间段，通过 `selectionPolicy.requireTimeCoverage` 打开。
- 已选窗口及其直接相邻覆盖范围只有在残余审计启用时才排除，防止同一句话进入两个队列。
- 需要排除特定内容时，通过 `selectionPolicy.excludedCategories` 指定，而不是把规则硬编码进通用 prompt。
- 情绪权重不要只奖励愤怒和惊讶；平静但故事完整的生活闲聊仍应由模型全量候选或残余审计召回。

## 运行和回归检查

- 自动切片结束后确认 `REVIEW.md` 与 `RESIDUAL_REVIEW.md` 都生成；审计失败不能阻塞已生成的自动 REVIEW。
- 抽查至少一条模型候选、一条热度候选和一条残余候选：视频时长、SRT 首尾时间、字幕烧录和封面来源都要正确。
- 对旧录播的错误字幕只做窗口级重新 ASR，记录原 SRT 和新 SRT 的来源；不要全量替换历史字幕。
- 用户说“已在队列里、不用检查”后停止状态轮询，上传 worker 继续自行处理。
