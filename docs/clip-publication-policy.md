# 岁己切片的发布取舍

自动召回继续最多选择 50 个完整事件；在边界校准、重叠去除之后、人物复核和视频制作之前，
单独决定本场优先制作哪些独立稿。`maxClips` 是召回上限，不能再把候选数量当作建议投稿数量。
筛选不授权投稿，既有人工确认、字幕、人物归属和上传门禁继续执行。

## 人工明确授权是线上编辑前置条件

凡是会改变 B 站线上稿件或其发布状态的操作，都必须先得到人的明确指令，不能从“准备”、
“部署”、“审核”、“生成”、“改一下”或上下文推断授权。这里的线上编辑包括但不限于：
修改标题、简介、标签、封面、可见性、分 P，替换视频或字幕，以及删除、恢复、重新投稿和
加入投稿队列。自动识别、自动审核、生成预览和本地成片可以继续进行，但只能产出待审核结果，
不得据此直接编辑线上稿件或投稿。

明确指令应直接覆盖目标和动作，例如“可以编辑这个稿件”“可以替换 BV… 的视频”“可以投稿
编号 123”。只说“部署”“准备好”“review”“修一下”时，仍停留在本地准备或待审核状态；
如果同时包含修改意见，先完成本地结果并等待单独的线上操作授权。授权只覆盖用户明确指出的
稿件、版本和动作；遇到其他稿件、替换线上内容或新增分 P，必须重新确认。所有线上操作在执行
前再次核对目标 ID/BV、当前版本和公开状态，并保留操作回执。

## 审核通过后自动投稿

`ownStreamClips.automaticPublication` 的 `mode` 支持 `off` / `auto`，默认配置为
`off`；生产为岁己启用 `auto`，`roomIds` 仅包含 `25788785`。`policyVersion`
为 `own-stream-v1`，`activatedAt` 记录首次授权生效时间，`authorizationNote`
保留用户授权范围；并发由 `concurrency` 控制（当前为 2）。最终复核沿用
`enhancements.stageDefaults` 和 `enhancements.stages.qa` 的模型配置。

岁己房间 `25788785` 的新自动切片启用自动投稿：最终审核明确通过的成片进入现有
单实例上传队列；未通过、审核不可用或证据不完整的条目保留候选编号，等待人工处理。
这是独立于下文选材分数/数量取舍的成片发布门禁。选材高分、人物审核通过或单独的
`uploadReady` 都不足以自动放行。

最终审核针对实际成片及其字幕、封面、公开文案和来源证据。审核结果与当前文件及
文案绑定，入队和 worker 上传前重新校验；任一内容变化、证据缺失或实质问题未解决都
停止自动投稿，后台制作完成后保留源录播供异步校验。审核读取完整保留字幕、完整
媒体解码结果和最终视频抽帧；抽帧不等于全片逐帧审阅，也不证明已经听审。需要原音
或连续动作才能判断的核心事实疑点仍交给人工。普通版和精切版分别以最后保留的版本为准，不能把精切尝试失败当作
精切审核通过，也不能沿用已被替换版本的审核结果。既有有限次自动修订继续运行，
仍有实质疑点时交给人工，不无限重试强行放行。

切前和成片 AI 共用事实影响标准：允许少量不影响理解、事件事实和公开文案的 ASR
同音错字、语气词、口语断句及非核心模糊短句，不为这些问题追加 ASR 或重压。
片内已有正确重复且整段无歧义的名词，单处缩略/同音误写不视为换了讨论对象；
局部解释漏字或连接句错字，若其他原话仍完整传达主线且不影响关键事实，也不单独阻塞。
先确定主线和文案承诺，再判断疑句是否改变它；附带例子、比喻或即时反应的一处模糊表达，
其余原话仍讲清主线且文案不依赖它时通过，不因有趣台词本身升级为核心事实。
实际音轨与字幕属于不同话题或持续错位仍必须阻塞。
人物归属、关键数字、否定、条件及主要内容无法理解仍阻塞。标题、封面和简介允许
有依据的概括，重点检查实质事实误差和夸大；“或许住一个月”保持不确定语气，不因
少了同义的“考虑”单独阻塞。允许小错不确认或修改原词，也不生成人工批准。
阻塞理由最多两条短中文，每条六十字以内，说明具体事实影响。

`subtitleProofreading.advisory` 中只有 `possible_foreign_audio` 提示时允许进入最终审核，
不把检测到外语等同于字幕错误。审核必须逐组说明其为不影响主线、文案不依赖的背景播放，
保存 `resolvedSubtitleAdvisories` 及完整 `subtitleAdvisoryEvidence`；这只判定事实影响，
不代表听过原音或确认转写正确，不改字、不删除提示。关键外语、来源不明及其他疑词仍阻塞。
入队和提交前重新校验每组覆盖、原提示及窗口，旧审核没有显式逐组结论时不放行。
拒绝候选重新规划时，整段游戏/歌唱/观影存档不与独立看点切片互相排斥；普通看点之间仍查重。
观影画面自带的电影对白字幕与大字主播评论是两层独立发言；电影切到下一幕而主播继续
评论上一幕不构成字幕错位。错位须比较主播字幕、对应原话/原音，不以电影对白不同为证据。
显式 `cut --automatic-review` 即使最终待核也登记新成片到原 ID，继续后续候选；
不会把已制作片段留成过期的 `pending_rebuild`，也不会因此授予投稿批准。

文案问题无论被模型归为内容、人物归属还是封面视觉，若每条具体问题都只涉及公开
文案、字幕和排除项已经通过，可有限次自动改文案并重做封面，再对当前产物独立复核。
实际字幕、政策、边界、连续动作或音轨问题不能通过改标题放行。仅缺失/过期的人物
审核或必要质检由流程补跑，保留 `attributionRequired` / `qaRequired`；不要求人工
代替缺失的 AI 阶段。质检使用当前完整字幕、真实封面/成片抽帧和媒体检查，明确获得
新的逐项 verdict 后才保存 `qaResult`。它与最终发布审核分开判定，共用一次媒体解码
和抽帧，避免重做视频、全场 ASR 或反复包装。相同产物的失败质检不盲目重试。
质检绑定视频、字幕、封面、文案四项；额外局部音频证据由最终发布审核独立绑定。
普通片人物和最终审核共用窗口内的原始 ASR 行投影：跨边界的字幕分组按完整原始行
拆开，编号仍来自原始行索引，原源哈希和逐行声纹不变。完整保留的首尾句可被引用；
被截掉的字句仍仅作上下文，不截词、改字或把窗外内容变成片内事实。人物审核中的
动物、昆虫和物品写入动作，不要求其实名；人物归属校验继续执行。
最终审核同时接收配置中的声纹登记名/人物 ID 与公开昵称表，并读取 G 分组内每条
`cue.items` 的声纹观察。别名表只解释名称；必须仍有对应原话的逐行测量支持，不能凭
昵称、主播名单或弹幕授予发言身份。已有声纹支持的登记名与其公开昵称不重复要求人审。
仅封面文字遮住主体/布局有问题且其他检查已通过时，自动重做一次封面并重新复核；
文案不变时复用已经通过的人物证据。封面从原录播的同一窗口取帧，遮挡问题改用下部排版，
保留视频/SRT 和必需审核条件；相同修订不会反复重做封面。
讨论下一部电影与背景正在播放的电影分别核对；观众弹幕/电影角色的亲属称呼不当作
主播现实家庭经历，排除仍以实际人物和话题为准。
身份未核时可去掉无依据的主语，但修订不能新增当面交流、搜索等场景或动作。
旧文案错误地写成提问时，人物复核可显式更正为源文支持的设想/陈述，但须保存
`originalQuestionCorrection` 的理由、完整字面原句和属于修订动作的片内 G-ID。
没有该证据的修订仍不得悄悄把真实提问改成确定事实；旧文案不视为源文真值。
观影评论中对角色说“你”，不证明角色与说话人面对面交流；按原话保留吐槽看点。
岁己房间仅排除负面或争议性的现实家庭关系，包括吵架、冷战、指责、财务纠纷和隐私冲突。
普通家人提及、童年坐车、无冲突的成长经历和日常回忆允许；晕车主题提到坐爸爸的车
不属于家庭矛盾。各阶段只按配置的具体范围判断，不因亲属词扩大排除，其他房间的明确限制仍有效。

自动发布记录保存在成片的 `automaticPublicationRequired`、`publicationReview` 和
`publicationDecision` 中；批次 `automaticPublication` 记录此次自动处理状态与入队
编号。审核 `passed` 和决定 `auto_queue` 同时成立才进入自动队列，`needs_human`
保留待核，`rejected` 不自动投稿。人工核对后仍可按现有编号命令保存复核并明确入队。

企微使用按上传 ID 升序排列的完整切片列表，清楚区分“已投稿”“已排队投稿”
“待入队”和“待人工复核”。这些状态以注册表为准，入队成功不写成投稿成功。
自动入队被拒绝时列出原因；回执丢失标记“入队结果待确认”，先核对队列而不重复
入队。重复素材关联既有 ID 并标记跳过，不再次要求人工批准。
普通切片与精切处理结果合并在最终清单内，不再为精切提前发送普通版清单；上传
worker 不逐条发送成功消息或 BV 号。通知失败不重投视频，结果不明确的通知保留
回执，不自动重复整批发送。长清单仍可按企微字节限制拆分。
普通和关键词清单每个候选之间保留空行，候选内仍提供短中文理由、SRT 节选和观众弹幕。
普通清单附带低分及其他未入选话题的 R/P 编号、原分数、主题和短理由；已补切项标明
关联上传 ID，仍保留原筛选决定。`deferredSelectionHistory` 独立保存同源直播的历史筛选，
时间轴修复及刷新不会覆盖它，也不继承旧审核或投稿授权。旧字幕窗口标明待校准，补切须
重新定位。边界拒绝保留原主题和草稿窗口；旧无名条目可从同源排序请求恢复
`reviewPresentation`，只提供查找线索，召回范围不代表批准的裁切边界或公开文案。
未校准的召回范围只显示保存的原话，不按旧时间读取 SRT 或配附近弹幕，避免把另一话题
当作复核证据。排序请求同时生成短话题标签与中文理由，供未入选清单直接展示，无需另跑摘要模型。
排序也比较相隔较远的同题片段：事件和看点重复时留完整清楚的一条，未选理由注明保留编号；
仅人物或关键词相同、实际事件与收束不同的片段仍可分别入选。旧排序响应保持可读。

此开关只用于启用房间之后新产生的自动成片，不扫描补投历史 ID。早于 `activatedAt`
的成片和旧计划重放不会自动投稿；在途任务仍使用启动时的配置快照。`clips:review`
刷新、`import-json` 编号登记和旧计划导入本身都不授予自动投稿；旧素材仍须明确
审核与投稿授权。已上传 ID 不再次排队，原有任务去重、限流重试和失败隔离继续
生效。人类发现线上异常可以直接在 B 站修改；自动流程不会覆盖线上标题、简介或
视频的人工修改。关闭自动投稿后恢复“成片待审核”的默认流程。

### 异常源字幕的时间轴恢复

普通片和关键词片的最终复核、自动入队及提交前验证都会读取源字幕的 `.asr_meta.json`。
Paraformer `sentence_info_fallback` 属于已知不可靠时间轴，模型通过、技术解码成功或轻微
ASR 错字容忍均不能解除该阻断。普通正常 ASR metadata 也随源证据绑定，复核期间变化
使结果失效。完整解码验证媒体可解码，静态抽帧验证画面；它们不证明声音与字幕主题一致。

既有数字 ID 可用 `rebuild --transcript-record` 接入已验证的校准转写，随后
`cut --automatic-review` 从原录播重建并执行新独立文案/成片复核。修订保存旧成片、源窗口
和 metadata 历史，清除旧时间轴的审核和 cue ID；新渲染收据绑定视频、SRT、窗口及校准
证据。重建后另从新成片实际音轨提取最多 120 秒、每段不超过 30 秒的无提示双模型
转写，供最终审核核对主题、时间与字幕对应，不用于猜测人物或修改字幕。该证据在入队
和提交前再次验证。只修改 SRT 路径或标签不能继承批准。该路径不创建人工批准；已投稿 ID 只允许
本地修订，替换原线上稿件是单独操作，须保留现有隐私状态和人工线上修改。
已采用同一校准字幕的后续文案/边界修订也可复用该转写描述符，但重新验证原来源及
各侧车哈希、重新渲染和核对新音轨；旧时间轴的精切计划、边界请求和音频/质检结果
随旧 metadata 保存，不作为新普通成片的审核依据，必需复核标记仍继承。

自动制作前识别已知 Paraformer `sentence_info_fallback` 对齐异常，仅在该异常出现
时重建分段转写与声纹侧车，保留原录播/SRT。最终审核接收完整 G-ID 行、原 ASR
与逐行声纹观察；`row_supported` 的测量证据仍按本行使用，`identityVerified:false`
表示没有人工认证，不能直接解释为本行声纹匹配失败。未知/拒绝行不会继承主播身份。

已制作但全部待核的本场可使用 `own_stream_clipper.js --repair-timing
--transcript-record <RESULT.json> --revision-note <具体原因>`，同时传原 media/SRT/XML。
该操作只恢复原计划的既有候选，靠独一的原文锚点提出新搜索区间，再重新细编、边界
与人物复核、渲染和当前成片最终审核；锚点不提供批准。未定位或未通过的原候选
保留待核，配置中的负面或争议性家庭关系等排除仍有效。metadata 路径、原数字 ID 保持，旧视频及
计划先备份，新媒体写独立修订目录。已批准、入队、发布的 ID 禁止此恢复。

### 关键词切片的独立授权范围

关键词/话题切片使用 `clipTopics.automaticPublication`，政策版本为 `topic-v1`，
范围为 `scope: "configured_keywords"`。生产 `mode: "auto"` 沿用现有关键词来源
房间，继续排除 `ignoredRoomIds`；默认配置为 `off`。它不共用岁己房间 allowlist，
也不凭旧 `clipTopics.autoUpload` 直接投稿。

新制作且晚于该策略 `activatedAt` 的预审 `ready` 成片，必须通过当前文件绑定的
独立最终复核，再以原数字 ID 进入同一个上传 worker。最终审核还核对关键词、身份
判断和预审修订证据；无最终成片的待核候选不因开关改变而自动烧录或投稿。
历史导入、手动修复和旧计划重放不继承授权。通知继续合并到原有话题切片列表，
不增加逐片成功消息或 BV 链接。具体协议见
[关键词切片最终审核后自动投稿](topic-event-editorial.md#关键词切片最终审核后自动投稿)。

### 最终审核后的普通片边界修复

新制作的普通 own-stream 成片若技术、人物、字幕、画面和政策检查都通过，仅因
片头/片尾不完整被最终审核拦住，会进入 `ownBoundaryRepair` 的有限工具循环。
模型每轮返回一个结构化动作，由程序校验后执行；不提供任意文件、shell 或投稿工具：

- `read_context` 补读同一来源的连续字幕，初始为片前 30、片后 60 秒，每侧最多
  600 秒，最多两次；不抽样删行，新增证据不得超过 60000 字符，完整请求不得超过
  80000 字符。无新增原文、超预算、无效动作或服务失败保留具体待核原因。
- `recut` 用已读 G-ID 提出窗口，只能修复原看点。复用现有细编及独立边界审核，
  该次细编不递归重试；再过人物和切前源内容复核，使用资源调度器与标准字幕烧录
  生成独立目录中的新视频、SRT、封面和文案。最多一次重裁，不重跑全场选材。
- `hold` 明确记录缺失证据、需要复听或无法独立成片的原因。

普通成片保留完整外窗，片尾夹带的新问题也必须有回答，或退到提问前真实的完整
句边界；不能假设内层精剪会删掉它。3175 的“冰火是啥”后漏掉回答属于此类。
重选不得丢失与原窗口的交集、超出已读范围、复用相同窗口或与本批其他保留片重叠。
新片继承必要审核标记，重新完成当前成片最终审核后才可能沿原授权入队。

`automaticBoundaryRepair` 在外部调用前持久化，记录工具动作、补读 cue IDs、旧窗口、
旧审核、旧输出及新修订路径；中断和失败不会在同一成片上自动再次开始。旧媒体保留，
成功修订仍使用原 metadata 路径和 review index。新独立审核失败的修订留待核。
已有数字 ID、发布记录、人工审核、已确认改词或精剪时间轴不进入此自动路径；
历史 ID 继续用既有重建命令，不因本次升级批量重裁或投稿。

此逻辑属于编译 workflow。验证仅生成候选 release；旧活动 release 缺少该入口时
保持原审核行为，损坏 release 则报告错误。启用须另行按部署合同激活。

## 默认策略与回退

`config/default.json` 与 `config/production.json` 的 `ownStreamClips.publicationPolicy`：

```json
{
  "mode": "curated",
  "roomIds": ["25788785"],
  "minScore": 90,
  "maxStandalone": 5,
  "standoutScore": 92,
  "hardLimit": true,
  "bundles": {
    "enabled": false,
    "minScore": 70,
    "protectScore": 90,
    "maxGroups": 2,
    "maxMembers": 3,
    "maxSeconds": 300,
    "minCombinedScore": 85,
    "minScoreGain": 5,
    "maxCandidates": 20
  }
}
```

| mode | 行为 |
| --- | --- |
| `all` | 恢复原模式，所有通过原流程的候选继续制作 |
| `score` | 仅按 `minScore` 筛选，不限制数量 |
| `curated` | 先过分数底线，再按全场分数优先保留 `maxStandalone` 条；`hardLimit: true` 时高分也不能超额，缺省软预算仍兼容高分保护 |
| `shadow` | 计算与 `curated` 相同的建议，但仍制作全部候选，便于比较 |

只对 allowlist 中的房间生效；缺少该配置的调用者保留原行为。日常 CLI 可用
`--publication-mode all` 临时回退。长期回退将配置的 `mode` 改成 `all`。
该回退只关闭本节的分数/数量取舍；已启用的同题核查与自动投稿精切要求继续生效。
被同题核查暂缓的候选仍写入待选库及 Web，可通过人工选择流程制作、投稿。
新启动的后台切片进程读取磁盘配置；已启动进程使用自己的配置快照，不改变正在处理或已排队投稿的内容。

只比较明确标记为模型全局重排、全量或分块选材的 0–100 数值分数；有全局分时优先使用全局分。
弹幕热度、候选池回退、缺分、无效分数不硬套这个尺度，保存在待选库。
同分按原时间和原序号稳定取舍；不按内容类别设配额，不凑满，不以时长淘汰完整独立事件。
高分保护只是编辑信号，不是爆款保证；分数尚未经过播放结果校准。

当前选择保留详细编辑，再做发布取舍，因而节省后续人物复核和制作开销，不能声称减少召回或细编请求。
这个位置也避免把仍需边界修正、最终会重叠的窗口提前挤进发布预算。

当前岁己制作准入底线为 90 分，每场最多 5 条，允许零条；高分不再突破本场上限。
账号现有注册表/worker 的滚动 24 小时保护上限为 25 稿，人工选中的稿件也遵守这个账号总量保护。
其他房间继续按 allowlist 外原模式执行，历史落选项不会因改阈值自动补切或入队。

### 同题核查与人工候补

`clipCuration` 在生产启用，覆盖 `roomIds` 中的主场和 `includeKeywordTopics` 指定的关键词来源。
两者在制作前共用严格价值复核及有界 B 站检索：最多复核 50 个候选，每个给出 1–2 个具体事件搜索词，
并补充确定性标题/原话搜索，具体上限由 `maxSearchQueries` / `maxSearchResults` 控制。原题材/标题相似不能确认同题；仅当其他 UP 的完整平台字幕与原话相互印证，
至少两条不同共同引句及起因、发展、结果引用均通过，才标记 `covered` 并让后续候选补位。
这是有界字幕证据核查，不代表看过对方视频或全站没有同题。缺字幕、可能同题但证据不足、请求失败均保留待核。
搜索词不再只依赖模型返回：流程会在模型词之外补搜“主播＋候选标题”和“主播＋源字幕中较有辨识度的原话”，
最多使用 `maxSearchQueries` 个词、每词最多 `maxSearchResults` 条结果。这样标题改写、口语说法不同或模型漏给搜索词时，
仍有机会召回已有成片。召回结果会把 BV、标题、简介、发布时间和状态写入 `curation.matches`；对方没有可读平台字幕、
读取失败或同题证据不足时，状态为待人工核查并保留 B 站链接，不会误判为“没有同题”。Web 审核页的“审核证据”会直接列出
这些链接和实际使用过的搜索词。只有 `covered` 才会阻止自制并执行配置的点赞、收藏、转发；`needs_review` 仍保留候选供人工决定。
同题核查独立于关键词切片的预审状态：只要候选窗口有完整源字幕，就算预审仍为 `needs_review` 也会先留下外部候选线索；
这不会解除预审、字幕、人物归属或最终投稿门禁。
`peer_coverage/` 下每次使用独立证据文件；源 SRT、窗口及报告摘要绑定成片，重新核查不覆盖先前证明。

`supportActions` 可配置 `like`（点赞）、`favorite`（收藏）、`repost`（转发动态），
默认及生产配置为 `["like", "favorite", "repost"]`。
更新旧运行环境时先验证、激活支持转发的 workflow release，再启用该配置并在队列空闲时
重启切片 worker，避免缓存旧 release 的进程拒绝新枚举。
自动流程只对确认覆盖的其他 UP 执行，关键词切片共用此流程。
账号级 `data/runtime/clip_peer_support.json` 保存目标身份、查询和写入意图，默认每天至多支持 10 个视频、
间隔至少 60 秒。互动前保存覆盖决定，互动失败不会恢复自制重复稿。未知 POST 不自动重放；
异常暂停一小时，残留锁需检查进程/回执后再由操作员恢复。这里不包含评论或投稿授权。
转发前在原 UP 最近至多三页动态中绑定作者、BV 和 aid，再转发对应原动态；
读取本账号最近至多三页动态核对转发状态。动态编号始终使用平台字符串，
保存原动态和新动态回执；查不到原动态或写入结果不确定时不猜目标、不自动重发。
与点赞、收藏共用账号级持久化意图及额度，重启或主场/关键词交叉命中不会重复发送。

投稿前自动门禁只在管理工作台真正执行“入队投稿”前运行一次，不在候选生成或制作阶段重复搜索。
它把源 SRT 的 SHA-256、源窗口、主播/房间和当前文案摘要绑定为缓存键；确认 `original` 的结果缓存 2 小时，
确认 `covered` 的结果缓存 24 小时，接口失败、登录态失效或限频结果缓存 30 分钟并暂停投稿。
缓存命中不会再次请求 B 站。投稿前门禁先用“岁己”（可由配置覆盖）按发布时间抓取一份共享的近期结果索引，
同一份索引供多个切片复用；索引只保持 2 分钟新鲜，过期才重新抓取，因此不会用数小时以前的空结果挡住刚发布的视频。
每次门禁只刷新一个广泛搜索词，同一词至少间隔 2 分钟，账号搜索之间至少间隔 30 秒，每日最多 30 次搜索；
超出限制会保留待复核状态，不会把失败当成“没有同题”。
确认同题时先持久化证据，再按 `supportActions` 执行点赞、收藏、转发，随后阻止入队并在 Web 审核证据中显示命中、互动回执、缓存状态和暂停原因。
`original` 才允许继续入队；`needs_review`、`covered` 和 B 站不可用均需要人工决定是否稍后重试。
只读接口探测：`npm run clips:peers -- --probe "岁己 具体事件"`；独立 manifest 核查缺省不互动，
须显式 `--support` 才互动，且不写投稿队列。

自动主场及关键词均配置 `editorialStyles.mode: precision`、`requirePrecision: true`，
最终自动审核再要求精切、画面与音轨复审完成。精切失败保留普通底版，停止自动投稿。
Python 入队/上传复核同时约束旧库存，缺少当前严格选材和同题证据的普通自动稿不能自行流出。

这些门槛仅约束自动投稿。候补不删除：主场将发布取舍中的 deferred 保留成原编号候选，
关键词保留 `pending_preflight` 草稿；Web 列表显示原因和同题证据，支持成片预览或原录播窗口回看。
已有普通版可人工选择直接投稿；未制作候补按原编号制作后投稿，无须补过自动分数或强制精切。
Web 的显式选择复用 `--feedback-authorized` 和绑定当前源、窗口、视频/字幕/封面/文案摘要的
`ownStreamHumanReview`。仅有布尔标记不放行；素材变化后原人工选择失效。
真实制作失败、待重建、同 ID/本账号重复投稿、内容排除和账号频率保护继续校验。

## 待选库与可重复预览

渐进通知保存历史前先绑定结果中唯一的来源，避免空来源生成另一份 P 编号。
历史空来源记录只有在候选编号、边界、标题、分数、理由及证据摘要完全相同且仅对应
一个明确来源时才合并展示，旧选择键保留为别名以查找补切记录；多来源或不同事件不合并。

详细编辑重试和边界校准可能重复记录同一条拒绝。审核清单按其持久化元数据路径
折叠重复项，保留原审核索引与数字 ID；不同元数据共用索引仍拒绝登记，不能靠
重新编号掩盖冲突。修复前已卡住的批次可用 `clips:review --plan PLAN.json` 恢复
清单与编号，复用已有成片和审核；该命令不自动投稿，恢复入队仍需原授权及当前审核。

企微先列需要处理的候选 ID（复核、制作/入队/投稿异常），已投稿或在队列中的项目不再要求批准；
主清单按上传 ID 升序显示，时间仍列在每项内。被剔除项是按需恢复，不要求逐个审核。
批次中断时明确显示处理失败；空返回代表候选统计尚未完成，不能显示为成功的零候选或
“无需人工处理”。已有候选仍展示各自状态，但标明清单可能不完整。批次错误优先展示，
保留限长、去凭证的原始错误首行与具体数量，供排查；正常完成的空清单保留原有语义。

企微与本地 REVIEW.md 均展示全部备选，不按分数、数量或已补切状态隐藏。
先展示 P 编号，再展示 R 编号，各组按数字升序排列（2 在 10 之前），不与时间顺序
交叉穿插；原编号和补切记录不变。长消息沿用企微字节限制分段完整发送。
这只是展示顺序，不授予投稿资格，也不要求逐个批准。

备选列表一行一个话题：`R编号` 是全场初选未选的话题，`P编号` 是
发布筛选留下的备选，包含时间、模型分、待核主题和短理由。两者均不是上传 ID，
不会因为列出就制作或入队。初选未选项保存原候选和源字幕摘要，供明确补切时复用。
补切 `R3/R8` 用 `clips:publication restore --plan PLAN.json --recall-indices 3,8 --output <新计划>`；
随后用已有 `own_stream_clipper --use-plan <新计划> --publication-mode all`。只有来源和
摘要仍相符才能进入详细编辑，再过切前复核和成片审核；不重扫整场、不绕过内容排除。

`PLAN.json.publication` 保存有效策略、所有原候选的决定、分数与原因，以及完整 `deferred` 候选。
选中项的 `publication.index` 是筛选前的原序号，不是上传 ID，也不是制作后的序号。
`PUBLICATION_REVIEW.md` 展示独立建议和待选理由；主 REVIEW 与通知给出数量摘要、备选列表和该文件路径。
待选项不会混入本场可上传清单，也不会仅因筛选而申请上传 ID。
筛选前已失败的候选仍走原有失败诊断/短 ID 复核流程。

离线预览只读旧计划、写新文件，不重压、不登记、不通知、不投稿；默认也不请求模型：

```powershell
npm run clips:publication -- preview --plan "录播目录/own_stream_fun_clips/PLAN.json" --output "temp/比较/preview.json"
npm run clips:publication -- preview --plan "录播目录/own_stream_fun_clips/PLAN.json" --output "temp/比较/score85.json" --mode score --min-score 85
npm run clips:publication -- preview --plan "录播目录/own_stream_fun_clips/PLAN.json" --output "temp/比较/budget12.json" --max-standalone 12
```

预览写完整 JSON 计划和同名 Markdown。输出文件必须是新路径，不能覆盖原计划。
对已筛选的计划再次预览会先恢复原候选池，避免越筛越少；`shadow` 的重复候选会按原序号折叠。

恢复待选项先导出新输入计划，再明确回退筛选并制作到新目录。导出时 `--indices` 对应上述原序号；
`--all` 可恢复整个候选池：

```powershell
npm run clips:publication -- restore --plan "录播目录/own_stream_fun_clips/PLAN.json" --indices 2,5 --output "temp/恢复/restored.json"
node src/scripts/own_stream_clipper.js --media "原录播.flv" --srt "原录播.srt" --xml "原录播.xml" --use-plan "temp/恢复/restored.json" --publication-mode all --output-dir-name "restored_clips" --no-notify
```

恢复保留原证据并重新走制作/复核，不恢复历史投稿授权。

## 可选关联合辑

默认关闭自动合辑建议。将 `bundles.enabled` 打开时，每场发布筛选后最多增加一个模型请求；
或只对某份计划临时使用 `preview --suggest-bundles`。模型/传输重试沿用现有配置与缓存。
建议失败或不符合合同只记录原因，独立片照常制作。

合辑只从待选库中挑选：

- 片段模型分达到 `bundles.minScore`，但低于 `protectScore` 和 `standoutScore`，优先独立稿绝不进入合辑。
- 字幕与生产使用相同的可信 ASR/说话人侧车证据，哈希匹配且无未解决的文案/引用问题。
- 每段向模型提供完整窗口原话；最多 `maxCandidates` 个、总字符不超过 60000，超预算整段略过。
- 只有具体事件续篇、前后照应、升级或对比才建议；“都在玩游戏/吃饭”、相同人物或关键词不够。
- 每组 2–3 段、总长最多 300 秒；每段贡献不同发展，按原时间顺序拼接，保留完整边界。
- 模型组合分至少 85 且高于最高成员分 5 分；每个成员有自己的原话引用，禁止未知 ID、片外引用、重叠和跨组合重复。

这些检查约束结构和证据，不证明模型理解正确或组合一定更好看。`relation`、`payoff` 与标题仍标为待核，
需要看原话和画面，尤其检查“翻车”“开打”“挑战”等是否来自模型推断。建议不自动替换单片、制作或上传。
复核后用以下命令制作某个建议，复用标准大字幕、GPU 调度、NVENC/CUDA 及 CPU 回退和已有合辑编译器：

```powershell
npm run clips:publication -- preview --plan "录播目录/own_stream_fun_clips/PLAN.json" --output "temp/合辑/preview.json" --suggest-bundles
npm run clips:publication -- build-bundle --plan "temp/合辑/preview.json" --group 1 --output "temp/合辑/bundle.mp4"
```

输出 MP4、合并 SRT、来源分段 manifest、编译计划与 REVIEW。编译前重新核对原字幕证据和成员资格，
字幕变化会停止。每段先按原窗口烧字，再按实际视频时长平移合并字幕，切段间不包含被跳过的录播。
新合辑需重新审核文案、归属、字幕，并按既有成片流程登记；不会继承单片的审核或投稿状态。

## 调参验证

同时比较候选数、独立建议数、高分保留数、实际通过审核数、恢复的漏选片和合辑采纳理由。
优先用至少几场不同题材的计划回放，检查固定阈值是否因某场普遍高分而失效。
播放效果应在相同上线时长后观察播放、点击、完播、互动，区分单片和合辑；
不能把投稿数量下降直接当作质量提升，也不能用未控制题材/时间的相关性声称数量稀释了流量。
若漏选较多，可降底线或提高预算；若某场全是高分而超额，应先检查评分尺度，不通过合辑吞并高分片。
