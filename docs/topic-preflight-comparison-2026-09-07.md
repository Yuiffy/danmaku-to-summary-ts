# 关键词切片烧录前准备：模型、分工与费用对照

> 后续状态：用户纠正领域事实后，已按冻结的新事件集重新做成稿质量与费用验收，并启用新版质量规则。最新判断见[质量优先的成本验收](topic-preflight-quality-cost-2026-09-07.md)，不要把下文的历史最优判断或过时事实扣分作为当前结论。

> **质量结论更正**：用户指出成稿质量应优先后，补审发现当前单次版仍有标题忽略否认、片段开头丢失对象等问题；两段版在部分完整性维度更好。下文保留实验与启用历史，但不能据此宣称单次版已通过质量验收或是最优方案。见[成稿质量补审](topic-preflight-quality-audit-2026-09-07.md)。实际配置本轮未切换。

## 启用决定

已开启关键词切片的烧录前准备，默认使用 **daiYu / gpt-5.6-sol / high / single**。

一次调用针对一组相邻关键词上下文，输出可变数量的独立事件、精确字幕边界、关键词判断、字幕局部校对、选片理由、标题、简介和两行封面文字。不固定追加第二遍 AI 审核。

本次选择 sol high 不是因为它最便宜，而是因为它在长故事的事件完整性与调用成本之间更适合当前任务。luna 更省钱；astra/max 在这些样本上没有显示出足够收益。下文都是小样本实测，不是总体准确率承诺。

## 实际执行顺序

1. 用现有无 hotword ASR 和替换流程召回时间点；按相邻上下文组织候选。
2. **全部候选组先完成 AI 准备**。提供逐条字幕 ID、原始 ASR/替换来源（有则提供）、主播来源、附近弹幕和前后文。候选命中不等于身份已确认。
3. 本地解析和校验：来源、关键词、区间、重叠、文案引用、字幕修改依据；保存完整 `_TOPIC_PLAN.json`。
4. 仅 `ready` 的片段写出校对后的切片 SRT，然后烧录、生成封面、写审核单和登记短 ID。
5. `needs_review` 或调用/解析失败的候选只保留元数据与原因，不烧录、不生成封面、不登记可上传 ID。原有上传仍需人工批准。

不会先生成一份封面，再让 AI 改标题；也不会先烧字幕再校对。整场原 SRT 不回写，校对只应用到切片副本。

## 模型参数核验

先发现并修复两个影响对比真实性的问题：

- 请求层原先将 `max` 静默降成 `high`，现在支持并传递 `max`。
- 原兼容逻辑会将指定的 `gpt-5.6-sol` 改写为 luna。新增 `exactModel`，本流程显式启用，旧调用默认兼容行为不变。

本流程严格使用 Responses，不在失败时静默改用 Chat Completions、其他模型或其他服务。记录请求模型、发出的 effort、返回模型和返回 effort，并拒绝已知不一致的结果。网关返回的是路由声明，不是对其内部实际权重的独立审计。

最终回归还遇到了工作区新加入的响应阶段用例，修复了共享解析器混入 commentary 的问题：按 `phase: final_answer` 提取最终答案，不按文字前缀猜测或删除。只有过程消息而没有最终答案时不会当成生成成功。此修复不改变已有已保存JSON的语义对照结果。

astra 开始时在 daiYu 分组返回404，曾用 tuZi 完成可用性探测及一条价格负例。用户随后补齐 daiYu 配置，正式 astra 对照改走 daiYu，价格负例也在 daiYu 重测。旧 tuZi 结果保留但不混入下面的同路由表；中断时正在进行的另一条 tuZi 请求消耗未知。

官方文档已核对三者支持 max：

- [推理参数](https://developers.openai.com/api/docs/guides/reasoning/)
- [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
- [GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)
- [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)

## 样本和方法

本轮使用8组历史上下文：金额误识别2122、真实姓名变体2144、长故事2145/2146/2147、直播安排2031、作业误识别2152、写错名字2130，以及后加的吃饭2077和年龄1986。

相同组使用相同字幕、附近弹幕及可用的局部无热词识别文字。正式模型对照均走 daiYu；交替请求顺序，不做并发竞速。首次三组用于开发，之后三组先作为留出测试；发现问题后明确转为修正回归，不能再称为独立留出。最终两组未用于本轮提示词调参，并且不提供额外复识别，模拟普通自动路径。

这不是人工逐字听写的金标集，也不是独立盲评。主要依据原字幕、局部识别、弹幕和已有上传记录核对；语义事实和声学正确性不能仅因引用校验通过而保证。没有向文本服务发送音频视频或账户信息。

## 发现问题后的第二轮

留出直播安排2031暴露出单次 sol high 的语义拼接：“明天做嘉宾”和“九点看小岁直播间”被合成“九点去小岁直播间当嘉宾”。仅检查各个词在字幕里出现过无法发现这种关系错误。

因此补充“相邻事实不等于同一活动、同一人物或因果”的约束，并再比较：

- 单次：选事件、校对和文案一起输出。
- 两段：先选事件并审核字幕；后段只接收锁定区间、通过校验的字幕、必要上下文和简化关键词定位，不把前段事件概括/理由当事实。后段不再改字幕或边界。

两种都用 sol high。以下三组是修正回归，不再算独立留出：

| 样本 | 单次输入/输出 | 两段输入/输出 | 单次秒 | 两段秒 | 单次USD折算 | 两段USD折算 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 长故事 | 15,112 / 9,640 | 45,148 / 11,032 | 197.26 | 220.95 | 0.23804 | 0.35561 |
| 直播安排 | 10,891 / 1,574 | 21,465 / 3,252 | 30.27 | 61.10 | 0.05984 | 0.12049 |
| 写错名字 | 11,614 / 3,899 | 23,024 / 6,839 | 71.28 | 126.38 | 0.10923 | 0.19846 |
| 合计 | 37,617 / 15,113 | 89,637 / 21,123 | 298.81 | 408.42 | 0.40711 | 0.67456 |

两段的长故事需要“首轮 + 两条最终片的文案”，实际3次请求；另外两组各2次。不能简单把它都说成2次。两段保留了主故事更多即时反应，但没有形成足够稳定的整体质量优势；写错名字的两段结果还略晚开始，措辞仍出现“当场露馅”。

两种都不再把观看直播写成当嘉宾。单次写错名字片段为2292.889–2341.284秒，保留解释及被指出表情不对的反应，并在谢礼前结束。边界来自字幕行，不代表已获得字级精度或逐帧人工验收。

## 费用口径

daiYu 的 `/api/pricing` 未提供可用计价数据；响应也没有实扣金额。因此报告使用请求实际 token 按官方标准价折算，不冒充实际账户扣费。tuZi公开公式与下列短上下文基础费率一致，但其用户分组折扣不能套到 daiYu。

| 模型 | 普通输入 USD/M | 缓存读取 USD/M | 缓存写入 USD/M | 输出 USD/M |
| --- | ---: | ---: | ---: | ---: |
| luna | 0.20 | 0.02 | 0.25 | 1.20 |
| sol | 4.00 | 0.40 | 5.00 | 20.00 |
| astra | 10.00 | 1.00 | 12.50 | 50.00 |

本轮所有输入远低于272K。缓存写入为0。计算式为：

`[(input - cached - cacheWrite) * inputRate + cached * cacheRate + cacheWrite * writeRate + output * outputRate] / 1e6`

输出包含推理，**不再加 reasoningTokens**。缓存命中只降低相应输入计价，并不使整次请求免费。所有实测均为各阶段冷请求，不把本地缓存重放时间当作模型延迟。

完整实验成功请求按标准价合计约2.81369美元，包括旧版本对照和一条保留的tuZi价格负例，不含可用性探测。另有5条失败请求和1条中断请求费用未知，不能称这个合计为真实总花费。日常费用应从生产请求ID对应的 daiYu账单核对。

## 字幕修改规则

- 输出精确字幕 cue ID、唯一原文子串、替换文本、理由和证据ID；不重写整条 SRT，不修改起止时间或说话人。
- 校对只接受原始 ASR、相应时间段的复识别或未被修改的片内证据支持；规范人名还需已有身份判断及已提供的可能识别形式。
- 对否定词、数字和人称变化使用更严格的局部对齐；不能因为另一个句子出现某个字就改掉本句含义。
- 不允许补写原文不存在的长句、未知 cue、重复/重叠补丁、片外改字，或以自己刚改出的字幕为后续修改的依据。
- 无依据的可选改字记为 `rejectedSubtitleEdits`，原字保留，审核单可见；这不自动否定整段真实事件。若主线身份/语义不确定，或公开文案引用了被拒绝改字产生的内容，则整段留待审核。
- 原始 ASR 本身仍可能错误，多个识别器也会一致出错。校验是降低风险，不是声学真值认证。所有上传继续人工审核。

## 配置和回退

两份实际 JSON 配置已启用：

```json
{
  "review": {
    "enabled": true,
    "mode": "preflight",
    "strategy": "single",
    "model": "gpt-5.6-sol",
    "reasoningEffort": "high",
    "maxOutputTokens": 24000,
    "maxDanmakuRows": 120,
    "maxEvidenceChars": 80000,
    "timeoutMs": 240000
  }
}
```

`strategy: staged` 保留为显式可选项，不作为失败时静默追加调用。`enabled: false` 回到既有事件编排路径；`mode: shadow` 是首轮开发的仅建议审核模式。

原 `aiModel: luna` 没有全局改成sol，其他总结、晚安、漫画、普通小岁/老岁片不受此模型选择影响。本流程使用 `review.model`，并在元数据中记录实际模型和推理档位。

超过证据预算时不悄悄截断字幕，也不直接裁剪无审核候选。源SRT在准备期间变化、模型调用/结构失败、模型被替换或计划无法保存，都保留待审核记录并停止该候选的烧录。

主媒体路径继承项目现有 NVENC `p4` / CUDA 参数与两阶段 copy 烧录，仍使用资源调度和 CPU fallback。关键词参数如显式指定编码器仍优先。
