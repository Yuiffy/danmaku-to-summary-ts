# 精剪流程与实验模式

岁己日常精切使用 `ownStreamClips.enhancements.workflow: "creative"`，每次整场选片最多选一条做精剪，
普通切片先交付。`roomIds` 仍限定岁己房间；原停顿删减可显式切回 `pacing`，多版包装实验为 `legacy_packaging`。
没有适合的内容或精切检查不通过时保留普通版。已有成片和投稿不会自动重做。
日常默认 `creative.style: "compact"`：先判断内容类型与语气，再安排删减、原地放大和视听表达。
`accent` 保留旧的连续时间轴轻效果流程。
通用策略位于共享 `creative_runner`，不依赖候选编号、某场游戏、头像固定位置或横屏比例；自动触发由对应工作流配置决定。

## 视觉精切与两段交付

面向代理的操作与决策步骤见[可复用精剪流程](../.agents/skills/sui-clip-queue/references/precision-editing.md)。
代码中的共享流程用于全批自动精选与按编号重渲染，不能只在临时脚本中保留用户认可的编辑做法。

已回退为普通版的自有直播片可按原数字 ID 单独重跑：

```powershell
python src/scripts/clip_upload_registry.py precision --id 123 --note "修复后重新制作精切供查看"
# 紧凑综艺版：完整句组删减、表情/关键点特写、较密效果与 BGM
python src/scripts/clip_upload_registry.py precision --id 123 --style compact --note "重新剪辑剧情与节奏"
# 游戏路线/操作是故事重点：保留主画面，只把面部反应放进圆形窗
python src/scripts/clip_upload_registry.py precision --id 123 --avatar-mode circle --resume-from "D:\clips\precision_revisions\123\r-example" --note "保留游戏画面并放大面部反应"
```

该入口验证源字幕、原人物审核和底版摘要，复用普通底版进行选点与画面分析，再从源录播渲染。
每次输出保存在原成片目录的 `precision_revisions/<ID>/r-*/`，其中 `RESULT.json`、`clip.json`
及 `REVIEW.md` 保存新视频、效果和检查结果；父目录 `latest.json` 指向最新完成的尝试。
失败返回非零退出码并保留证据。原成片、注册表与已投稿 BV 不变，新版仅供本地审核；
不重新生成 ASR，不发送通知，也不入队或替换线上稿件。存在待重压字幕或活动上传的 ID 须先完成原任务。
画面修复反馈逐项标出有问题的缩放节点与字段；无法确认安全裁切时撤掉该处缩放，保留其余有效效果，
不能把 `safeToCrop` 改成 `true` 来绕过校验。
修复后重试可加 `--resume-from <旧修订目录>`：工具核对同一 ID、普通底版及源文件快照，
复用旧故事/节点草案，重新执行结构校验和审核。若故事保留区间变化，不复用旧时间轴上的节点；
若节点与时间轴均完全一致，也可复用画面草案后按当前规则重新校验。实际渲染和成片审核始终重跑。
如果旧版已通过整片 QA，且原素材、底版、文案与剧情时间轴均未变化，沿用其已绑定的故事审核，
避免仅修混音/构图时因重新抽样又改变已确认的剧情。新视频仍独立检查。
内容分类、语气、密度、连续性或音乐/笑声策略变化时，旧故事批准、节点和视觉草案不能直接复用。
超过七个节点的画面证据按编号拼成多行图，
每次请求仍不超过八张图片，不缩小单帧证据来强行塞入数量上限。

### 按内容决定的精剪（`creative.style: "compact"`）

新计划先生成 `editorialProfile`，独立故事审核同时核对分类、语气和视听选择。字段为
`kind`、`tone`、`density`、`preserveContinuity`、`music`、`laughter` 及依据 `reason`。
它决定删减边界、效果密度以及是否适合笑声/BGM，不能把任意素材都套成密集喜剧。

| 内容 | 重点保留 | 适合强调的主体 |
| --- | --- | --- |
| 游戏 | 操作、路线、目标与反应的关系 | 原头像、游戏关键点或相关弹幕 |
| 聊天／连麦 | 人物关系、提问、接话与上下文 | 当前相关人物、头像或聊天原文 |
| 故事／杂谈 | 铺垫、因果、转折、收尾 | 反应、具体原话与已确认的细节 |
| 教程 | 必要步骤、说明和结果 | 操作区域、文字和控件 |
| 连续表演 | 乐句、段落和原有音乐的连贯性 | 表演主体或真正有价值的细节 |
| 混合内容 | 当前片段的主要内容和转换关系 | 根据实际画面选择 |

中性、严肃片不加罐头笑声或轻快 BGM；连续表演保留内部连续性，不混入额外音乐。
效果密度分 dense/moderate/light，分别最多 24/12/6 个节点，不能为了凑数量制造重点。

先根据完整字幕选择按原顺序保留的句组，再为新时间轴安排效果。可删掉重复说明、无进展操作和支线，
不能截断一句话、颠倒因果或删除标题/简介/封面依赖的人物与事实依据。计划记录保留区间及理由，
独立审核完整性；结构校验及语义审核各最多修订一次。新内容策略不以固定压缩比例判断合格与否，
完整教程或连续表演可保留整段。旧的无 profile 计划仅作为已审核历史版本兼容，不据此推断新素材语气。

字幕逐字复用已批准的片内 SRT，只映射保留句子的时间；画面和声音按相同源区间拼接。所有特效在
新时间轴安排，取证帧反向映射到原视频。紧凑模式最多 24 个节点、每处 0.6–12 秒（通常 4–8 秒；仅连续表达有必要时延长）、间隔至少 0.15 秒，
密集喜剧的总覆盖最多 90% 且不超过 150 秒，可每 4–8 秒形成具体节拍；中、低密度分别最多覆盖 60%/30%。

反应、嘴硬和反问优先面部特写，小脸允许 3–5 倍；游戏细节必须指向明确关键物体。
模型需提供源画面中的 `targetBox`，程序检查目标确实位于裁切范围；看不准就不用该处放大。
`creative.focusPlacement: "source"` 默认在原主体附近放大。原头像在右下时放大仍在右下，不能为了
腾位置移去左侧遮挡弹幕。边缘处优先保证眼睛、嘴和下巴可见，圆框可以自然超出屏幕。问号、贴图围绕同一主体排布，
尺寸适配并优先放上方，其次侧方；无合适空间时省略，不能塞到无关角落。
当放大区域与字幕重叠时，只重排烧录用 ASS：保持原字号、字词、说话人样式和连续时间，
让字幕换行并排到主体旁或上方；SRT 不改词、不缩字。横屏、方形和竖屏都按实际分辨率计算。
字幕在裁切与贴图之后独立烧入。原片画面取证、成片对照和语义审核继续保留。

`creative.avatarMode: "auto"` 按内容选择表达方式：找路、解谜或操作本身构成笑点时，优先
`faceInset` 圆形放大窗保留游戏全景；纯聊天可全屏面部特写。`--avatar-mode circle` 显式将
已选中的面部特写转成圆窗，复用已核对的剧情和节点，另用三帧证据核对脸框与摆放位置。
圆窗由实际视频裁切，保持脸部比例，白色描边，字幕最后烧入；该节点的情绪滤镜只作用于圆窗。
原地特写 `faceInsetDiameter: 0.60` 是放大上限（画面高度的 60%，可设 0.28–0.72），
`edgeOverflow: true` 允许圆圈自然出屏。靠边取景产生的源画面外补齐部分必须完全落在屏幕外，
不能为塞进完整圆圈而在底部露出黑色补边。眼睛、嘴和下巴仍须在可见范围；字幕和关联贴图按新边界避让。
实际放大限制为 1.2–4.5 倍，不允许只做大圆而没有表情放大；旧自由摆放模式保留原有边界限制。

全屏放大游戏/画面细节时，另检查原三帧的人脸位置：若放大裁掉了人脸，可附带
`faceInset.mode: "retain"`，用原始视频独立分支、1:1 像素比例、原位置保留一个小圆窗。
它不会套用大特写直径，也不会从已经放大的游戏画面再次裁脸；滤镜只作用于当前放大的细节，
保留人脸维持原色。源画面没有人脸或脸仍完整可见时不重复叠窗。最终 QA 分别检查主细节、保留人脸和字幕。
如果细节取景边缘残留半张放大的人脸，程序尝试最小幅度平移取景；只有原来确认的关键目标仍完整
落在取景范围内时才采用，避免同时出现残缺大脸和小圆窗。通过 QA 的源脸位置可在同源、同时间轴、
同节点且视觉草案未变的重渲染中复用；每次仍按当前取景重新判断是否需要保留，并重做成片 QA。
人物、弹幕或画面细节也可使用 `focusInset`：`target=avatar/person/chat/detail`，
`shape=circle/rectangle`，`placement=source`，并提供有画面依据的 `sourceBox`。
文字和矩形区域按源像素比例放大，不截断所强调的文字；周围画面继续保留。
需要精确校准时，可用 `--inset-plan <JSON>` 传入编辑布局；文件包含 `version: 1`、`clipId`、
原 metadata 文件的 `sourceMetadataSha256`、保留时间轴 JSON 的 `timelineSha256`，以及按 `momentId`
列出的 `insets`。每项使用归一化 `sourceBox`、圆窗左上角 `x/y`、相对画面高度的 `diameter`
和 `clearOfAction`。工具验证原编号、元数据、时间轴、位置及完整覆盖，复制布局到新修订目录，
最终仍检查实际成片；这不是批准上传，也不能用来改写原字幕或排队状态。

### 用户确认后的原稿替换

`replace-precision --id ... --revision ... --review-note ...` 发布已确认的新版本到该编号原有 BV。
`--dry-run` 只验证；实际替换保存用户授权和版本摘要，验证通过的 AI／音频审核与原素材后才上传新文件并编辑。
标题、简介、标签、封面和其他分 P 沿用线上内容。注册表保存 `precisionReplacement` 回执，
保留原普通媒体作为后续重做的底版，不重复入队新增投稿。具体命令及异常处理见上述操作步骤。
工具的 `submitting/unknown` 回执禁止自动重发；先核对创作中心是否已有对应新 CID，再人工处理不明确结果。

外部笑声先归一化至 -16 LUFS 再应用节点增益，通常为 -3 至 0 dB；合成短提示音使用固定振幅基准，
节点增益通常为 -8 至 -4 dB，淡入淡出随短音效长度缩短，不能把整个 pop 淡没。
两个反应音重叠时优先保留真实笑声并记录被省略的短提示音，避免声音堆叠。
混音只轻度压低附加声音，保留原对白电平；额外测量音效相对原声的能量，低于 -11 dB 或
绝对新增 RMS 低于 0.006 时拒绝，不能仅以“能检测到变化”宣称可听见。
这些是技术指标，听感仍由成片审核确认。

`creative.laughAssets` 是可轮换的笑声池，按轻／中／强反应选择合适素材，优先用本片未使用过的片段，
避免相邻重复。以文件摘要＋起止片段区分素材，给同一片段换 ID 不算新的笑声。
默认四种为 Kinoton 的短笑、另一组短笑、起伏笑声和带掌声的笑声；前三种来自
[Sitcom Laughter 9x](https://freesound.org/people/Kinoton/sounds/383207/) 的不同片段，第四种来自
[Sitcom Laughter with Applause](https://freesound.org/people/Kinoton/sounds/371562/)，均为 CC0。
各次成片记录实际用到的素材 ID、SHA-256、截取位置和时长，重试时仍重新检查音轨。

适合轻松喜剧时，BGM 可使用 `creative_music.js` 生成的原创拨弦/打击乐循环，不采样外部歌曲；输出素材绑定 SHA-256
并记录出处。音乐在对白下方归一化至 -27 LUFS、轻度侧链压低、首尾淡入淡出。音乐会改变波形
相关性，因此以原声回归增益及完整时长检查保留程度，同时检查背景音可测响度。真实媒体回归测试：

```powershell
$env:DANMAKU_TEST_REAL_MEDIA='1'
npm test -- --runInBand src/scripts/clipping/creative_compact_media.test.ts
```

### 轻效果版（`creative.style: "accent"`）

1. 人物/文案每审核完一批就立即生成该批普通底版，与余下审核并行。全批完成后，
   从全批选一条有具体反应、反差或画面重点的完整故事。
   `creative` 的硬上限为一条；一条的小批次也可参与。允许选零条，缺少静音不是淘汰理由。
   文案待审、人物归属未过审或审核已过期的候选仍不能入选。
2. 其余普通片按现有 GPU copy 两段式烧字流程生成，先保存 `REVIEW.md`、审核状态和上传编号，
   发送普通清单，并明确“正在把候选N《标题》制作成精切，完成后另行通知”。
   这里的候选N是计划序号；精切成片登记后才有上传短 ID。普通片可先人工审核，不必等精切。
3. 精切复用该条已经生成的普通底版，不再重复粗剪和烧字，底版保留作失败回退。模型根据完整片内字幕与弹幕选择最多六个时刻，
   再看每处开始/中间/结束三帧和实际素材索引决定具体效果。拼图每个小帧单独计归一化坐标，不能假定主播固定在右下角。
   不确定是否遮挡游戏重点或人物时可放弃该处。字幕只用于找到相关时刻，不单独证明画面位置。
4. 综艺精剪版默认最多六个节点，支持最大 2.4 倍主体/细节推近后切回，优先在适合的反应处用
   1.6–2.2 倍明确特写。问号、叹号、闪光符号与本地登记的透明 PNG 都可静态、弹跳或滑入。
   可用真实观众笑声与短促 pop/ding，及黑白、冷色、暖色、暗角滤镜。
   每处 0.6–6 秒、间隔至少 4 秒，总覆盖不超过片长 30% 且最多 40 秒；这些是上限，不要求用满。
   `variety: true` 拒绝多处效果全是同一类型的方案，最终 QA 还检查剪辑是否有实际可感知的表达。
5. 从原视频重新渲染画面效果后，按原规格烧录字幕，避免把已经烧入的视频字幕一起放大或裁掉。
   原音轨保持完整；音效有淡入淡出，`offsetSeconds` 可对准笑点句尾。
   对白作为侧链信号压低附加音效，原声不随笑声降低；混音器保留原片长度，限幅器抑制叠加峰值。
   保持源时间轴与 SRT 不变；第一版不把停顿删减和画面效果同时叠用。`pacing` 的原能力保留。
6. 检查音视频、时长、完整解码；独立模型看源画面与实际效果帧、字幕及封面。
   通过后绑定视频、字幕、封面和文案摘要，重新绑定原人物审核。
   任何模型失败、越界参数、源文件变化或质检拒绝均恢复普通版；保留原来的待审核状态。
7. 最终更新完整清单和同一普通片编号映射，单独发送“精切完成”，列出效果数量、视频路径与精切 ID。
   失败则发“精切处理结束：已保留普通版”或制作失败，不冒报成功，也不重复发送整批普通列表。
   两阶段均遵守 `notify.enabled` / `--no-notify`；不自动投稿。

```json
{
  "enabled": true,
  "roomIds": ["25788785"],
  "workflow": "creative",
  "experiment": { "enabled": true, "ratio": 1, "maxClips": 1 },
  "creative": {
    "style": "accent", "maxMoments": 6, "maxZoom": 2.4, "soundEffects": true, "filters": true,
    "variety": true, "assetManifest": "config/clip-creative-assets.json"
  }
}
```

轻效果版滤镜只作用于选中的短时刻，不加 BGM。紧凑版使用上述原创 BGM；外部歌曲素材、复杂转场、
GIF 及持续运动跟踪尚未实现。未来转场用于确实的场景/章节变化，不覆盖对白连接处。

通常增加一次全批抽选和三次逐片模型调用（时刻、画面方案、成片 QA），沿用现有账本及传输重试。
视觉方案全部没有音效而目录有真实声音素材时，独立增加一次声音编排，只选最多两处合适的笑点，严肃内容可不选。
声音可在画面效果结束后最多延迟 1.5 秒进入，在句尾自然落下；绝不延长原视频，也不截掉原音轨。
时刻或画面方案校验失败时各最多修复一次，原始响应与失败原因保存在临时目录，不无限重试。
每次 QA 每个节点一张“上排原画、下排成片”的六帧拼图，加一张封面，避免重复单帧预留图片 token；
拼图不能替代完整观看或听感审核。
`creativePlan`、`creativeResult`、`enhancement.baseline` 与临时 `creative-plan.json` 留存依据和回退位置。
`PLAN.status=precision_pending` 表示普通片已进入交付阶段而精切尚未结束；这不是持久后台队列。
任务仍由原切片进程顺序完成，进程中断后保留部分成片和待完成计划，需按原任务恢复，不会宣称精切已完成。
`REVIEW*_DELIVERY_<phase>.json` 对已发送内容去重；发送超时或部分成功记为 `unknown`，须核对企微后再决定补发。
`creative` 在全批审核/底版完成后只抽选一次，但底版沿用 `streamReviewRendering` 的渐进渲染，
不再因等待精切抽选而暂停普通压片。选中底版暂标为待精切质检，不作为已完成精切登记；
普通清单发出后复用底版进入效果制作。其他房间及 `pacing` 保持原渐进渲染路径。

## 剪辑经验依据

- [More Jeyraident：ULTIMATE Video Editing Guide for VTubers](https://www.youtube.com/watch?v=ApouG96eZ5c)：
  2:03 节奏不宜过慢或过快，3:47 瞬间/平滑放大，4:26 运镜与音效配合，5:29 图片、表情与动图，
  7:01 BGM，7:56 从观众角度反复检查。本文按这些操作分类设计，但不直接采用其音乐推荐或素材授权假设。
- [Melon Sour：A Walkthrough on Clipping and Subbing VTubers](https://www.melonsour.com/post/clip-sub-vtubers/)：
  先确定剪辑时间轴，再对齐字幕；ASS 保存字号、颜色和位置，最后用 FFmpeg 烧入；字幕变化可与放大关键帧同步。

这些是创作者的制作经验，不是“加特效即可热门”的效果证据。首版先比较真实成片的节奏、定位、字幕可读性和听感，
再决定扩展效果密度或素材库。

## 素材库与声音处理

`config/clip-creative-assets.json` 只维护素材 ID、语义用途、来源、作者、许可链接、下载地址和 SHA-256。
素材文件下载到被忽略的 `data/runtime/clip-creative-assets`，不随仓库再分发。新机器运行：

```powershell
node src/scripts/clipping/creative_assets.js fetch
```

自动任务只读取已缓存且摘要匹配的素材，缺失或内容变化会记录为不可用，不临时抓取未知网址。
模型只能选择目录里的 ID，不能指定任意文件、URL 或 FFmpeg 表达式。实际贴图在字幕前合成，
最大高度为画面 35%，底部限制在 80% 高度以上，给大字幕留空间；还须视觉核对没有挡住脸或操作。

| 素材/操作 | 当前用途 | 时机 |
| --- | --- | --- |
| irasutoya 捂嘴笑 | 轻松的自嘲、发现操作失误 | 原话笑点成立后 |
| irasutoya 能量饮料 | 明确说到喝饮料、补给的情景类比 | 对应原话，不能冒充实际游戏画面 |
| irasutoya 头晕 | 晕 3D、转圈、眩晕的说明 | 对应片内解释 |
| Audience laughing | 后期观众笑声，默认截取约 1.8 秒 | 可延迟到句尾；严肃/难过内容不用 |
| Sitcom Laughter / Kinoton | 情景喜剧罐头笑声，2.6 秒完整短段 | 笑点句尾，当前默认笑声素材 |
| monochrome / cold | 自嘲愣住 / 短暂疑惑 | 只作用于当前节点 |
| warm / vignette | 轻松强调 / 聚焦反应 | 不铺满全片 |

[irasutoya 条款](https://www.irasutoya.com/p/terms.html)与[FAQ](https://www.irasutoya.com/p/faq.html)
允许将素材作为视频设计的一部分；商用每个作品最多 20 个不同素材（含缩略图），不同表情分别计数，
禁止将原图再分发或作为编辑应用素材打包。当前最多八个节点低于此数量限制，封面中的重复素材不重复计数。
当前实物图片均来自官方作品页，作者为みふねたかし。原图不写入 Git。

[Audience laughing](https://pixabay.com/sound-effects/people-audience-laughing-6323/)由
Soundeffects4You (Freesound) 提供，页面标明适用 [Pixabay Content License](https://pixabay.com/service/license-summary/)，
可合入剪辑作品，不作为独立音效再分发。视频 JSON 的 `enhancement.assetSources` 保存实际使用素材的出处与摘要。
当前 `creative.laughAsset: "sitcom_laugh"` 使用 Kinoton 的
[Sitcom Laughter 9x, Small Audience](https://freesound.org/people/Kinoton/sounds/383207/)，
作者明确标为 laugh machine / canned laughter，适用 [CC0](https://creativecommons.org/publicdomain/zero/1.0/)。
使用页面公开提供的 HQ MP3，截取 7.5–10.1 秒，保留该段笑声起落。旧素材保留用于历史记录；
重试旧方案时，旧 `audience_laugh` 节点会按当前偏好换成新素材，新的实际素材摘要重新绑定。
FFmpeg 的 [sidechaincompress](https://ffmpeg.org/ffmpeg-filters.html#sidechaincompress) 将原音轨接入控制端，
压低附加音效；原音轨自身不进入压缩器的被处理端。渲染测试需要同时验证音效段确有额外声音能量、
非效果段原声保留、总时长、音画起点和峰值，不能仅凭画面宣称听感已通过。

有音效时自动解码底版和成片为 16 kHz 双声道浮点 PCM，`audioQa` 记录长度、峰值、
非效果段相关性/增益、效果段的可测新增能量及 PCM 摘要。长度差不得超过 80 ms、非效果段相关性
至少 0.98；较小的编码损失不等于删改原声。图像模型只审画面/字幕/语义，不要求静帧证明混音。
技术检查通过仍保留 `listeningReview: pending_human_review`，不宣称模型已经听过或评价听感。
片尾时间按毫秒规范化后绑定源片长，避免 `209.444` 与浮点减法得到的 `209.443999…` 被误判为越界。

## 日常节奏精切

1. 从原始 ASR 时间与显示字幕都未覆盖的长间隙中寻找候选，保护前后 0.2 秒。
   缺少原始 ASR 时间的旧 SRT 不自动精切。每批默认最多扫描 120 秒间隙音频，单窗最多 30 秒。
2. 解码到双声道 16 kHz PCM，以 10 ms 窗口检查双声道峰值，安静阈值默认 -40 dBFS。
   有背景音乐的区间用本机已安装的 FSMN VAD 分别检查两个声道，都没有人声才作为 `non_speech` 候选。
   VAD 只读缓存模型，不下载模型；不可用时保留普通版并报告原因。
3. 结果绑定媒体路径、大小、mtime、SRT/PCM SHA-256 和模型版本；源文件变化则失效。
   缓存保留完整证据，时间精度表示分析网格，不是语音分类准确率保证。
4. 保留停顿两端各 0.3 秒；每片至少减少 3 秒且不少于 2%，最多减少 20%，每片最多两处。
   阈值用于筛掉没有实际收益的尝试，不要求凑出删减；批次仍受 `experiment.ratio/maxClips` 限制。
5. 每个候选提供停顿前、中、后三帧，模型只判断是否值得删。无对白不等于无价值；
   战斗、操作、视觉笑点、等待答案和反应余韵必须保留。决定不删时立即结束，不跑包装或成片 QA。
6. 复用通用 GPU 两阶段烧字路径，对保留段同时拼接音视频，字幕按同一时间轴重映射。
   必须保留全部对白字面内容及顺序。文案未改且原审核的字幕、声纹、弹幕引用都保留时，
   通过确定性检查继承原事实审核，再绑定新成片；删掉引用或改了文案不能继承。
7. 从新成片生成同文案封面，检查时长、音画起点、字幕范围与完整解码，抽查剪切点两侧。
   最后一次模型调用只检查删减是否伤害含义或连续性。正常路径共两步模型调用，不另跑抽选、包装、封面选择和人物重判。
8. 新成片不通过或任何阶段异常时恢复普通版，保留失败原因及用量。原版本未获审核的状态仍保留，
   不能借回退获批。只有实际删减且检查通过的输出标为精切，上传授权和产物摘要校验继续生效。

```json
{
  "workflow": "pacing",
  "pacing": {
    "noiseDb": -40,
    "nonSpeechVad": true,
    "minRemovedSeconds": 3,
    "minRemovedRatio": 0.02,
    "maxRemovedRatio": 0.2,
    "maxPausesPerClip": 2,
    "maxScannedSeconds": 120
  }
}
```

可选 `pacing.vadModelPath` 指定已安装模型目录，`pacing.pythonPath` 指定 Python。
模型沿用 `stageDefaults` 和 `stages.edit/qa`，每次输出上限不超过 8000 token；接口重试独立计数。
该模式不做对白压缩、句子重排或无证据的咳嗽删除；语义精剪需要另一套完整事件和音频边界契约。

## 旧包装实验的抽选规则

配置入口是 `ownStreamClips.enhancements`。`enabled` 和 `roomIds` 同时匹配才启用；`experiment.enabled` 打开后，每批只让 AI 选中的条目进入增强。

- `experiment.ratio: 0.25`，`maxClips: 5`：上限为 `min(5, floor(批次条数 * 0.25))`，例如 20 条最多选 5 条。
- AI 通读候选的完整片内字幕，选择可能改善节奏或包装的独立故事，允许少选或不选。不满 4 条的小批次不抽选。
- 发布文案未完成或人物归属审核尚未通过的条目保留普通流程；审核已通过且文案摘要、源证据摘要及时间范围仍匹配的条目可以参与抽选。`attributionRequired` 表示必须审核，不等于审核未通过。
- 抽选失败时整批保持普通流程；不随机补名额、不把全部条目改成精切。相同输入可复用已校验的抽选结果。PLAN 另记可抽选数量、排除原因计数及未选中原因。
- PLAN 和逐片 JSON 的 `precisionExperiment` 保存批次摘要、分组、选择理由和调用账本 ID。此为 AI 定向抽选，不是随机实验，不能仅凭组间平均值宣布质量优劣。

## 标注与对照

- 企微切片列表只为实验条目添加 `精切`，不混入删减或 token 数。
- 列表发送后另发“精切实验模式详情”，使用同一上传 ID，汇总理由、删减秒数、用量、耗时和质检结果。过长消息沿用企微的字节上限拆分。
- 没有精切时仍另发“本批精切 0 条”，区分无符合条件的候选、批次不足、请求失败和 AI 主动未选。刷新审核通知时，去重摘要同时覆盖列表与精切详情。
- 视频简介含 `【精切实验模式】`，并区分实际多段剪辑与保留连续时间轴。标注在最终质检及内容摘要绑定之前生成，不添加 token/费用明细。
- 逐片 JSON 的 `enhancement.baseline` 保留普通版媒体、字幕、封面及文案；`editPlan.removed` 保留实际删除区间。未选择的普通条目不触发逐片增强请求。

## 安全条件

`editing: true` 表示允许多刀，不表示强制删减。只有匹配源文件身份的可信音频事件、原始 ASR 时间及对白保护均通过时才删除；SenseVoice 的粗粒度标签和显示字幕空隙不能单独当精确证据。`pacing` 无证据时跳过增强；`legacy_packaging` 无证据时仍可实验标题/封面和独立质检。

封面选择检查实际渲染图，最终质检检查源上下文、保留字幕、成片关键帧及文案。最多修复一次，仍失败则恢复普通版的连续视频、原文案和封面，重新审核；最终不通过的条目不给上传资格。不会用没有事件内容的短标题替代原文案。字幕、视频、标题/简介和封面的摘要变化会使审核失效。

已通过人物归属审核的条目进入精切后，最终文案还需一次只核验、不改写的归属复核，再进入成片质检。只允许引用保留区间内的字幕和弹幕；删除区间不能支持新标题。此复核复用现有动作/人物校验规则，保留先前审核记录，并绑定新文案、源证据与保留区间摘要。复核失败进入同一有限修复/回退流程，不能把旧文案的批准直接用于新文案；发生改写的精切仍需新的审核，普通对照不增加此调用。

详情中的模式标注是程序生成的状态声明，不当成主播原话。归属审核核对正文，最终成片质检及上传校验绑定包含标注在内的完整文案。最终视频/字幕仍由既有产物摘要校验保护。

## 用量记录

日常实验使用：

```json
{
  "budget": {
    "mode": "log_only",
    "ledgerPath": "data/runtime/clip-enhancement-ledger.json"
  }
}
```

`log_only` 不要求已确认单价，也不执行单场/房间/全局金额上限。每次调用仍先登记，再记录模型、推理档位、阶段、耗时、请求 ID 和原始用量。未知单价时 `costCny: null`，不冒充免费；用量已知和费用未知是不同状态。账本写入失败仍不允许无记录调用。

`stageDefaults` 提供共享渠道、模型、协议、推理档位、超时、输出上限和能力声明；`stages.selection/edit/packaging/cover/attribution/qa` 覆盖阶段参数。`attribution` 是精切最终文案的归属复核，未单独配置时继承共享参数，调用同样写入用量日志。令牌/输入合法性、完成状态、原意保护及上传授权检查不随金额限制放宽。

`stageDefaults.retry` 和 `stages.<阶段>.retry` 配置同渠道、同模型重试；每次尝试独立记账，
失败用量未知时保留未知，不能当作零费用。重试次数包含第一次请求，共享阶段总超时，
不会重跑成功阶段。默认最多两次请求；内容审核不通过仍走原有有限文案修订，不能靠传输重试放行。
参数与错误分类见 [请求重试与 JSON 容错](post-stream-residual-audit.md#请求重试与-json-容错)。

## 并发与证据输入

媒体处理由 `ownStreamClips.clipConcurrency` 和自适应资源调度控制；完成基础视频/封面后立即释放媒体名额。
逐片 AI 增强使用独立的 `ownStreamClips.enhancementConcurrency`（默认 3，范围 1–16）。
不同片段可以同时等模型，同一片段仍按剪辑、文案、封面、归属和质检的依赖顺序执行。
增强中的转码、抽帧、视频检查和封面仍需重新取得同一媒体名额，忙时降档仍然有效。

增强证据格式 v2 将重复 ASR/声纹对象放入 `provenance` 表，`retainedSpeech` 用稳定 S-ID
引用完整 `sourceSpeech`，保留相对成片时间。原话、原始 ASR 时间、说话人未知/混合状态、
全部观测及弹幕均可无损还原；没有把未知身份变成已确认。源窗口外上下文仍不能用于支持公开事实。
独立 QA 将制作方标签与片内事实文案分开读取，已通过的最终归属审核只支持其中明确核验的动作。
不能仅凭下一句字幕紧接着出现或 `boundaryAligned=false` 判定截断，仍需判断是否延续同一事件。

报告中的平均单片耗时包含增强等待，不等于单路编码速度。另记媒体与增强累计耗时，
两者可能因并发重叠而大于整批墙钟耗时。输入字符数减少不等于等比例 token、费用或运行时间减少，
实际质量和耗时仍需后续真实批次验证。

独立模型评测仍使用 `mode: enforce`（省略模式也为 enforce）和原有预算预留。不要把评测账本与日常仅记录账本混用，也不要把未知费用累计为零。

## 生效范围

新编译阶段须经 `npm run build:workflows` 验证后，用 `npm run workflow:activate` 激活。配置供新启动的切片进程读取；已经运行、已加载旧版本的进程继续其原流程，不中断重启在途录播或上传任务。关闭 `enhancements.enabled` 只影响后续生成，既有记录和人工批准状态保持不变。
