# 精切实验模式

日常精切默认使用 `ownStreamClips.enhancements.workflow: "pacing"`，只处理具有可验证删减收益的停顿。
先做本地音频筛选，再判断画面和上下文；不重写已经审核的标题、简介和人物归属。
没有合格停顿、模型决定保留或新成片未通过检查时，返回完整普通版。已有成片和投稿不会自动重做。
旧的多版包装实验仍可显式选择 `legacy_packaging`。

## 日常节奏精切

1. 从原始 ASR 时间与显示字幕都未覆盖的长间隙中寻找候选，保护前后 0.2 秒。
   缺少原始 ASR 时间的旧 SRT 不自动精切。每批默认最多扫描 120 秒间隙音频，单窗最多 30 秒。
2. 解码到双声道 16 kHz PCM，以 10 ms 窗口检查双声道峰值，安静阈值默认 -40 dBFS。
   有背景音乐的区间用本机已安装的 FSMN VAD 分别检查两个声道，都没有人声才作为 `non_speech` 候选。
   VAD 只读缓存模型，不下载模型；不可用时保留普通版并报告原因。
3. 结果绑定媒体路径、大小、mtime、SRT/PCM SHA-256 和模型版本；源文件变化则失效。
   缓存保留完整证据，时间精度表示分析网格，不是语音分类准确率保证。
4. 保留停顿两端各 0.3 秒；每片至少减少 3 秒且不少于 2%，最多减少 20%，每片最多两处。
   阈值用于筛掉没有实际收益的尝试，不要求凑出删减；批次仍受 `experiment.ratio/maxClips` 限制。
5. 每个候选提供停顿前、中、后三帧，模型只判断是否值得删。无对白不等于无价值；
   战斗、操作、视觉笑点、等待答案和反应余韵必须保留。决定不删时立即结束，不跑包装或成片 QA。
6. 复用通用 GPU 两阶段烧字路径，对保留段同时拼接音视频，字幕按同一时间轴重映射。
   必须保留全部对白字面内容及顺序。文案未改且原审核的字幕、声纹、弹幕引用都保留时，
   通过确定性检查继承原事实审核，再绑定新成片；删掉引用或改了文案不能继承。
7. 从新成片生成同文案封面，检查时长、音画起点、字幕范围与完整解码，抽查剪切点两侧。
   最后一次模型调用只检查删减是否伤害含义或连续性。正常路径共两步模型调用，不另跑抽选、包装、封面选择和人物重判。
8. 新成片不通过或任何阶段异常时恢复普通版，保留失败原因及用量。原版本未获审核的状态仍保留，
   不能借回退获批。只有实际删减且检查通过的输出标为精切，上传授权和产物摘要校验继续生效。

```json
{
  "workflow": "pacing",
  "pacing": {
    "noiseDb": -40,
    "nonSpeechVad": true,
    "minRemovedSeconds": 3,
    "minRemovedRatio": 0.02,
    "maxRemovedRatio": 0.2,
    "maxPausesPerClip": 2,
    "maxScannedSeconds": 120
  }
}
```

可选 `pacing.vadModelPath` 指定已安装模型目录，`pacing.pythonPath` 指定 Python。
模型沿用 `stageDefaults` 和 `stages.edit/qa`，每次输出上限不超过 8000 token；接口重试独立计数。
该模式不做对白压缩、句子重排或无证据的咳嗽删除；语义精剪需要另一套完整事件和音频边界契约。

## 旧包装实验的抽选规则

配置入口是 `ownStreamClips.enhancements`。`enabled` 和 `roomIds` 同时匹配才启用；`experiment.enabled` 打开后，每批只让 AI 选中的条目进入增强。

- `experiment.ratio: 0.25`，`maxClips: 5`：上限为 `min(5, floor(批次条数 * 0.25))`，例如 20 条最多选 5 条。
- AI 通读候选的完整片内字幕，选择可能改善节奏或包装的独立故事，允许少选或不选。不满 4 条的小批次不抽选。
- 发布文案未完成或人物归属审核尚未通过的条目保留普通流程；审核已通过且文案摘要、源证据摘要及时间范围仍匹配的条目可以参与抽选。`attributionRequired` 表示必须审核，不等于审核未通过。
- 抽选失败时整批保持普通流程；不随机补名额、不把全部条目改成精切。相同输入可复用已校验的抽选结果。PLAN 另记可抽选数量、排除原因计数及未选中原因。
- PLAN 和逐片 JSON 的 `precisionExperiment` 保存批次摘要、分组、选择理由和调用账本 ID。此为 AI 定向抽选，不是随机实验，不能仅凭组间平均值宣布质量优劣。

## 标注与对照

- 企微切片列表只为实验条目添加 `精切`，不混入删减或 token 数。
- 列表发送后另发“精切实验模式详情”，使用同一上传 ID，汇总理由、删减秒数、用量、耗时和质检结果。过长消息沿用企微的字节上限拆分。
- 没有精切时仍另发“本批精切 0 条”，区分无符合条件的候选、批次不足、请求失败和 AI 主动未选。刷新审核通知时，去重摘要同时覆盖列表与精切详情。
- 视频简介含 `【精切实验模式】`，并区分实际多段剪辑与保留连续时间轴。标注在最终质检及内容摘要绑定之前生成，不添加 token/费用明细。
- 逐片 JSON 的 `enhancement.baseline` 保留普通版媒体、字幕、封面及文案；`editPlan.removed` 保留实际删除区间。未选择的普通条目不触发逐片增强请求。

## 安全条件

`editing: true` 表示允许多刀，不表示强制删减。只有匹配源文件身份的可信音频事件、原始 ASR 时间及对白保护均通过时才删除；SenseVoice 的粗粒度标签和显示字幕空隙不能单独当精确证据。`pacing` 无证据时跳过增强；`legacy_packaging` 无证据时仍可实验标题/封面和独立质检。

封面选择检查实际渲染图，最终质检检查源上下文、保留字幕、成片关键帧及文案。最多修复一次，仍失败则恢复普通版的连续视频、原文案和封面，重新审核；最终不通过的条目不给上传资格。不会用没有事件内容的短标题替代原文案。字幕、视频、标题/简介和封面的摘要变化会使审核失效。

已通过人物归属审核的条目进入精切后，最终文案还需一次只核验、不改写的归属复核，再进入成片质检。只允许引用保留区间内的字幕和弹幕；删除区间不能支持新标题。此复核复用现有动作/人物校验规则，保留先前审核记录，并绑定新文案、源证据与保留区间摘要。复核失败进入同一有限修复/回退流程，不能把旧文案的批准直接用于新文案；发生改写的精切仍需新的审核，普通对照不增加此调用。

详情中的模式标注是程序生成的状态声明，不当成主播原话。归属审核核对正文，最终成片质检及上传校验绑定包含标注在内的完整文案。最终视频/字幕仍由既有产物摘要校验保护。

## 用量记录

日常实验使用：

```json
{
  "budget": {
    "mode": "log_only",
    "ledgerPath": "data/runtime/clip-enhancement-ledger.json"
  }
}
```

`log_only` 不要求已确认单价，也不执行单场/房间/全局金额上限。每次调用仍先登记，再记录模型、推理档位、阶段、耗时、请求 ID 和原始用量。未知单价时 `costCny: null`，不冒充免费；用量已知和费用未知是不同状态。账本写入失败仍不允许无记录调用。

`stageDefaults` 提供共享渠道、模型、协议、推理档位、超时、输出上限和能力声明；`stages.selection/edit/packaging/cover/attribution/qa` 覆盖阶段参数。`attribution` 是精切最终文案的归属复核，未单独配置时继承共享参数，调用同样写入用量日志。令牌/输入合法性、完成状态、原意保护及上传授权检查不随金额限制放宽。

`stageDefaults.retry` 和 `stages.<阶段>.retry` 配置同渠道、同模型重试；每次尝试独立记账，
失败用量未知时保留未知，不能当作零费用。重试次数包含第一次请求，共享阶段总超时，
不会重跑成功阶段。默认最多两次请求；内容审核不通过仍走原有有限文案修订，不能靠传输重试放行。
参数与错误分类见 [请求重试与 JSON 容错](post-stream-residual-audit.md#请求重试与-json-容错)。

## 并发与证据输入

媒体处理由 `ownStreamClips.clipConcurrency` 和自适应资源调度控制；完成基础视频/封面后立即释放媒体名额。
逐片 AI 增强使用独立的 `ownStreamClips.enhancementConcurrency`（默认 3，范围 1–16）。
不同片段可以同时等模型，同一片段仍按剪辑、文案、封面、归属和质检的依赖顺序执行。
增强中的转码、抽帧、视频检查和封面仍需重新取得同一媒体名额，忙时降档仍然有效。

增强证据格式 v2 将重复 ASR/声纹对象放入 `provenance` 表，`retainedSpeech` 用稳定 S-ID
引用完整 `sourceSpeech`，保留相对成片时间。原话、原始 ASR 时间、说话人未知/混合状态、
全部观测及弹幕均可无损还原；没有把未知身份变成已确认。源窗口外上下文仍不能用于支持公开事实。
独立 QA 将制作方标签与片内事实文案分开读取，已通过的最终归属审核只支持其中明确核验的动作。
不能仅凭下一句字幕紧接着出现或 `boundaryAligned=false` 判定截断，仍需判断是否延续同一事件。

报告中的平均单片耗时包含增强等待，不等于单路编码速度。另记媒体与增强累计耗时，
两者可能因并发重叠而大于整批墙钟耗时。输入字符数减少不等于等比例 token、费用或运行时间减少，
实际质量和耗时仍需后续真实批次验证。

独立模型评测仍使用 `mode: enforce`（省略模式也为 enforce）和原有预算预留。不要把评测账本与日常仅记录账本混用，也不要把未知费用累计为零。

## 生效范围

新编译阶段须经 `npm run build:workflows` 验证后，用 `npm run workflow:activate` 激活。配置供新启动的切片进程读取；已经运行、已加载旧版本的进程继续其原流程，不中断重启在途录播或上传任务。关闭 `enhancements.enabled` 只影响后续生成，既有记录和人工批准状态保持不变。
