# 精切实验模式

精切实验模式在普通自动切片中选择少量条目进行保守剪辑、标题/封面选择和独立质检，其余条目保持普通流程供人工对照。实验结果不自动批准上传，也不重跑已有成片。

## 抽选规则

配置入口是 `ownStreamClips.enhancements`。`enabled` 和 `roomIds` 同时匹配才启用；`experiment.enabled` 打开后，每批只让 AI 选中的条目进入增强。

- `experiment.ratio: 0.25`，`maxClips: 5`：上限为 `min(5, floor(批次条数 * 0.25))`，例如 20 条最多选 5 条。
- AI 通读候选的完整片内字幕，选择可能改善节奏或包装的独立故事，允许少选或不选。不满 4 条的小批次不抽选。
- 发布文案未完成或需要专门人物动作复核的条目保留普通流程，避免后续改写使原有归属审核失效。
- 抽选失败时整批保持普通流程；不随机补名额、不把全部条目改成精切。相同输入可复用已校验的抽选结果。
- PLAN 和逐片 JSON 的 `precisionExperiment` 保存批次摘要、分组、选择理由和调用账本 ID。此为 AI 定向抽选，不是随机实验，不能仅凭组间平均值宣布质量优劣。

## 标注与对照

- 企微切片列表只为实验条目添加 `精切`，不混入删减或 token 数。
- 列表发送后另发“精切实验模式详情”，使用同一上传 ID，汇总理由、删减秒数、用量、耗时和质检结果。过长消息沿用企微的字节上限拆分。
- 视频简介含 `【精切实验模式】`，并区分实际多段剪辑与保留连续时间轴。标注在最终质检及内容摘要绑定之前生成，不添加 token/费用明细。
- 逐片 JSON 的 `enhancement.baseline` 保留普通版媒体、字幕、封面及文案；`editPlan.removed` 保留实际删除区间。未选择的普通条目不触发逐片增强请求。

## 安全条件

`editing: true` 表示允许多刀，不表示强制删减。只有匹配源文件身份的可信音频事件、原始 ASR 时间及对白保护均通过时才删除；SenseVoice 的粗粒度标签和显示字幕空隙不能当精确证据。没有精确证据时保留连续时间轴，仍可实验标题/封面和独立质检。

封面选择检查实际渲染图，最终质检检查源上下文、保留字幕、成片关键帧及文案。最多修复一次，仍失败则尝试连续片段与保守包装；最终不通过的条目不给上传资格。字幕、视频、标题/简介和封面的摘要变化会使审核失效。

## 用量记录

日常实验使用：

```json
{
  "budget": {
    "mode": "log_only",
    "ledgerPath": "data/runtime/clip-enhancement-ledger.json"
  }
}
```

`log_only` 不要求已确认单价，也不执行单场/房间/全局金额上限。每次调用仍先登记，再记录模型、推理档位、阶段、耗时、请求 ID 和原始用量。未知单价时 `costCny: null`，不冒充免费；用量已知和费用未知是不同状态。账本写入失败仍不允许无记录调用。

`stageDefaults` 提供共享渠道、模型、协议、推理档位、超时、输出上限和能力声明；`stages.selection/edit/packaging/cover/qa` 覆盖阶段参数。令牌/输入合法性、完成状态、原意保护及上传授权检查不随金额限制放宽。

独立模型评测仍使用 `mode: enforce`（省略模式也为 enforce）和原有预算预留。不要把评测账本与日常仅记录账本混用，也不要把未知费用累计为零。

## 生效范围

新编译阶段须经 `npm run build:workflows` 验证后，用 `npm run workflow:activate` 激活。配置供新启动的切片进程读取；已经运行、已加载旧版本的进程继续其原流程，不中断重启在途录播或上传任务。关闭 `enhancements.enabled` 只影响后续生成，既有记录和人工批准状态保持不变。
