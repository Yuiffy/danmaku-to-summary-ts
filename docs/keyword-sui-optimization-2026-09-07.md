# 岁己关键词切片：调研、实验与采用决定

本文保留首轮调研快照。随后用户要求开启烧录前审核并比较多个模型，后续实现和启用决定见 [烧录前审核对照](topic-preflight-comparison-2026-09-07.md)。下文“默认关闭、未激活”只描述首轮结束时的状态。

## 结论

本次不启用 ASR hotword，不更换识别模型，不把“未上传”自动标成误识别。

正式保留到代码和配置中的改动：

1. 保留原始 ASR 假设、音素纠正记录和最终替换结果，供选片、文案生成和人工核查使用。
2. 为真实复现的“小四位”和两种“四时小路”误识别形式增加局部替换保护。保护发生在改字之前，不把历史字幕中的“小岁”反向猜回其他词。
3. 修复旧 burst 密集采样丢失命中附近连续字幕的下标错误。当前事件编排的完整证据路径不受该采样错误影响。
4. 增加可开启的独立关键词、字幕、文案、边界审核。默认关闭；开启后也只保存建议，不自动删片、改字幕、改文案、移边界或授权上传。

不采用“再加一个文字 AI”或“双 ASR 一致才保留”作为默认硬门槛。本次实测出现明显的真提及被拒绝，缺少正式切换的依据。

没有重启服务、切换编译工作流指针、修改历史素材、重做已上传稿件或操作上传队列。这里的“正式保留”指已实现并验证的源码/配置变更，不代表已激活新的生产工作流版本。

## 现有流程实际行为

- `clipTopics.aiVerify` 在生产配置中是 `false`；原 `verifyClipWithAI` 没有被实际生成流程调用。不能把它当成正在运行的独立审核层。
- 实际是关键词召回后，由 burst/事件选片模型顺便判断是否误识别。失败回退仍保留候选供人工审核。
- 旧独立验证函数只给前 500 字上下文，且读到的是改字后的字幕；本次保留其导出兼容接口，未重新启用它。
- 当前工作区已有“按完整事件编排、锁定区间后生成文案”的修改。本次沿用，没有把这些已有工作算成本次新成果。
- 生产通用 `safe` 表包含“小四、小 c、C级、小睡”等广义形式。音素纠正又可能先把其他词变成名字，后续 LLM 容易把被替换出来的人名当成事实。
- 音素相似度不是“这句话指岁己”的概率；第二个识别器的词形不同也不是未提及的证明。

## 样本与限制

本地登记快照有 717 条 `topic_clips`：359 条 uploaded、331 条 review、24 条 uploading、2 条 queued、1 条 needs_retry。在活动盘和归档路径中，本次找到 145 条完整元数据/源字幕，来自 61 份源字幕；572 条没有找到可用元数据，未擅自认定其删除原因。

从可用记录中挑选 36 条疑难与正例混合样本，时间集中于 2026-08-29 至 2026-09-06。其中 9 条已上传。未上传记录中也存在明确的真实提及，例如 1620、1690、1980、2028、2072。

- 32 条有可用音频，每条取首个命中前后各 9 秒，共约 696.76 秒不同音频。
- 本地 Paraformer、SenseVoice 各运行一次，不传 hotword，不做替换；共 64 份独立转写。
- 1731、1926、1944、1979 缺少可用音频，保留字幕样本，没有伪造音频证据。
- 新审核模型不接收上传状态、原标题、简介或真实短 ID；按固定散列顺序分成 6 条一批。文案审核实验另行接收待核对的原文案。
- 未进行独立人工逐句听写或随机总体抽样。“已上传”只是较强正例线索，不是零误差金标；两种 ASR 也不是人工真值。
- 这是候选审核方案的回顾性实验，不是整条新旧生产流程的随机 A/B。不能从这些数值推导全站准确率、总体误杀率或召回率。

## 关键词审核 A/B

两组使用同一现有 daiYu 路由、`gpt-5.6-luna`、`high` 推理档位。同一批字幕、同一三态审核提示词；B 额外附上本地无热词识别的文字结果，不发送音频或视频。

| 候选方案 | 确认 | 不确定 | 拒绝 | 9 条已上传样本中被拒绝 |
| --- | ---: | ---: | ---: | ---: |
| A：改字后字幕 + 命中前45秒/后60秒语境 | 17 | 10 | 9 | 1 |
| B：相同输入 + 两种无热词 ASR 文字 | 10 | 7 | 19 | 4 |

表中共有 36 条，4 条没有音频补证。只看有音频的 32 条，A 为 16/8/8，B 为 9/6/17（确认/不确定/拒绝）。分批生成也会存在模型波动，不能把所有变化归因于新增 ASR。

关键反例：

- 2031：确实是在安排去小岁的直播间；邻句的“小帅”和复识别“小碎”使两版审核都拒绝。
- 2064、2144、2151：B 把“小 C、小崔、C级”等既有 ASR 变体当成其他人的证据而拒绝；A 原本保留。
- 1977：两种无热词识别都支持“睡几个小时”，B 能发现原稿“小岁每天来调研”的错误。
- 2122：两种识别都为“小四位”，历史标题却是“小岁报价很贵”。
- 1945、1946、1947：实际语境持续讨论四时小路，错误名字嵌入其称呼。
- 2152：SenseVoice 支持“把其他作业也写，虽然这个可能今晚写不完”，原字幕含“小岁然”。

因此，B 增加拒绝数不等于质量提高。现阶段最有价值的用途是提出可定位的疑点，让人工检查，而不是自动扔掉候选。未上传也不能直接作为训练负标签。

## 可采用的局部保护

使用 64 份无热词识别，按每个房间的配置重放完整链路：

`音素纠正（包含转发的保护规则） -> normalizeAsrResult -> 通用/路由替换 -> 关键词匹配`

对照为原配置和最终候选规则，共 128 次本地文本重放。最终只保留：

```json
{
  "exclude_when": {
    "小四": ["小四历", "小四十小鹿", "小四个小鹿"]
  },
  "exclude_pattern": {
    "小四": ["小四位(?![于列居置])"]
  }
}
```

以上是相关字段片段，不替代现有其他排除项。两份配置均已保留原有规则。

结果：

- 5 份转写去除了假命中：1945/Paraformer、1946/两个模型、2122/两个模型。
- 对应 3 条历史片段、2 份录播，不能算成 5 个独立直播样本。
- 其余 59 份输出逐字不变，包含 9 条已上传片段的 18 份转写。
- 加入同句真名、跨字幕分段及“小四位列第一”的反例测试，避免金额保护阻断“岁己位列第一”这种名字用法。
- 没有提高热词权重、相似度阈值或扩大替换词表。

初期只调用音素纠正、未转发完整替换保护时，还复现了“睡几个小时 -> 岁己个小时”“万岁集团 -> 万岁己团”。但完整现行链路在这批短窗上已保留原词，新增保护无增量收益，故未正式加入。短窗复识别不同于原整场识别，不能据此断言这些历史问题已经全面消失。

## 字幕、文案与边界审核

对 1977、2122、2123、2130、2144、2152 做了 6 次独立审核。输入包含完整片内字幕、片前60秒/片后90秒辅助语境、局部复识别及原文案。辅助语境明确不能用于向锁定切片的文案增加片外事实。

观察：

- 2122：找出了把金额误写成人物及“人物报价”的错误，建议改成卡牌实际售价；这仍不意味着该片是合格的岁己关键词片。
- 2130：指出“回忆中的事情”不应写成当前现场发生；建议边界从 `2292–2350.4` 调整为 `2292.889–2341.284`，保留解释和反应，在谢礼前结束。
- 2152：能提出补回点数作业铺垫的边界，但它本身属于疑似关键词误命中。扩成完整作业故事不能解决关键词不相关问题。
- 2123：能标记歌曲/餐饮名称、人物归属的歧义，但不能稳定给出可靠改稿。
- 2144、2130：也会过度怀疑“小 C／C级”等正确指代，以及“小栞／栞栞”等昵称关系。

初版响应有 4/6 直接通过结构与引用校验。另两条分别为模型输出前言、建议文案声称观众行为但没有对应证据。随后只在本地重解析已有回复：采用项目已有 JSON 解析逻辑，并将“不合格改稿”与“有依据的审核意见”分开处理，保留了 6/6 的意见、3 条通过现有格式/引用检查的文案建议、2 条边界建议；1 条无依据的新文案被丢弃。引用检查通过不等于事实正确。

所有建议均未应用。没有重切视频，也没有人工/逐帧验证建议边界，因此不报告起止时间精度提高了多少。

## 实现与开关

### ASR 溯源

主 ASR 写出 SRT 时新增同名 `.asr_evidence.json`：

- `sourceSpan.rawText`：音素纠正前的识别假设。
- `sourceSpan.recognizedText` 和 `phonemeCorrections`：原始段与音素改字记录。
- 行级 `recognizedText`：进入别名替换前的文本，可能已经音素纠正。
- `correctedText`：别名替换后、展示格式处理前的文本。
- 原始段起止、最终字幕行起止与文本、SRT SHA-256。

长段拆成多行时，保留的是同一完整源段，不伪造逐字原文对齐。没有原始文本就明确标为不可用，不做逆向替换。读取时核对 SRT 哈希、行数、时间和文本；文件过期、错配或损坏均不使用。

带说话人标签的 `.speaker.srt` 会去除标签后，与同名普通 SRT 的溯源逐行核对正文和时间；不匹配则拒绝关联，不把音轨/人名标签当成原始识别真值。

新增旁路记录不改变 SRT 的文本和时间；已有整场字幕不被批量回写。新证据会进入事件编排与最终文案的提示词，但不能当作人工真值。

### 可选独立审核

```json
{
  "clipTopics": {
    "review": {
      "enabled": false,
      "maxEvidenceChars": 40000,
      "timeoutMs": 120000
    }
  }
}
```

默认保持 `false`。改为 `true` 后，对已选择的最终片段增加关键词、文案两次审核；结果写到元数据的 `aiReview`、REVIEW 和通知中。只做 shadow review：

- 关键词为 confirmed/rejected/uncertain，调用失败单独标记 unavailable，不写成“审核通过”。
- 名称核验不读取旧标题和上传状态；文案审核单独接收待审稿。
- 支持字幕修改建议、片内证据约束的新文案建议、带 cue ID 的边界建议。
- 不自动复识别音频。历史实验中的双 ASR 尚未接入正式自动路径。
- 不自动改稿、改字幕、改边界、删候选、重做封面、排队上传；继续遵守现有人工批准流程。
- 超出证据预算不会静默取前几百字；审核不可用时保留候选并记录警告。
- 成功且校验有效的结果复用现有阶段缓存。

## 成本、失败与验证

- 本地 32 段 Paraformer ASR 共 132.03 秒，中位数 2.88 秒；SenseVoice 共 91.83 秒，中位数 1.82 秒。首段含模型加载，分别约 42.40/35.17 秒。统计不含 FFmpeg 提取，也不是整场端到端性能。
- 6 次单片文案审核为 20.21–116.06 秒/片。额外审核的代价明显，不宜无验证地加到每个候选上。
- 关键词实验 B 有一批返回缺失样本，整批被校验拒绝；重试该批后通过，其他五批复用缓存。未把不完整返回算成成功或自动否定。
- 初次实验遇到原有 60 秒超时并触发过配置中的 tuZi 备用路由，未得到可评估结果，随后停止该进程。正式对照和文案审核关闭备用服务，仅走 daiYu。没有向文本服务发送音频视频、账户数据或上传状态。
- 23 套相关 JS 测试共 329 项通过；8 项音素保护 Python 回归通过；TypeScript 类型检查和 build:check 通过。
- 当前环境没有 pytest，8 项既有无参 Python 用例通过标准库 unittest.FunctionTestCase 实际执行，不是只做语法检查。
- 架构检查未通过：检查时 `audio_processor.js`、`sensevoice_speaker.py` 超出既有行数预算；不是本次修改范围，未改动或提高预算来掩盖。

## 后续更合适的优化路线

1. **先标注再学习**：分开记录“是否提及”“是否值得发布”“字幕是否正确”“文案是否准确”。uploaded 仅作为优先复查的正例来源；未上传仍为 unlabeled，不生成伪负标签。
2. **将不同来源的 ASR 变体作为候选，而非定论**：显示原文、改字位置和另一读法，不把“小 C”直接认定为其他人。不要将另一个同音词补进强制替换表来掩盖不确定性。
3. **只复识别疑难命中**：命中来自低置信替换、孤立短句、另一实体名称或两模型冲突时，才取10–30秒原音频辅助人工核对。缺少独立证据时保持不确定。
4. **按主播和录播日期做留出集**：同一事件的重叠切片、双 ASR 和重复字幕不能当成独立样本，避免训练/评估泄漏。
5. **先锁定语义边界，再做时间精修**：cue ID 保证不凭空编时间；人工确认事件完整后，才用已有字时间戳/VAD或可靠强制对齐检查句首句尾。同音名字的语义身份不能仅靠声学对齐确定。
6. **以误杀与人工成本验收**：报告真实提及保留率、明确负例残留、每小时误报、不确定队列量和审核耗时。不要把 LLM 自报置信度当已校准概率。
