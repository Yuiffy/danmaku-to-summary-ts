# 完整游戏切片与外挂字幕

`streamGameClips` 保留指定房间的完整直播游玩过程。`games` 保存明确游戏及专用合集；生产配置中《艾尔登法环》继续进入原独立合集。用户授权的 `otherGames.enabled` 从与当前 SRT/XML、完整上下文摘要绑定的 `LIVE_CONTENT.json.content.games` 增补本场其他游戏，并使用 `otherGames.collection` 的默认合集（生产为“岁己游戏合集”）。固定游戏名称与别名优先，默认合集不会覆盖法环路由；概要只提供候选名称，仍须完整文字检测、独立画面、原音边界及投稿验收。缺失或过期概要保持失败，不当成无游戏。动态游戏 ID 由规范化名称稳定生成，集号沿用原场次登记。`authorizationNote` 必须明确覆盖该范围；识别本身不授权投稿。原有趣味切片、歌切和同步视听继续各自运行。

## 识别与完整性

每段源录播的所有 SRT/XML 窗口都必须检查完；检测失败、缺少 SRT、覆盖空洞不代表没有游戏。SRT 是混合音轨转写，XML 是观众发言，不能将弹幕当成主播说的话。检测保留启动、捏人、读图、探索、反复失败、跑尸、菜单、过场和收尾，按地点、Boss、阶段提供章节，不只取高光。

完整文本检测覆盖结束且没有游戏候选时，正常返回 `no_gameplay`（零投稿包、零分段），不进入抽帧、画面审核、渲染或上传；同源续做复用该结果，不因不存在游戏而触发后台失败重试。缺失转写、检测请求失败或覆盖未完成仍是故障，不能当成无游戏。此空结果以完整文本检测为准，不声明完成了独立画面检查。

存在游戏候选时，另以每 120 秒一张的整场原画面联系表独立检查所有采样，区别实玩、其他活动和观看游戏视频。相邻游戏菜单与实玩仍属于一个会话。画面出现前附近的转写启动点保留给原音复核，短于采样间隔的文字候选也保留给复核。采样检查是发现漏切的第二层，不能代替完整文本覆盖和精确边界检查。

时间轴抽帧按 JPEG 格式和解码尺寸校验，合法的黑场小图不按文件字节数判为缺帧。
快速跳转即使正常退出也可能没有生成末尾帧；此时最多向前解码十秒，再跳到同一源时间
重试一次，不能用附近画面代替该采样。仍无有效图则保留明确失败供恢复。

每个候选再次用原录播起止音频和章节画面核实真实游玩、完整起止及公开文案。未知地点/Boss 名称使用有证据的阶段标题；无法确定的边界或文案暂停该录播，保留源文件和具体原因。真实家庭/家庭关系内容遵守房间排除规则，游戏虚构人物对白不按真实家庭话题排除。

原音复核 v2 必须分别记录两段音频实际听到的话和每张原帧的观察；保留区间内至少一帧可辨认的直播实玩才能通过。聊天、周边海报和播放器内的他人游戏画面不能作为实玩证据。未渲染的旧复核在恢复时升级检查，已投稿的验收包继续复用，避免重复投稿。

窗口切换或捕捉故障可能让开局准备很长；视觉合并保留文字检测到的真实启动候选，不以固定十分钟阈值截掉准备过程。起止复核若看到保留区间之外还有实玩，必须重新找边界或保留不确定，不能宣称已覆盖全程。

原音复核 v3 对通过章节检查的候选增加独立起止检查：只向模型提供原音和附近画面，不提供字幕或检测结论。开局和收尾各用一个原音请求，防止两段原话串位；候选边界向前保留上下文，开局原音至少覆盖首次游戏采样附近，收尾原音围绕候选退出点，整场画面另行检查。保留较长的捕捉设置和退出处理。模型独立选择真正开局和最后收尾的原话，程序将该原话绑定到相应音频范围内唯一、连续的原字幕句，按整句起止校准边界；模型估计的秒数仅保留作诊断。原话缺失、重复歧义、边界未知或保留区间之外仍有实玩都会停止投稿，不能用字幕推测代替原音观察。完整性检查保留尚未被后续窗口确认的原始启动/结束候选，不让稀疏画面取代真正的退出点。

旧 ASR 的文字与时间戳若和原音矛盾，保留原 SRT，并用当前完整文本/字符时间戳转写重建独立字幕。重建后按新字幕源签名重新检测、核对公开章节和边界；相同原媒体的完整画面审计可复用，不能沿用错误字幕的证据编号或审核结论。

复核协议 9 将收尾原话和最终视频结束点分别保存。原音确定最后收尾原话后，逐张检查其后每两秒的原画面，保留无声的退出确认、标题/加载画面和游戏图层淡出；发现延后退出时，将最后游戏画面到纯聊天画面的过渡细化到 0.25 秒。仍有游戏、画面不明或没有足够后续证据时保持待核。验收重新计算结束点并校验所有收尾原帧的摘要，不能用“收尾说完”替代真正退出。已投稿包继续复用，不因协议升级另投。

游戏文字检测默认使用 `streamGameClips.ai.provider=daiYu`，不受全局文字 provider 的覆盖；该默认路线的严格检测失败会保留错误。章节、专名、文案及开场/收尾画面核验通过 `ai.frameModelProfile: "pro"` 使用共享路线：带鱼 `gpt-6.1-sol` → 智谱 `glm-5.3` → DeepSeek `deepseek-flash`，媒体请求统一用 `openai_chat`。各站使用自己的凭据，保留所有原帧和本地独立转写，不追加 luna 或 tuZi。未配置 profile 时仍兼容 `frameProvider/frameApiMode/frameModel` 的固定路线。缓存绑定已解析的整条路线、原媒体身份和证据窗口；失败或结果不确定仍保留待核。

`ai.boundaryEvidenceMethod` 默认是 `independent_local_asr`：协议 10 / 复核 v4 先从原录播提取起止音频，单独运行本地 Paraformer，不向听写提供源 SRT、检测结论或改词规则，再用独立转写与原帧交给上述画面 provider 判断启动和收尾。图片模型只收到转写和图片，不能宣称听过原音。开/看/卡等开局动词歧义另取原音短段重听；未解决的歧义保留待核。程序将同一原话分别绑定到新听写与源 SRT 的唯一连续句，两个边界时间相差超过三秒会拒绝。音频、提取参数、源媒体身份、听写与出处文件都有摘要，投稿验收重新读取这些证据及所有章节/收尾原帧。需要其他原生音频服务时，须显式选择 `native_audio` 并配置 `boundaryProvider/boundaryApiMode/boundaryModel`；不会因本地 ASR 失败自动启用 tuZi。v3 的非原生音频诊断仍不能投稿，不能只改方法字段来升级旧诊断。

没有可辨认实玩原帧的文字候选，用覆盖整个候选和前后文的独立原音转写、原帧另查复盘、推荐、读观众消息和其他活动。只有明确证明整段不是实玩才能排除，疑似窗口外操作或画面不明仍待核。该排除流程不能产生可投稿的 keep。整场稀疏图片服务继承章节图片配置，也可用 `visual.provider/apiMode/model` 单独配置；不确定采样用相同的独立原音方法复核，不能向只读图服务发送音频后声称听过。

文字无法落实名称的章节可再查该阶段原帧，只有 Boss 血条、地点横幅或地图实际拼出拟用名称才恢复专名。原帧、精确时间、可见标签和模型原始回复一起绑定，投稿前再次验证，场景外观或常识不能替代文字证据。公开标题优先采用已核实的 Boss/地点名称，简介仍按完整游玩顺序提供章节。

文字检测的 `nameEvidence` 必须是所引字幕/弹幕实际出现的名称文字，不能填 T/D 引用编号；编号误填会退回检测修正，不直接降级成空泛阶段。普通敌人可由文字证据落实名称，不强求 Boss 血条。原帧读到的正式名称与拟定俗称不同时，可用 `correctedTitle` 将标题替换为原帧标签本身，继续接受完整章节复核，不凭俗称推定别名或胜利。总标题在 40 字焦点预算内优先保留至多三个已核实地点/Boss，分 P 标题也优先选本 P 实际包含的具名章节。

协议 11 对章节文案的具体拒绝提供一次自动修订机会：用该阶段完整原字幕及已提取的原帧提出更简洁、事实有据的标题/简介，保留已核实的名称，再重新运行完整原音、原帧与文案复核。提议没有审核权限，不会清空边界疑点，也不会调整时间或字幕。同一章节最多自动提议一次；再次不通过仍保留待核。提议原始回复、改前/改后文案和原帧摘要绑定到验收包，投稿前重新核验。

章节改写策略 v2 只陈述一个有依据的活动或讨论，标题最多 24 字、简介最多 48 字；
已由原帧核实并锁定的名称保留原标题。删掉导致拒绝的细节，不再逐帧串写骑乘、
地形或动作顺序，也不把路线询问写成已完成的行动。尚未制作的失败章节若已有 v1
改写，可按 v2 再提议一次，保存 `previousRevision` 和 `policyVersion`；同策略不会
反复提议。完整原音、原帧和文案仍须重新通过复核，已完成或已投稿包继续复用。

修订文案同步绑定本阶段实际原字幕编号，保留旧引用，避免沿用相邻阶段的证据。同起点的不同章节分别复核，共用直到下一个不同起点的阶段范围；图片与章节的原始索引不能合并、遗漏或重新编号。

收尾的暗帧若在随后已确认的游戏画面之前，整段仍完整保留，不以该暗帧提前结束。最后确认游戏画面之后的暗帧会连同相邻原图、原分辨率目标图再次独立核验；能辨认残留菜单或标志时保留到淡出结束，仍无法辨认则继续待核。验收绑定补查图片和原始回复，不可手改判断来消除疑点。

源字幕与独立听写对同一句话的分句不同，可能令短引文落在不同的整句起止。源字幕命中的完整句段原文须在独立听写中唯一连续出现，或其句首/句尾原文须唯一出现并紧邻已独立识别的短引文，才能对齐整句；上下文连续性和时间仍满足原三秒限制。保存短引文及句段上下文两种出处，投稿验收重新计算。未听到的上下文、重复歧义和真实时间漂移仍拒绝。

长听写句段中的开局歧义会补取短原音独立转写。只有短段仍唯一包含同一引文、其原音窗口包含于先前窗口，且更细的引文范围落在原粗范围附近并与源字幕满足原三秒限制，才能解决粗分句的时间差；保留粗、细两套原音、听写和出处。不能用不相交的另一处同名句或模型猜测的秒数消除时间漂移。

定向短段转写采用字符时间戳的小段，避免长哼唱或谢礼句的起点被误用为稍后开局原话的起点；使用独立证据目录保留先前粗分句转写。仍以相同字面引文、原始声学时间和三秒误差限制核对，不根据文字长度推算秒数。

已审核原帧在三十秒内从聊天或黑屏转到游戏时，附近五秒内包含“我来了”“我走了”“我要离开”等歧义过渡词的独立听写也补取短原音精细转写。这只补充音频证据，不把短句本身认定为开局；模型仍须结合真实画面和前后语义判断，未解决的语义歧义继续待核。

协议 12 允许单独验证无声开局。只在独立原音开局判断待核、原帧已有三十秒内的最早聊天到游戏转场时尝试；保留已确认的口头开局分支。新分支重新查看完整前文独立 ASR、窗口开头和全部相关原帧，必须明确证明窗口从无关活动开始、整个前文没有更早或歧义的启动准备、确为本人的无声游戏转场。没有找到口头开局句本身不足以通过。仅在原转场区间补两秒原帧，再将首个可辨游戏画面与此前最后确定非游戏画面夹逼到 0.25 秒以内，从后者开始保留完整淡入和菜单；任何黑帧、未知画面、疑似更早准备或非最早转场均拒绝。不开固定前摇，不把游戏画面之后的口头句子当开局。

无声分支标记 `original_visual_transition`，没有 `heardWords` 引文，结束仍使用原有独立原话和退出原帧规则。`clipping/gameOpening` TypeScript stage 保存原图提取收据、媒体/ASR出处、每批原始回复及输入绑定、完整前文审核，Node 缓存验收与 Python 投稿验收都重新校验文件摘要、所有帧观察和时间。细采样追加后保持原始样本 ID，按时间排列但不重编号，每批 ID 必须不重不漏地覆盖全部样本。旧已完成投稿包直接复用；新协议沿用相同原媒体提取目录，独立缓存新审核，不重复转写已有粗 ASR。

协议 13 补充保守保留开局前文：独立 ASR 中有可能是更早准备的短句时，可选取最早相关的完整原始句段，从该句段真实起点一直保留到首个游戏画面及后续全程。仅审核将被排除的更早前文，必须明确证明它从无关活动开始、没有更早可能准备；保留区间内的语义歧义无需被强行解释成确定开局。原帧仍按原规则精确验证最早游戏出现，游戏归属、排除内容、窗口外活动或遗漏仍不明时继续待核。新分支标记 `original_visual_context` / `before_retained_context`，不冒充听到的开局引文；保留句段的原索引、完整文字及声学时间与完整独立听写和原始答复绑定，Node 与 Python 验收均重新计算起点。旧无声开局和已投稿包继续兼容。

章节原帧使用所选画面 provider 的多模态请求，每批最多八张；每条公开章节文案必须有独立检查结果。单张稀疏采样不足时，补查该章节前、中、后三张原画面和对应阶段的完整字幕，证据仍不足就保留待核。新复核协议不重新渲染或投稿已完成的源。

章节审核策略 v3 聚焦公开标题、简介的实质准确性，不因修辞偏好、缺少可选细节或稀疏截图未拍到已有文字支持的动作而拒绝。首轮提供相关章节的完整阶段字幕，减少截断上下文导致的补查。普通 `phase` 章节未出现在公开文案中的旧 `nameEvidence` 仅是内部检测提示，不送入文案审核；原计划保留该字段和修订历史。公开文案实际使用的名称、会进入总标题的 Boss/地点名称和原帧锁定名称仍须核实。策略更新单独失效未通过的章节审核缓存，复用原音、原帧和独立听写；完整性、原音边界及投稿验收保持原有要求，已完成或已投稿包继续复用。

均重读完整 ASR 出处、原图提取收据、每批原始回复和上下文输入绑定，重新计算结束点。
开局补查可用维护适配器的 `openingContextSeconds` 在原有 600 秒上限内扩大原音窗口；
维护恢复可复用旧审核目录中的原音听写，投稿验收按所绑定的真实路径重读提取收据、
源身份、窗口及全部摘要，不要求音频复制到新审核目录，也不因目录复用豁免证据校验。
它不改变文字检测配置或重新扫描全场。旧已投稿包和原有口头收尾规则继续复用。
窗口内找不到最早开局转场时，可一次扩大开局原音到原有 600 秒上限；收尾仍缺少明确
无关后文时，可一次扩大至 600 秒后文。仅补充真实原音和
原图，重新执行完整审核并复用相同证据的缓存；窗口扩大本身没有通过或排除权限。
开局 v3 另可保守保留含黑屏的启动过程：完整独立原音必须提供真实的最早可能准备句段，
且其起点严格早于所有可能游戏或不明原帧。此前原帧与完整语音须均可排除更早准备；
后续必须出现已确认的本人的目标游戏。窗口内原帧最长三十秒覆盖，所有不明图层均在
保留起点之后连续保留。该分支不声称找到了精确的首个游戏像素，记录 `sampleSeconds:30`、
`resolutionSeconds:null`，仍以原 ASR 整句起点确定保留边界。没有真实准备句、窗口一开始
就有不明图层、准备句晚于不明原帧或游戏归属不明仍拒绝；不能把黑屏改判成其他活动。
同场早段可能在聊天图层背后编译着色器或调整设置，实玩却在长时间无关活动后才开始。
这类候选不能仅因没有实玩原帧被排除，也不能冒充实玩通过常规审核。只有本源后续已有
完整通过原音、原帧和章节检查的同一游戏场次，才可另查 `preparation_only` 准备段。
独立审核必须以完整早段原音转写、早段原图、后续实玩原图与独立开局转写，证明当前
真实设置操作及同一游戏归属；共享录播或检测名单本身不构成归属证据。保留最早至最后
可能相关的完整听写句段，并证明被排除的前后文均为无关活动。归属、设置语义或前后
完整性仍不明则待核。公开文案只表述实际准备，不称已有实玩。准备段不能给另一个
准备段作实玩证据；Python 投稿验收重新完整检查所绑定后续场次的原音、边界、原帧与
章节证据，不依赖其旧的 keep 字段。已成功视频仍复用原 ID。
章节改写后的复核若暴露另一章的问题，可继续为该章提议一次；同策略下每章仍最多
修订一次，边界不明或无可修订章节时停止，不通过循环重试消除真实疑点。

### 本场游戏锚定（防串游戏）

`LIVE_CONTENT.json` 已核实的 `content.games` 是本场真正玩过的游戏；`games` 配置里的固定条目（如《艾尔登法环》）只是长期允许名单，不代表本场玩过。两者混在一起平权交给图片模型时，同类型动作 RPG 会按画风被判成另一个游戏，进而把整段实玩当成“其他游戏”丢掉。2026-11-01 的《影之刃零》Boss 战就曾因此被判成《艾尔登法环》，误杀约 95 分钟。

现在整场画面检查、单采样复核都带本场锚点：本场只有一个已核实游戏时，提示词明确说明其他允许条目只是常驻配置，画风、镜头、配色或魂类血条都不构成证据；确实要判成另一个游戏，必须同时返回 `textEvidence`，逐字引用画面上读到的该游戏标题或独占界面文字。没有这段文字证据时，`parseTimeline` / `parseSampleReview` 会把该段归并回本场游戏，并在 `ranges[].note`、`timeline.anchorCorrections` 和 `TIMELINE.json` 里留痕，不会静默改写。没有 `catalogEvidence`（例如固定法环场）时行为不变。

### 覆盖度守卫（防静默丢内容）

错的 `other` 判定不会报错，只会得到一集更短的视频。渲染前由 `stream_game_coverage.js` 对比文字检测的原始游戏时段与画面时间轴实际保留的部分：某段长候选只保留了一部分（保留比例在 5%–85% 之间）且丢弃超过 20 分钟或 15% 时触发告警。整段被判为其他活动的候选不算丢失，它们本来就要经独立原音边界复核。

触发时写出 `COVERAGE.json`（每段候选的保留/丢弃分钟数、丢弃区间、邻近判定理由）和 `COVERAGE_SHEET.jpg`（每个最大丢弃区间三帧，带时间码），一条日志 `[GAME_COVERAGE_ALERT]`。默认 `visual.coverageGuard=warn` 只告警不阻断；改成 `fail` 会在渲染前停止并保留源文件，适合无人值守且绝不能误发的阶段；`off` 关闭。阈值是 `visual.coverageMinDroppedMinutes`（默认 20）和 `visual.coverageDroppedRatio`（默认 0.15）。

### 原帧名字纠错（防形近误读）

原帧核对是“逐字读血条”，但视觉模型仍可能把形近的字读错。2026-11-01 的血条 `斧老大：彭猛` 被读成 `斧光大：彭猛`，同场的 `新娘阿花` 被读成 `斩娘阿花`——两个字各差一笔，肉眼扫过几乎看不出区别，但会一路传到分 P 标题、描述和总标题。

`stream_game_name_spelling.js` 在章节命名之后、拼分 P 之前，用录播同目录的弹幕与字幕给画面名字“对音”：只在长度相同、仅差一个字、且观众写法出现 ≥3 次并至少是画面写法 3 倍时替换（那场弹幕打了 13 次 `斧老大`、0 次 `斧光大`），两字名字不做替换（差一个字就占了一半，容易误伤）。血条形如 `称号：本名` 时，若弹幕只喊称号（`斧老大` 13 次、`彭猛` 0 次），发布名取 `斧老大`，分隔符保持原样。只处理 `nameEvidenceSource=original_frame` 的章节；主播亲口说出来的名字不是 OCR，不参与改写。

改写保留全部痕迹：章节上写 `nameCorrection`（原字面、发布名、每次替换的观测次数），`frameNameEvidence.correction` 记下字面与发布名的差异，日志输出 `[GAME_NAME_SPELLING] 斧光大：彭猛 → 斧老大`。没有弹幕或字幕时整步跳过，画面字面原样保留。

### 标题焦点规则（按重要性选，不设配额）

总标题固定为 `<游戏名> 第NN集｜<焦点> <日期>`，焦点由 `stream_game_focus.js` 选出。早期版本按“2 个 Boss + 1 个地点”的固定配额取，遇到一晚连打三个重要 Boss 就会丢掉第三个，遇到纯探索场又硬凑一个 Boss；配额取消后改为对每个候选打分取最高的。

打分来源分两层：

1. **结构**（无弹幕也能用）：Boss 12 分、具名地点 5 分（驿站/营地/篝火这类补给点只算 2 分）、有 `nameEvidence` 加 6 分；同一实体反复出现的章节数按对数加分（打了五遍的 Boss 比一遍过的重要），时长每 5 分钟加 1 分（上限 6）。
2. **观众反应**（`stream_game_audience.js`，直接读录播同目录的 XML/SRT）：某章节窗口内的弹幕峰值（60 秒滑窗）相对整场中位数的倍数、弹幕与字幕点名该实体的密度（字幕权重更高，主播亲口说才算数）、SC 金额与礼物件数。SC/礼物取自录播姬 XML 里的 `<sc price>`、`<gift giftcount>`、`<guard>`（`ts` 是绝对时间，用首条弹幕自带的 Unix 时间戳换算成相对秒；录播姬没开这几类记录时该信号为 0，也可用 `<stem>.gifts.json` 边车补）。这些全是确定性计数，不调模型，标题因此可复现、可解释。

数量不是配额而是预算：最多 4 个标签、总宽度 ≤ 30 全角字符，低于最高分 55% 的候选不进入标题，避免用零碎地点凑长度；若预算允许，仍会补一个 Boss 和一个非补给类地点作为叙事骨架。Boss 在前、各自按游玩顺序排列。

标签归一在选之前完成：

- `阿花 / 新娘阿花 / 斩娘阿花` 合并成一个实体，保留最具体的写法；`叶师傅 / 叶师傅处 / 与叶师傅交手` 统一成 `叶师傅`（Boss 章节优先于地点章节命名）。
- 相邻且中间没有其他章节的地点章节合并成一个区域（`驿站 → 杀气塔 → 高塔 → 地下室` 视为一段，取名 `杀气塔`），避免地图碎片占满标题。
- 连续地点章节里若弹幕主要在喊另一个 Boss 的名字（2026-11-01 的“鬼新娘”窗口里 25 条弹幕在聊“阿花”，自称仅 1 条），判为同一场战斗的别名并合并。
- 去掉“连续挑战/反复尝试”这类重试噪声、“启动游戏/调整键位/探索与战斗”这类流程标题，以及“沿溪流探索/搜寻屋顶物品”这类动作短语。

2026-11-01 的真实回放：自动标题 `斧老大连续挑战、斧光大：彭猛、阿花` → 名字纠错把 `斧光大` 还原成 `斧老大`、`斩娘阿花` 还原成 `新娘阿花` → `斧老大、新娘阿花、杀气塔`；2026-11-02 → `追命、叶师傅、杀气塔`。每个标题的入选理由写在 metadata 的 `copy.focus`（弹幕峰值、点名次数、礼物额），落选的前 8 个候选写在 `copy.candidates`，人工复核时能看出为什么某个 Boss 没进标题，不必重跑。

### 输出截断自动升级

图片请求返回 `finish_reason=length`（含 `MAX_TOKENS`）时，`requestMediaVerification` 会把 `max_tokens` 翻倍（上限 32768）重试一次再判定失败。始终思考的模型先耗光预算再输出 JSON 时，不必再改配置重跑整场。

## 投稿组织与平台权限

渲染前和真实上传前都查询官方视频投稿页使用的 `archive/white` 与 `archive/pre` 接口，不能用创作中心通用 `white` 的同名字段替代。`have_permission_of_p` 确认当前网页投稿渠道能否新投多 P，`new_web_edit.max_count` 给出当前 P 数上限，`season_add_multip` 单独确认多 P 入合集权限；这些字段不能推导出其他客户端的资格或统一粉丝/等级门槛。未开通多 P 时，每场游戏按约 60 分钟上限拆成单 P 稿件，优先在地点/Boss/阶段章节处分段，避免极短尾段；同场保持一个集号，用（1/3）等编号，简介提供时间轴。允许多 P 时，同场章节集中在一个投稿包，超过本地 P 数保护才另拆投稿。

单视频时长和文件体积按当前账号能力限制。默认单视频最大 3600 秒；如果实际输出仍超文件限制，自动保存该源的时长约束，继续拆短后恢复，不降低码率或修改原编码画质设置。游戏优先复制原视频和音频码流，检查实际时长及导出的前三个解码画面与指定源起点逐帧一致，避免关键帧起点偏移；实际输出时长误差不能超过 0.25 秒。生产配置的 `requireOriginalStreamCopy: true` 落实用户保留原码流的要求：复制或边界校验失败时停止该场制作并保留原因，不能自动重编码。该选项默认关闭，其他配置可继续使用既有编码回退和自动资源调度。视频不烧录字幕。成功或已入队的媒体重跑时复用原验收包，不因新分段或编码方式另投一遍。

投稿数量按稿件计算，各 P 不各占一个稿件。现有队列的 90 稿/滚动 24 小时是本项目的保守保护值，不是所有账号统一的平台上限；137022 等平台限频仍按实际响应退避。多 P 权限、文件限制和限频是不同限制，查询结果会随账号和平台变化。字幕或合集失败时保留已成功的 BV，禁止重新发视频来补传。

原码流复制若仅出现大于 0.25 秒且不超过 0.5 秒的轻微尾部超时，可从同一源、同一起点
自动重封装一次，将复制时长最多缩短 0.25 秒。仍须满足原定区间的 0.25 秒时长误差和
前三个解码原帧逐帧一致，保存 `processing.copyTailAdjustmentSeconds` 供诊断。明显超时、
短缺、无效时长或重试后仍不合格均停止；该恢复不重编码，也不修改审核区间。

## 运行与恢复

录播下播后由 `background_clip_runner` 调用完整游戏流程，审核通过的产物进入已有单实例投稿队列；未知/失败内容保留源文件，不阻止其他切片流程。默认配置关闭自动投稿，生产配置启用已授权范围。

自动后台顺序为普通切片、歌切、完整游戏切片、同步视听。游戏流程在目录内逐请求保存 `AI_USAGE.games.json`，按阶段和模型统计文本检测、全场画面、章节、边界等实际请求的 token、失败及未知用量，另记缓存复用和本地 ASR 时长。每次结束或失败后发送企微汇报；`streamGameClips.notify.enabled=false` 可关闭。报告提供本次及启用统计后的累计值，缺失字段保持未知，缓存/推理明细不重复相加；通知失败不重跑模型。具体口径与通知状态见[活动切片用量说明](stream-activity-clips.md#ai-用量与企微汇报)。

```powershell
$env:NODE_ENV = 'production'
npm run game:clips -- plan --media 'D:\录播.flv' --srt 'D:\录播.srt' --xml 'D:\录播.xml'
npm run game:clips -- run --media 'D:\录播.flv' --srt 'D:\录播.srt' --xml 'D:\录播.xml'
npm run game:clips -- inventory --root 'D:\files\videos\DDTV录播\25788785_岁己SUI'
```

`plan` 只完成文字检测；`run` 完成整场画面、原音复核、渲染、字幕、验收及配置允许的入队。`--no-register` 可制作本地包。历史补录可用 `--episode <集数>`；`data/runtime/stream_game_episodes.json` 将场次身份与集数绑定，重跑保持集号且拒绝另一场复用。检测缓存、失败窗口及已完成媒体按源身份和参数恢复。

用户选择整场游戏联动合辑时，`run --combine-games` 将同一录播、同一合集的多款游戏
作为连续场次处理。保留游戏之间的全部过渡，只核验整段外侧开头和结尾，公开章节
按游戏列出；整场覆盖、内容排除、原音原帧、原码流和外挂字幕验收照常执行。原检测
事件保存在 `sessionCombination.originalEvents`，不将分场的待核边界当作通过。平台
不支持多 P 时按能力拆成连续编号稿件。已制作或已投稿的源继续复用原稿件，不能借
合并产生第二套投稿。
维护适配器的 `continuousEventIds` 可将同一游戏连续的候选段连同重启、排障间隔保留为
一段，原事件保存在 `gameContinuation`。不得跨过其他游戏、继承旧审核或另投已完成源；
合并后的外侧边界和全部章节仍重新验收。细采样才发现的含混淡入会转入现有保守前文
分支，仍需真实更早准备句及完整原帧、独立听写证明，不能把不明淡入改判成游戏或聊天。

用户选择保守保留最后一场游戏的全部后续时，维护适配器可用
`retainRecordingEndEventId` 指定最后一个事件。收尾 v3 连续保留到真实源时长，最多补充
一小时；完整独立原音和最长三十秒覆盖的原帧必须重新证明游戏归属与内容允许。
已有密集原帧和听写按原提取收据复用。该分支不声称观察到退出，不要求被完整保留的
排障或聊天已经无关，也没有排除的后文；`laterContextUnrelated` 与 `retainedTail` 均为
null。源时长、完整原音窗口、每张原图、每批原答复和 EOF 保留判断在 Node/Python
投稿验收重新核对。非最后事件、超过补充范围、缺失或不允许的内容继续拒绝；普通
精确收尾的两秒/0.25 秒规则保持原样，已完成源仍只复用原投稿。

准备段的归属缺少画面证据时，维护适配器的 `preparationFrames` 可按事件 ID 补充至多
两张处于完整原音窗口内的真实原图，合并包仍不超过八张，提取收据与原始回复照常绑定。
观众画面文字只能作为观众证据，结合主播独立原音判断，不能归为主播原话。审核仅判断
被排除的前后文是否无关，保留区间内的含混语义不被强行解释；章节时间是阶段标签，
不要求把此前已经保留的准备删除，也不能将“讨论难度”误读成“实际选择难度”。

关闭自动投稿时，检查本地完整媒体和文案后可用 `npm run game:clips -- approve --metadata 'D:\...\elden-ring_E001_1.json' --note '已核对完整游戏及文案，用户已授权投稿' --enqueue` 刷新验收并加入队列。已成功的投稿不会再次加入队列。

产物位于 `stream_game_clips/<录播基本名>/`，归档源通过现有 D/E 映射写回 D。`PLAN.json` 保存完整覆盖、章节、排除区间和独立复核；签名子目录保存无烧字 MP4、各视频重置时间的 SRT、封面、投稿元数据、`UPLOAD_MANIFEST.json`。`REVIEW.md` 提供集名、简介与本地文件。媒体、字幕、顺序、文案和合集绑定 `gameReview`，修改后必须重新验收，不能手改队列或审核摘要绕过。

## 外挂字幕投递

视频投稿成功后，在创作中心查询真实 P 顺序、标题、时长和 CID，与已验收媒体逐一绑定，然后提交字幕。验收元数据使用 `zh-CN` 表示简体中文；当前平台接口使用语言代码 `zh`，不依赖 SDK 中过时的语言目录。CID 尚未生成时单独等待和重试，不重复视频投稿。每个 BV 的任务保存于 `data/runtime/game_subtitle_tasks/`，每个 CID 的已提交字幕只提交一次。

`game-subtitle-queue-runner` 是独立 PM2 服务，每 30 秒检查可重试任务。字幕 POST 超时可能已成功；保存为 uncertain，仅通过读取线上同 CID、同语言且同字幕正文确认，不盲目再次 POST。OS 文件锁随进程退出释放。字幕完成状态同步回原投稿状态和注册表。

### 本地画面预分析

游戏整场画面抽帧后会先运行一次本地 `stream_game_local_cv` 预分析。它使用现有
`sharp` 计算亮度、暗帧比例、边缘密度、颜色比例和相邻帧差，保存到同场景的
`temp/game-timeline/<key>/LOCAL_EVIDENCE.json`，并在 `PLAN.json` 的视觉时间线中保留
`localEvidence`。本地结果会和文字检测到的游戏窗口一起选择少量上游视觉复核样本：长时间
稳定区按较稀疏的节奏送审，场景切换、候选死亡画面和游戏边界附近的样本强制保留；每批请求
最多 `maxFramesPerBatch` 张联系图，单批失败可以独立重试。相邻 AI 结果一致且没有本地切换信号
时，省略样本才会标记为本地稳定插值，其余样本继续待核，不会被静默当作实玩。`deathCandidates`
只是疑似死亡画面的时间簇，不能直接当作死亡次数、击杀结果或投稿依据；最终仍由原帧、原音
和现有审核门确认。这样可以减少单次请求的图片数量并复用整场抽帧，降低上游超时或 503 导致
整场失败的概率。

阈值位于 `streamGameClips.visual.localEvidence`：`sceneCutThreshold`、`deathThreshold`
和 `deathMinGapSeconds`；上游取样位于 `streamGameClips.visual.aiSampleSeconds`、
`aiOtherSampleSeconds`、`aiBoundaryPaddingSeconds` 和 `maxFramesPerBatch`。本地预分析不请求
网络、不下载模型，也不会自动把不确定窗口标成已通过。后续可在此证据上增加 OCR/模板匹配或
OpenCV 后端，仍应保留候选语义并由独立音画审核决定是否计数。

新稿在创作中心已有 CID，字幕接口仍可能明确拒绝 `79022 当前视频不存在`。此时等待稿件处理/公开后，只重试该 BV 的字幕，按退避延迟恢复；视频和合集不重新投稿。只有确认接口拒绝的提交可以重试，结果未知的 POST 保持只读核实。

```powershell
npm run game:subtitles
pm2 start ecosystem.config.js --only game-subtitle-queue-runner --env production
# 仅恢复明确返回 79011 的语言拒绝；不重复提交已成功或结果未知的字幕
python src/scripts/game_subtitle_upload.py --retry-rejected-language BVxxxxxxxxxx
```

合集创建/复用使用 `npm run game:collections`，具体参数见 `--help`。展示用 season ID 与实际添加稿件用 section ID 分别保存，游戏合集不会改变通用房间合集路由。
