# 完整游戏切片与外挂字幕

`streamGameClips` 保留指定房间、指定游戏的完整直播游玩过程。生产配置目前仅允许岁己房间 `25788785` 的《艾尔登法环》，使用独立合集；原有趣味切片、歌切和同步视听继续各自运行。用户的历史整理和后续自动投稿授权保存在 `authorizationNote`，不能把识别到其他游戏当成新的投稿授权。

## 识别与完整性

每段源录播的所有 SRT/XML 窗口都必须检查完；检测失败、缺少 SRT、覆盖空洞不代表没有游戏。SRT 是混合音轨转写，XML 是观众发言，不能将弹幕当成主播说的话。检测保留启动、捏人、读图、探索、反复失败、跑尸、菜单、过场和收尾，按地点、Boss、阶段提供章节，不只取高光。

另以每 120 秒一张的整场原画面联系表独立检查所有采样，区别实玩、其他活动和观看游戏视频。相邻游戏菜单与实玩仍属于一个会话。画面出现前附近的转写启动点保留给原音复核，短于采样间隔的文字候选也保留给复核。采样检查是发现漏切的第二层，不能代替完整文本覆盖和精确边界检查。

每个候选再次用原录播起止音频和章节画面核实真实游玩、完整起止及公开文案。未知地点/Boss 名称使用有证据的阶段标题；无法确定的边界或文案暂停该录播，保留源文件和具体原因。真实家庭/家庭关系内容遵守房间排除规则，游戏虚构人物对白不按真实家庭话题排除。

原音复核 v2 必须分别记录两段音频实际听到的话和每张原帧的观察；保留区间内至少一帧可辨认的直播实玩才能通过。聊天、周边海报和播放器内的他人游戏画面不能作为实玩证据。未渲染的旧复核在恢复时升级检查，已投稿的验收包继续复用，避免重复投稿。

窗口切换或捕捉故障可能让开局准备很长；视觉合并保留文字检测到的真实启动候选，不以固定十分钟阈值截掉准备过程。起止复核若看到保留区间之外还有实玩，必须重新找边界或保留不确定，不能宣称已覆盖全程。

原音复核 v3 对通过章节检查的候选增加独立起止检查：只向模型提供原音和附近画面，不提供字幕或检测结论。开局和收尾各用一个原音请求，防止两段原话串位；候选边界向前保留上下文，开局原音至少覆盖首次游戏采样附近，收尾原音围绕候选退出点，整场画面另行检查。保留较长的捕捉设置和退出处理。模型独立选择真正开局和最后收尾的原话，程序将该原话绑定到相应音频范围内唯一、连续的原字幕句，按整句起止校准边界；模型估计的秒数仅保留作诊断。原话缺失、重复歧义、边界未知或保留区间之外仍有实玩都会停止投稿，不能用字幕推测代替原音观察。完整性检查保留尚未被后续窗口确认的原始启动/结束候选，不让稀疏画面取代真正的退出点。

旧 ASR 的文字与时间戳若和原音矛盾，保留原 SRT，并用当前完整文本/字符时间戳转写重建独立字幕。重建后按新字幕源签名重新检测、核对公开章节和边界；相同原媒体的完整画面审计可复用，不能沿用错误字幕的证据编号或审核结论。

复核协议 9 将收尾原话和最终视频结束点分别保存。原音确定最后收尾原话后，逐张检查其后每两秒的原画面，保留无声的退出确认、标题/加载画面和游戏图层淡出；发现延后退出时，将最后游戏画面到纯聊天画面的过渡细化到 0.25 秒。仍有游戏、画面不明或没有足够后续证据时保持待核。验收重新计算结束点并校验所有收尾原帧的摘要，不能用“收尾说完”替代真正退出。已投稿包继续复用，不因协议升级另投。

章节和收尾图片服务可通过 `streamGameClips.ai.frameProvider/frameApiMode/frameModel` 配置，独立原音服务使用 `boundaryProvider/boundaryApiMode/boundaryModel`；默认使用 TuZi 的 Gemini 原生请求。图片服务能读图不代表能读取音频，不能仅凭请求成功改用它做原音审核。缓存分别绑定服务、模型、协议、原媒体身份和证据窗口。

`ai.boundaryEvidenceMethod` 默认是 `native_audio`。可显式选用 `independent_local_asr`：协议 10 / 复核 v4 先从原录播提取起止音频，单独运行本地 Paraformer，不向听写提供源 SRT、检测结论或改词规则，再用独立转写与原帧判断启动和收尾。图片模型只收到转写和图片，不能宣称听过原音。开/看/卡等开局动词歧义另取原音短段重听；未解决的歧义保留待核。程序将同一原话分别绑定到新听写与源 SRT 的唯一连续句，两个边界时间相差超过三秒会拒绝。音频、提取参数、源媒体身份、听写与出处文件都有摘要，投稿验收重新读取这些证据及所有章节/收尾原帧。v3 的非原生音频诊断仍不能投稿，不能只改方法字段来升级旧诊断。

没有可辨认实玩原帧的文字候选，用覆盖整个候选和前后文的独立原音转写、原帧另查复盘、推荐、读观众消息和其他活动。只有明确证明整段不是实玩才能排除，疑似窗口外操作或画面不明仍待核。该排除流程不能产生可投稿的 keep。整场稀疏图片服务继承章节图片配置，也可用 `visual.provider/apiMode/model` 单独配置；不确定采样用相同的独立原音方法复核，不能向只读图服务发送音频后声称听过。

文字无法落实名称的章节可再查该阶段原帧，只有 Boss 血条、地点横幅或地图实际拼出拟用名称才恢复专名。原帧、精确时间、可见标签和模型原始回复一起绑定，投稿前再次验证，场景外观或常识不能替代文字证据。公开标题优先采用已核实的 Boss/地点名称，简介仍按完整游玩顺序提供章节。

协议 11 对章节文案的具体拒绝提供一次自动修订机会：用该阶段完整原字幕及已提取的原帧提出更简洁、事实有据的标题/简介，保留已核实的名称，再重新运行完整原音、原帧与文案复核。提议没有审核权限，不会清空边界疑点，也不会调整时间或字幕。同一章节最多自动提议一次；再次不通过仍保留待核。提议原始回复、改前/改后文案和原帧摘要绑定到验收包，投稿前重新核验。

章节原帧使用 Gemini 原生多模态请求，每批最多八张；每条公开章节文案必须有独立检查结果。单张稀疏采样不足时，补查该章节前、中、后三张原画面和对应阶段的完整字幕，证据仍不足就保留待核。新复核协议不重新渲染或投稿已完成的源。

## 投稿组织与平台权限

渲染前和真实上传前都查询官方视频投稿页使用的 `archive/white` 与 `archive/pre` 接口，不能用创作中心通用 `white` 的同名字段替代。`have_permission_of_p` 确认当前网页投稿渠道能否新投多 P，`new_web_edit.max_count` 给出当前 P 数上限，`season_add_multip` 单独确认多 P 入合集权限；这些字段不能推导出其他客户端的资格或统一粉丝/等级门槛。未开通多 P 时，每场游戏按约 60 分钟上限拆成单 P 稿件，优先在地点/Boss/阶段章节处分段，避免极短尾段；同场保持一个集号，用（1/3）等编号，简介提供时间轴。允许多 P 时，同场章节集中在一个投稿包，超过本地 P 数保护才另拆投稿。

单视频时长和文件体积按当前账号能力限制。默认单视频最大 3600 秒；如果实际输出仍超文件限制，自动保存该源的时长约束，继续拆短后恢复，不降低码率或修改原编码画质设置。游戏优先复制原视频和音频码流，检查实际时长及导出的前三个解码画面与指定源起点逐帧一致，避免关键帧起点偏移。复制切片不能满足边界检查时，沿用既有 NVENC/CUDA、CPU 回退和自动资源调度；实际输出时长误差不能超过 0.25 秒。视频不烧录字幕。成功或已入队的媒体重跑时复用原验收包，不因新分段或编码方式另投一遍。

投稿数量按稿件计算，各 P 不各占一个稿件。现有队列的 90 稿/滚动 24 小时是本项目的保守保护值，不是所有账号统一的平台上限；137022 等平台限频仍按实际响应退避。多 P 权限、文件限制和限频是不同限制，查询结果会随账号和平台变化。字幕或合集失败时保留已成功的 BV，禁止重新发视频来补传。

## 运行与恢复

录播下播后由 `background_clip_runner` 调用完整游戏流程，审核通过的产物进入已有单实例投稿队列；未知/失败内容保留源文件，不阻止其他切片流程。默认配置关闭自动投稿，生产配置启用已授权范围。

```powershell
$env:NODE_ENV = 'production'
npm run game:clips -- plan --media 'D:\录播.flv' --srt 'D:\录播.srt' --xml 'D:\录播.xml'
npm run game:clips -- run --media 'D:\录播.flv' --srt 'D:\录播.srt' --xml 'D:\录播.xml'
npm run game:clips -- inventory --root 'D:\files\videos\DDTV录播\25788785_岁己SUI'
```

`plan` 只完成文字检测；`run` 完成整场画面、原音复核、渲染、字幕、验收及配置允许的入队。`--no-register` 可制作本地包。历史补录可用 `--episode <集数>`；`data/runtime/stream_game_episodes.json` 将场次身份与集数绑定，重跑保持集号且拒绝另一场复用。检测缓存、失败窗口及已完成媒体按源身份和参数恢复。

关闭自动投稿时，检查本地完整媒体和文案后可用 `npm run game:clips -- approve --metadata 'D:\...\elden-ring_E001_1.json' --note '已核对完整游戏及文案，用户已授权投稿' --enqueue` 刷新验收并加入队列。已成功的投稿不会再次加入队列。

产物位于 `stream_game_clips/<录播基本名>/`，归档源通过现有 D/E 映射写回 D。`PLAN.json` 保存完整覆盖、章节、排除区间和独立复核；签名子目录保存无烧字 MP4、各视频重置时间的 SRT、封面、投稿元数据、`UPLOAD_MANIFEST.json`。`REVIEW.md` 提供集名、简介与本地文件。媒体、字幕、顺序、文案和合集绑定 `gameReview`，修改后必须重新验收，不能手改队列或审核摘要绕过。

## 外挂字幕投递

视频投稿成功后，在创作中心查询真实 P 顺序、标题、时长和 CID，与已验收媒体逐一绑定，然后提交字幕。验收元数据使用 `zh-CN` 表示简体中文；当前平台接口使用语言代码 `zh`，不依赖 SDK 中过时的语言目录。CID 尚未生成时单独等待和重试，不重复视频投稿。每个 BV 的任务保存于 `data/runtime/game_subtitle_tasks/`，每个 CID 的已提交字幕只提交一次。

`game-subtitle-queue-runner` 是独立 PM2 服务，每 30 秒检查可重试任务。字幕 POST 超时可能已成功；保存为 uncertain，仅通过读取线上同 CID、同语言且同字幕正文确认，不盲目再次 POST。OS 文件锁随进程退出释放。字幕完成状态同步回原投稿状态和注册表。

新稿在创作中心已有 CID，字幕接口仍可能明确拒绝 `79022 当前视频不存在`。此时等待稿件处理/公开后，只重试该 BV 的字幕，按退避延迟恢复；视频和合集不重新投稿。只有确认接口拒绝的提交可以重试，结果未知的 POST 保持只读核实。

```powershell
npm run game:subtitles
pm2 start ecosystem.config.js --only game-subtitle-queue-runner --env production
# 仅恢复明确返回 79011 的语言拒绝；不重复提交已成功或结果未知的字幕
python src/scripts/game_subtitle_upload.py --retry-rejected-language BVxxxxxxxxxx
```

合集创建/复用使用 `npm run game:collections`，具体参数见 `--help`。展示用 season ID 与实际添加稿件用 section ID 分别保存，游戏合集不会改变通用房间合集路由。
