# 漫画与切片安全并行

本轮完成源文件保留和并行编排，未启用生产并行。`ai.comic.overlapClips` 在默认/生产配置及配置类型中明确设为 `false`，整体性能验收仍未完成。

## 依赖关系

旧流程在晚安完成后启动梗概任务，再等待梗概、漫画脚本及截图准备，收到 `COMIC_SCRIPT_READY` 才启动后台切片。切片本身不依赖漫画脚本，但某些音频保留策略会在切片完成或启动失败后删除原视频。

直接提前切片存在风险：漫画后来才打开视频截帧，原路径可能已经被后台删除。原有 Python 已支持 `SOURCE_VIDEO_PATH`，因此采用读取别名，不引入复杂的跨进程引用计数数据库。

## 实现

- `src/scripts/comic/source_lifetime.js` 对已经封闭的录像创建临时硬链接，保留同一个文件对象，不复制或重新编码整个视频。
- 别名在仓库 `tmp/comic-source-reads/comic-source-*/source.<扩展名>` 下，不放在可能被整目录归档的录像日期目录里。
- 必须同文件系统、能建立硬链接且建立前后的文件身份、大小和修改时间一致。跨盘、链接不支持、权限错误、源正在变化时，返回原串行流程，不降级为耗时的大文件复制。
- `src/scripts/comic/pipeline.js` 在成功保留输入之后才允许提前请求启动切片，然后仍按原规则等待漫画所需的梗概。漫画通过已有环境变量读取别名；原始文件路径删除不影响这个读取入口。
- 队列、切片并发/资源保护、模型、推理档位、编码器、画质、字幕样式和图片重试策略都不改变。
- 默认关闭时不创建别名，仍由漫画脚本准备完成的回调启动切片。回调多次到达不会重复启动。
- 主编排仍先发出晚安可发布信号，再进入漫画/切片安排；没有增加晚安等待。

硬链接保护的是路径删除/改名，并非数据快照：如果其他程序在同一个文件对象上原地写入，内容也会变化。该功能只用于 ASR 与融合输入已经准备完成的封闭录播，不适用于仍在增长的录制文件。

## 生命周期与失败

每个别名目录保存 `owner.json`，记录所属主机、父进程、读者进程、未确认启动状态、别名文件名及文件身份。其他主机的记录不会按本机 PID 状态清理。

- Python 的 `spawn` 事件会登记读者 PID。父进程在生成完成的 `finally` 中释放别名，但读者进程仍存活时保留。
- 若登记待启动状态失败，后台切片尚未提前启动，此时退回串行。
- Python 已启动但 PID 写盘失败时，内存保留真实 PID，磁盘状态按未确认处理；生成可以继续，不因元数据写盘失败丢图。父进程异常退出后，清理器不会猜测这个读者已经结束。
- 新建别名时会回收父进程与读者进程均明确结束的旧别名。仅因超时、PID 不明、元数据损坏或权限不足，不会删除可能仍在使用的文件。
- 未确认启动的残留、被替换的别名文件、目录符号链接、无法验证身份的文件均保留，必要时人工核查。这些极端失败可能留下临时磁盘占用，不能宣称所有异常都自动无残留恢复。
- 清理只删除本任务的别名和所有者记录，不修改原视频删除策略，不删除替换进来的无关文件，不递归穿过目录链接。
- 剪辑入队失败不会阻止漫画继续；漫画准备或生成失败会执行别名释放逻辑。

## 验证

最新全仓回归：63 个 Jest 套件、651 项测试通过，含其他并行任务新增的测试；独立 Node 测试10/10、Python截图测试4/4、类型检查、构建检查和工作流构建通过。工作流构建未激活，生产 `overlapClips` 仍为 `false`。架构检查目前有其他任务改动的 `audio_processor.js` 和 `sensevoice_speaker.py` 行数超限。

### 实际文件和进程

测试真实创建硬链接，确认原文件与别名的 inode 一致、链接计数增加；第二个 Node 进程删除原路径后，别名仍可读取相同的 64KB 内容。

另一个真实子进程测试覆盖：读者 PID 存活时显式释放仍保留别名；读者读取结束、所有者均结束后才回收。还覆盖跨盘错误、源内容变化、未知启动结果、写盘失败、路径替换及目录链接。

### 实际 FFmpeg

`tmp/validate-comic-source-overlap-20260907.cjs` 生成一段 2 秒、160x90 的人工 FFV1 视频，不使用真实录播或模型。先截一帧，再让模拟切片进程删除原文件名，漫画从保留别名截取同一帧：

- 截帧字节完全相等，SHA-256 为 `8c441556ea173da4dec871190f3cd6838fa14ec2379b6b49be4c00ae62dbdfec`。
- 事件顺序：切片启动、原路径删除、漫画准备、漫画截帧。
- 原路径删除后仍成功读帧，生成结束后别名释放。
- 最近一次整个小型检查耗时 278ms，模型请求 0，上传 0。这不是长视频压制性能基准。
- Python 截图路径解析测试确认原路径消失时仍会使用 `SOURCE_VIDEO_PATH` 指定的别名。

### 时序回放

采用 09-05 已记录的阶段间隔：梗概 71,609ms，梗概后至漫画脚本/截图可用 95,409ms，后续生图 140,284ms，后台切片整体 2,357,706ms。虚拟时钟回放执行实际编排函数，固定各阶段耗时和结果不变。

串行时切片请求晚 167,018ms；并行时这段前置等待移除，漫画完成时刻不变，任务调用次数也不增加。

这只证明依赖等待可以被移除，不证明线上必然提速167秒。真实后台队列可能繁忙，额外同时在途的模型请求也可能影响供应商排队、梗概或漫画延迟；这些因素必须另测。没有将虚拟时钟结果当作 P50/P95 或不降质量/速度的最终验收。

## 可观测性

主流程新增 `[COMIC_CLIP_SCHEDULE]` JSON 日志，包含房间、录像名、是否请求并行、是否采用受保护的并行时序、别名准备耗时、漫画准备/生成耗时和切片启动请求时间。

`overlapUsed` 表示采用了并行安排，不代表后台 worker 已开始执行；`clipLaunchRequestedAt` 是请求入队/启动的时间，实际开工时间仍需结合后台 worker 日志。指标记录失败不影响内容生成。
