# 鹿饼 QQ 群聊回复

`services/qqbot` 接收腾讯官方 SDK 的已认证消息；`tools/qqbot/run.ts` 装配凭据、
只读录播资料、固定文本模型和发送适配器。无需 DeepSeek Harness，亦不运行通用
coding agent。底层使用 `@tencent-connect/qqbot-nodejs` 1.0.5；扫码绑定可独立使用
`@tencent-connect/qqbot-connector` 1.2.0，手机 QQ 为官方机器人的管理者。

## 当前交互

- 群聊仅接受 `GROUP_AT_MESSAGE_CREATE`，或 `GROUP_MESSAGE_CREATE` 中服务端标注
  `mentions[].is_you=true` 的消息。昵称、普通文字“@鹿饼”、手打 mention 标记和回复引用
  均不单独触发。普通群消息直接丢弃，不保存群历史。
- 私聊仅接受 `C2C_MESSAGE_CREATE`，回复配置中的固定进群引导；同一私聊用户每十分钟
  至多提示一次，不检索资料、不调用模型。未配置具体群号时不会虚构邀请链接。
- 每次群聊提问独立运行 OpenAI Agents SDK（`@openai/agents-core`）的 `Agent` / `Runner`，
  复用鹿饼人设，由模型选择资料或图片工具、读取结果、补查后回答；可以零工具直接回复，
  不按生图关键词分流，也没有固定工具步骤。`QQKnowledge` 每题创建
  独立的房间范围、证据 ID 和工具闭包，不再先按关键词跑固定的 `CommentKnowledge`。
  保留资料日期、房间和覆盖标记；不读取 B 站账号凭据，不改变共享索引。
- 空艾特返回使用提示。启用 `images` 时，agent 可选择专用图片接口，使用
  `ai.streamerRegistry` 的名字/别名和 `public/reference_images` 的其他具名角色参考图，
  多名角色分别带参考图；明确的新图要求直接执行，无需固定确认口令；
  支持引用图片或同条消息附图后提出明确改图要求。未启用时返回准备提示。通用附件理解、群历史记忆、主动聊天及
  定时消息仍未实现。

## 配置与命令

示例为 `config/qqbot.example.json`。所有相对路径以项目根目录为基准。
示例通过 `secretConfigPath` 直接读取 Git 忽略的 `config/secret.json` 中的专用 `qqbot`
分组。扫码取得的 AppID/AppSecret 与专用 sub2api key 在这里统一维护；不要打印或提交
真实凭据。仅在受跟踪的 `config/secret.example.json` 留占位结构：

```json
{
  "qqbot": {
    "appId": "替换为扫码取得的 AppID",
    "appSecret": "替换为扫码取得的 AppSecret",
    "keyName": "qq鹿饼用",
    "baseUrl": "http://127.0.0.1:8080",
    "apiKey": "替换为专用密钥"
  }
}
```

兼容旧配置的 `credentialsPath` 和 `providerConfigPath` 两个独立 JSON 文件；配置了
`secretConfigPath` 时只读中央分组，缺失字段不会回退到旧文件。密钥更改后需重启 QQ 服务。
Web 配置编辑器会隐藏 `appSecret` 和 `apiKey`，保留遮蔽值即可保持原密钥。

文本模型固定为 `gpt-6-luna`。QQ 专用字段直接读取，不合并全局配置、其他 provider 的密钥或
环境变量，防止无意用错 sub2api key。endpoint 必须为 HTTPS 或本机 loopback HTTP。
模型上下文不包含密钥、QQ openid、消息 ID 或其他群消息。

### 问答与图片 agent

采用 SDK 的标准工具循环。`QQAgentModel` 实现 SDK 的 `Model` 适配器，保持现有
专用 daiYu endpoint、代理、固定模型及可注入 HTTP 传输；不添加 shell、任意路径或发布接口，
没有第二个规划模型，也不自动重试付费请求。SDK tracing 在每个 Runner 上关闭，查询过程
仅保存在本地问答记录。框架接口见 [Agents SDK models](https://openai.github.io/openai-agents-js/guides/models/)
与 [running agents](https://openai.github.io/openai-agents-js/guides/running-agents/)。

| 工具 | 用途 |
| --- | --- |
| `read_live_overview` | 最新可用场次或指定日的直播梗概、晚安回复、漫画叙事，无需猜关键词 |
| `search_recordings` | 原录播、弹幕、精选摘要、切片字幕的限定范围检索 |
| `read_context` | 展开本题已有证据，核对原话上下文 |
| `read_recent` | 当前仍在录制场次的最近 5/10 分钟及延迟信息 |
| `list_recordings` / `read_recordings` | 浏览日期目录、按本题 ID 分页或批量读取 |
| `aggregate_evidence` | 对已返回证据的时间偏移作确定性统计 |
| `read_image_sources` | 核实本次艾特的原图，返回数量、尺寸和内容指纹 |
| `find_image_characters` | 按一个或多个人名查询可信角色名字、别名与外观描述 |
| `generate_image` | 选择 create/edit 和修改说明，服务端绑定原图、参考图及一次图片调用 |

工具集合由可信配置限定，命名主播只能选择已授权的房间；每题跨房间结果分清来源。
QQ 示例启用 `knowledge.allConfiguredRooms=true`，使用 `runtimeConfigPath` 中
`questions.recordingRoots` 的全部已配置主播；每题仍按提问中的主播名或 `roomAliases`
选择最多八间房，未指名时使用 `roomId`，不会全库扫所有主播。未启用时兼容原来的
`roomId` 加 `collaborationRooms` 白名单。录播目录名会提供完整主播名和中文简称，
其他昵称需在 `roomAliases` 显式配置。泛问主播情报时优先查直播概述；没有生成概述时，
继续浏览该主播的 ASR、弹幕，不能把“没有概述”解释成“没有资料”。此设置不改变 B 站评论范围。
直播资料对象仅在实际调用资料工具时初始化；检索房间限制不会在绘图、看图或普通聊天之前抛错。
QQ 显式使用八房上限，共用资料组件的其他调用方仍默认三房。超出八房时，资料工具返回限制，
其他工具仍可用。没有资料配置时仍可直接聊天；帮助和普通聊天也由 agent 判断，不强制检索。
工具参数错误或读取失败作为固定、不含原错误路径的反馈返回，允许 agent 修正或换工具。
“上次玩某游戏/何时做过某事”优先用主题词搜索历史正文，不以最新概述代替；
正式名称问题先按主题、简称或同音变体查指定日的字幕/弹幕，再展开上下文。
原文仅重复问题里的叫法不能证明正式名称；继续核对命名、英文名或商店标题线索，
仍无证据时区分已确认的直播叫法与未确认的正式名称。
目录与开头/抽样预览仅提供线索，未搜正文不能据此宣告未找到。命中游戏名仍须区分
推荐、回忆与实际游玩；索引覆盖不足时只能报告已查到的线索，不能断言最近一次。
同一操作不重复 IO；每题最多 9 次模型调用、8 次工具操作，每次只执行一个工具。
轮次上限由共享 `QQ_AGENT_LIMITS` 约束，调整时同步部署 QQ 运行闭包与管理 API 的
记录校验和额度策略，保证较长调用链仍可归档并在网页读取。
预算按完整请求 UTF-8 字节数保守预留；继续检索前另留下一步结果及最终答案空间。
最终作答禁用工具并省去工具 schema，避免重复发送和预留无用的 schema 挤占检索预算。
每步资料最多 6000 UTF-8 字节，并按本轮实际剩余作答预算进一步收缩；预留时计入
工具 JSON 嵌入下一轮请求后的转义开销。缩减完整记录并附 `truncated`，不截坏 JSON。
最终结构化输出包含公开回答、回答依据类型和证据 ID；事实答案必须引用本题实际保留的
工具证据，资料不足的回答也可引用已确认的局部线索；所有非空引用都须校验，未知 ID
会导致生成失败，聊天常识的引用必须为空。图片工具不直接发送，返回生成、拦截或失败回执；
worker 持久化图片后，与最终单段文本合成一次被动回复。图片和资料工具共用上述次数上限。
规划模型只获得原图元数据，不接收图片像素；原图字节由服务端交给图片编辑模型。

`questions/LiveOverview` 只读配置录播根目录及其日期子目录，每根最多最近 14 个日期目录、
每目录最多 10000 个条目，至多尝试 48 份产物；不递归扫描媒体或切片目录。
按录制文件名时间排序，支持 DDTV 与历史下划线时间命名，不用复制/生成的 mtime 判新旧。
返回最近有可用概述的同一录制产物，以及目录中最新已见录制时间，两者不能混作真实开播历史。
跨零点的新片段不自动算另一场；最新也不等于查询当天。指定日期缺资料不会借用其他日期。
只接受 `_LIVE_CONTENT.json` 的成功 v1 同房间结构化内容，剥除晚安 Markdown 的 front matter，
漫画只取叙事与画内文字，不取绘图指令；成功梗概优先，其次同场晚安、漫画，缺少时可用精选摘要。
生成概述可支持内容概括，不能充当主播逐字原话，精确引用仍需回查字幕。

### 参考图生图

`images.registryConfigPath` 指向受维护的角色配置（示例 `config/production.json`），
只读取原始角色注册表及 `ai.roomSettings` 的角色参考图、名字和描述，不合并凭据配置。
新图正文中的角色名字、昵称和别名匹配参考图；英文别名
按单词边界匹配。同图最多八个角色参考；匹配到一名角色不证明同一要求中的其他角色已识别。
可用 `images.characters` 补充显式名字、别名、外观描述和图库内路径。
同次请求会收集全部命中角色，以独立的 `image[]` 文件字段上传，并在提示词中逐张编号绑定角色，
支持三人以上同框，仍受八张参考图上限约束，不会只取第一个角色。多角色分别保留外观和动作关系。
简称与完整账号名不一致时，应在受维护的 `streamerRegistry.aliases` 显式补齐，
不从长中文名字任意截取短名。例如阿梓的“阿梓 / 梓神 / 阿梓从小就很可爱”均绑定
`azusa_standing.png`；“七海使用魔贯光杀炮攻击阿梓”会同时附带七海和阿梓各自的参考图。

新图绘制意图由 agent 判断；用户直接发送“生成岁己和栞栞在摔角赛场上对战的图片”
或“帮我画一个星汐”等明确要求即授权本次绘图，无需再按固定格式确认。
图片工具、worker 和生成适配器在付费调用前复核原始正文中的绘图要求；
只有“确认”、引用示例、否定绘图、询问用法或未说明主体的空泛请求不会授权新图。
这些请求不预留图片额度或启动间隔；agent 规划与说明仍消耗文本预算。
保留兼容格式 `确认按描述生图：完整绘图要求`，中英文冒号均可。
未匹配的具名角色仍须说明外观不确定，不把猜测当成已核实设定；不因陌生角色要求重复确认。
不从群历史或其他用户的确认补全要求，也不新增待确认队列。原有限额和安全检查保留。
参考列表由 CLI 装配给 agent 工具与 worker，生成前仍按可信图库复核；新图正文明确命中的
已知角色不会因模型漏选而丢失参考图，模型另选的角色也必须来自图库。确认前缀不会进入绘图提示词。

例如发送“生成三理穿宇航服站在月球上的图片”会直接带三理参考图，复用晚安图的身份一致、
精细画质、自然比例规则，再加入用户指定的场景、动作、服装和风格；不会擅自添加
晚安文字或虚构直播事件。仅有本机 `public/reference_images` 下的参考图可上传。
有参考图使用 `/v1/images/edits`，无参考图使用 `/v1/images/generations`，两者都用
中央 `qqbot` 分组的专用 key；示例模型为 `gpt-image-2.5-sunburst`、`high` 质量。

### 引用图片修改

在 QQ 中引用要改的图片并艾特机器人，例如 `@鹿饼 改成一前一后抬棺`，或将原图与
`把背景换成月球` 等修改要求一起发送。明确改图指令和本条消息携带的原图引用即可授权
这次编辑；“生成图片,改成一前一后抬棺”等表述也由模型判断为编辑。
引用中的文字不进入创作指令。仅引用或称赞图片
不会触发生图，普通群消息仍不因引用获得回复权限。

`QQImageInputPolicy` 只解析已认证 SDK 的 `attachments`、`refMsgIdx` 和引用 `msgElements`。
优先选择与规范化 `refMsgIdx` 匹配的元素，否则查找携带图片的元素，再兼容第一个引用元素。
明确的图片附件不依赖可选引用 ID 或消息类型，缺这些元数据时仍可下载当前事件明确附带的原图。
不从文字链接、昵称或其他群消息猜原图。
`QQImageInputs` 在成功发送图片后将平台 `id` 与 `ext_info.ref_idx` 映射到本机生成的 PNG；
索引位于 `data/runtime/qqbot/image-replies/<AppID>/`，键包含会话哈希，值仅保存日期、
请求哈希与内容 SHA256，不保存原始群号、用户标识或平台引用 ID。重启后可继续修改
这些图片；同群其他成员可引用，其他群和 AppID 不可复用此索引。
平台引用 ID 按不透明字符串处理，最多 512 字符，允许标点但拒绝空白、控制字符和隐藏格式字符；
只使用其会话绑定的 SHA256 构造本地索引文件名，不把平台 ID 当作路径。

引用机器人自己发出的图片时，先按精确引用读取同群、同 AppID 的已校验本机回执和原图；
引用事件中的附件 URL 无效不影响这条本机读取路径。找不到匹配回执时，无效附件仍拒绝下载。
没有本机回执时，只下载当前认证事件所附的 QQ 图片 URL，限定
`multimedia.nt.qq.com`、`gchat.qpic.cn`、`c2cpicdw.qpic.cn`，统一 HTTPS，禁止重定向，
不附带图片接口密钥。每张最多 10 MiB、2500 万像素，每次最多八张原图与角色参考图合计。
原图先规范化为 PNG，按原图在前、补充角色参考在后的顺序送入 `/v1/images/edits`；
提示词要求保留全部人物的性别、年龄感、脸型、发色、瞳色、服装和数量，以及未要求改变的
画风和场景。模型不能将带原图的请求改为 create 来丢弃原图；拿不到原图、校验失败或图片过多时，
不回退到凭文字重新生成；提示重新引用或附图。旧图片没有本机索引时需要 QQ 在引用
事件中提供图片附件，否则须重新附图。改图与新图共用原有图片额度、启动间隔和失败计数。

用户询问图片画面、文字、细节、错误或要求点评时，模型先选择 `read_image_sources`。
工具读取成功后，下一轮回答请求附带真实 JPEG 图像预览，不能只用尺寸、指纹或用户文字猜图。
预览最多八张、长边 1024 像素、每张 256 KiB，并去除元数据；不改变编辑时使用的原始 PNG。
每轮为每张预览单独预留 16384 额度，不把 base64 编码当作文本 token；仍受单题总额度和轮数限制。
图片仅送现有 QQ 专用回答接口，不把 URL、原始平台 ID、base64、路径或图像字节写入工具 JSON 和诊断。
图片内容不作为操作指令；看图、点评不授权生图或修改，闲聊和称赞可跳过读取。
成功读取预览时记 `qq_image_sources_loaded`，只含请求哈希和图片数量，用于区分引用解析与真实读图。

图片单次请求、不自动重试；每人滚动五小时最多 10 次，默认每人每天 30 次、全局每天 300 次，启动间隔至少一分钟，
调用前持久化预留，失败亦计次数。同题原图加载结果缓存，读取与生成工具不会重复下载；
图片付费尝试后，即使参数改变也不能再调一次。

示例启用 `images.background: true`，`images.timeoutMs: 900000`：启动持久化任务后，先在原消息
的安全窗口内等图；及时完成就直接回复图片，不要求再次艾特。等待预算包含前面的排队和模型耗时，
以原消息四分钟内部有效期减二十秒为截止点，预留落盘、上传和发送时间。
快到截止点还未完成时才回复接单提示；停止等待不会取消图片生成，后台总上限仍为十五分钟，
不使用过期消息主动补发。原提问者在同一群里
再次艾特时，优先领取上一张图或查询进度，不再调用回答模型、生图接口或扣除图片额度。
每用户每群只保留一个未领取任务，全局最多同时生成两张。取图优先于处理该次艾特的新要求，
用户收到图片后可再发新要求。关闭后台模式时保留同步兼容路径，图片 HTTP 上限180秒。
原消息回复与后续领取各自受入站消息四分钟内部有效期约束。

`QQImageJobs` 在现有 QQ 进程/账本所有者锁内维护独立的
`data/runtime/qqbot/image-jobs/<AppID>.json`，记录用户/群哈希、原始任务键、图片指纹和发送意图。
已完成结果在重启后可领取；中断任务标为结果不明，不重新付费生成。生成失败或中断时，
在当前安全窗口内或下次艾特只发一次状态说明，收到成功回执后才释放新任务。图片领取前持久化发送意图，
只有 QQ 成功回执才标为已领取，发送不明时禁止自动重发。后台任务不持有 QQ 发送接口。
完成/失败记 `qq_image_job_ready` / `qq_image_job_failed`，只有 `qq_reply_sent` 才表示 QQ 已确认回复。
`qq_image_inline_ready` 表示在原消息窗口内取得图片；`qq_image_deferred` 表示等待预算耗尽转为后台领取。
任务记录最多1000条，仅清理已领取超过24小时的记录；不清理未领取结果。
个人图片窗口通过可选 `users[].imageStarts` 时间戳持久化，跨重启、跨北京时间零点保留；
每日图片计数在北京时间零点重置。旧 version 1 账本缺少图片窗口时从空窗口开始，已有日计数保留。
额度提示区分个人五小时、个人每日、全局每日与一分钟启动间隔。
成功图片规范化为 PNG 后与问答记录同目录保存，记录模型、完整提示词和内容 SHA256。
QQ 通过本地图片文件上传并被动回复；平台回执前不记为已回复。

```powershell
npm run qqbot -- --check
npm run qqbot -- --status
npm run qqbot -- --live
```

默认 `--check` 只检查配置、SDK 加载和资料运行配置，不连接 QQ、不调用模型或发消息。
`--live` 为显式运行入口。PM2 的 `shikamochi-qqbot` 使用独立的
`dist/qqbot/tools/qqbot/run.js`，仅在该功能的部署任务授权后，按架构指南验证候选、
部署到这个独立目录并启动该进程；不覆盖其他服务的 `dist` 文件。
QQ 候选应从已通过 `verify:all` 的 `build/service` 收集该入口的完整静态依赖与 JSON 资源，
保存文件清单及 SHA256，在隔离目录先执行编译入口的 `--check` 和使用注入传输的离线检查。
确认账本及后台图片日志无处理中或不明发送后，仅停止 `shikamochi-qqbot`，保存账本、图片任务日志快照和旧 QQ 目录，
整体切换独立目录再启动；核对文件清单、新 PID 的 `qq_ready`、未暂停状态及既有收据。
回退仅恢复代码目录及对应配置，保留最新额度、图片任务、结果和发送收据，不使用 Webhook 部署脚本操作 QQ 分区。
SDK 仅发布 ESM，`QQSdk` 用固定的原生 import 表达式保留 CommonJS 构建兼容性；
不接受来自配置或聊天的模块名。

## 去重、限额和失败

单进程串行处理，默认至多 20 条未完成请求、每个用户 2 条。群提问每用户滚动五小时
最多 100 次，没有额外的个人每日文本次数上限；
全局每滚动一分钟最多 5 次文本生成。每次预留 262144
token，示例每日预算为 40960000 token。QQ 独立记账，不与 B 站共享已用次数或预算，
不读取或推断 QQ 用户的 B 站粉丝牌。完整上限先持久化，成功后按全部模型轮次的用量结算、
释放未使用的预留；缺少 provider 用量时使用保守字节估计。失败或中断保留完整预留，防止重试刷费。
每次 HTTP 前累计检查消息、工具 schema、输出上限和协议余量；接近上限时停止补查并完成回答。
这是调用预算，不等同于含缓存折扣的网关实际
usage 账单。额度提示每用户一小时至多一次。私人固定引导和空艾特不消耗文本模型预算；
图片请求与能力说明使用同一 agent，按一次提问预留，只有实际执行图片工具才预留图片次数。
用户分组依据 QQ openid，不猜 B 站
粉丝牌或跨平台身份。五小时窗口跨午夜保持，日计数仅作统计并单独重置。

消息有效期四分钟；每次文本 HTTP 超时九十秒，未启用图片时整个 agent 也限九十秒；
启用图片时整个循环最多使用消息剩余有效期减十秒。所有发送开始至少间隔五秒。文字答案只允许单段
至多 300 字纯文本，拒绝公开工具调用、截断响应、链接和凭据输出。一次请求至多一次
被动回复，发送目标始终由入站事件确定，不能由模型修改。

状态位于 `data/runtime/qqbot/<AppID>.json`，复用 PID 独占锁和原子快照。只保存消息
摘要哈希、额度、时间和收据状态；问答正文单独长期保存，原始 openid 不落盘。收据保留
24 小时、最多一万条。内存排队请求不跨重启恢复；进入模型前已持久化的请求不会
重放。中断的生成保留预算并标记跳过；中断或异常的发送标记 `unknown` 并暂停。
磁盘检查点失败同样停止后续调用与发送。恢复前检查 `--status` 与平台情况，显式执行：

```powershell
npm run qqbot -- --resume
```

恢复不会重试旧收据；之后重新启动 QQ 进程。进程退出码 2 禁止 PM2 自动重启，以免
反复发送不明结果。日志使用结构化 JSON，带 `diagnosticsVersion: 1`、PID、AppID 和时间；
请求相关事件共用 `requestId`（本地请求哈希），可与存档文件名和网页诊断标识对应。
`qq_generation_started` 区分 text/image 并记录开始处理前的等待时间；`qq_agent_trace`
在模型调用前后、工具完成及最终清理后记录最新受限 trace。失败事件附同一份安全诊断，
即使存档磁盘写入失败，仍可通过 `qq_state_failure` 定位异常和对应请求。
启用图片时，已接收群艾特额外记录 `qq_image_input`：消息类型、是否有引用、顶层及引用
元素附件数量、已解析原图数量和无效标记，数量均有界；不保存图片 URL、签名、引用正文或原始平台 ID。
普通群聊与重复入站不写此诊断。不启用 SDK 原始调试日志，不记录任意异常 message、原始堆栈、HTTP 错误正文或请求凭据。

## 本地问答记录与网页

`data/runtime/qqbot/records/<AppID>/<北京时间日期>/<请求哈希>.json` 独立保存每次已接收
问答的正文、答案、模型、状态和时间，群/用户标识只记录哈希；QQ 事件若提供发送者昵称，
另存经清理且最多 80 字的 `senderName`，用于 Web 展示和筛选，不用于身份授权或额度分组。
旧记录和未提供昵称的事件兼容显示用户哈希，不推断昵称。生成前保存问题，发送前保存
答案，平台成功回执后才标记 `sent`。磁盘失败停止后续调用和发送；普通未艾特群聊不入档。
固定私聊、额度提示和已接收后跳过的请求也留档。发送中断保留待核对状态，不自动重试。
此目录不随 24 小时收据清理，可供后续复盘。
文本问答另保存可选 `agent`：模型调用数、用量、工具名/结果状态/耗时，以及逐轮 `calls`
和 `failures`。每次 HTTP 前先持久化 `running` 轮次，完成后记 `ok/failed`；预算或轮数
在 HTTP 前拦截时记 `blocked`，不算已发出的模型调用。工具执行后立即保存，最终清理失败
也不覆盖原始错误。后续发送检查点保留这些字段，兼容没有诊断字段的 version 1 旧记录。
不保存工具原始参数、摘录全文、模型原始回答、凭据或 SDK 云端 trace。

每轮记录时间、耗时、请求 UTF-8 字节数、调用前累计预留、本轮预算和上限；收到响应时
保留 HTTP 状态、安全的上游请求 ID 和固定枚举的 `finish_reason`。`failure` 区分模型准备、
预算、HTTP、JSON 解码、响应结构、SDK 运行、答案/证据校验、资料工具、清理、诊断写盘、
图片准备/HTTP/解码/存图等阶段。错误码区分超时、主动取消、网络失败、HTTP 失败、截断、
无效 JSON/schema/引用、不可公开回答及预算/轮数不足；回答校验还记长度和失败校验项。
未知错误保留白名单异常类型、系统错误码、SHA256 异常指纹，以及最多六条仅文件名与行列号
的项目/Agents SDK 调用位置，不含完整机器路径。凭据不会因异常或响应头进入诊断。
`queuedMs` 记录消息创建至开始处理的等待时间，避免把排队误判成模型耗时。
生成失败的根因保留在 `failure`；若固定失败提示也未确认发送，另存 `sendFailure`，
不覆盖前面的生成错误。诊断存档失败和其他持久化检查点一样暂停，不继续调用或发送。

网页“查询过程”展示逐轮 HTTP 与工具顺序，“失败原因”显示阶段、错误码、预算、请求 ID
和安全调用位置；旧记录明确提示没有详细原因，不能从新字段反推历史异常。只读 API 对新增
诊断对象同样逐字段投影，剥除未知字段。

Web 工作台侧栏“QQ 问答”（`http://127.0.0.1:3000/#qq`）经本机鉴权只读
`GET /qq-records` 展示记录，每 5 秒刷新；按北京时间日期、群/私聊、状态及正文关键词
筛选，每页 50 条，默认最新有记录日期。单次最多读取选中日期一万条，损坏或超限明确报错。
支持精确的 `user` 和 `conversation` 筛选，值均为 `<AppID>:<64位哈希>`，与日期、消息类型、
状态和关键词组合，不混合不同机器人的同名用户。用户下拉列出所选日期和消息类型下的所有用户；
选中用户后，会话下拉只列其参与的会话，用户统计表定位该用户。用户统计同样按所选日期与
消息类型汇总，不受会话、状态、关键词或分页影响；默认展示最近提问的 100 位用户，
其余用户可通过下拉筛选定位。问答概览则按全部筛选条件、在分页前统计记录、已回复、生成/发送异常、
额度提示、用户、会话、处理中、跳过和成图数。生成失败但成功发送固定提示可同时计入异常和已回复。
额度提示数只识别固定限额提示，不能据此判定当前仍限频。

当前额度独立于历史日期筛选，使用只读运行账本及默认常驻进程的
`config/qqbot.example.json` 中公开的预算/生图限额，返回快照时间。显示个人五小时用量与剩余量、
全局每分钟文本门控、每日文本预算、生图个人五小时与每日额度、全局一分钟间隔、私聊引导冷却以及暂停状态。
限频原因分别给出可重试时间，个人五小时窗口跨午夜保留，每日预算在北京时间零点按规则投影重置。
`noticeUntil` 只抑制重复提示，不作为实际限频依据。账本或额度配置缺失、损坏时显示未知；
运行账本合计最多读取 32 MiB，超限账号同样显示未知。不读取 key，不改写账本，不清额度，
不恢复暂停，也不以文件存在证明网关在线。
生图记录同时展示成图预览和提示词；只读图片路由为
`GET /qq-records/<AppID>/<日期>/<请求哈希>/image`，校验目录、JSON 归属、PNG 签名和
内容哈希，拒绝符号链接和任意路径。页面不调用模型、发 QQ 消息或读取 provider/账号凭据。
