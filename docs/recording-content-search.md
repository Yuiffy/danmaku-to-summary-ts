# 录播内容检索方法

用于在 DDTV 主目录和 DDTV-E 归档目录中查找某位主播看过的电影、节目或游戏。

## 搜索顺序

1. 先搜 D 盘当前录播根目录，再搜 E 盘归档根目录；较老或已迁移的场次重点看 E 盘。
2. 只进入目标主播目录，按年份/月和日期目录缩小范围。
3. 先用准确标题搜索文件列表和各日期的命中数，不要直接输出所有匹配行。
4. 对命中集中的日期，再查看字幕、AI 摘要、弹幕 XML/CSV 中的时间戳。
5. 用“准备观看 -> 连续剧情讨论 -> 片尾/评分”三段证据确认实际观看，不能把点播建议或改日预告当成观看记录。
6. 最后用 `ffprobe` 核对媒体时长，并抽查候选时间点的画面或音频。

录播根目录：

```powershell
$roots = @(
  'D:\files\videos\DDTV录播'
  'E:\EFiles\Evideo\DDTV录播-E'
)
$streamer = '25788785_岁己SUI'
```

准确标题搜索应先使用 `rg -l` 或 `rg --count-matches` 控制输出规模：

```powershell
foreach ($root in $roots) {
  $dir = Join-Path $root $streamer
  if (Test-Path -LiteralPath $dir) {
    rg -l -S `
      --glob '*.srt' --glob '*.txt' --glob '*.xml' --glob '*.csv' `
      '天气之子' $dir
  }
}
```

准确标题找不到或证据不足时，再分批搜索容易被 ASR 识别错误的角色名、剧情词和观看动作。不同类别不要混在一次超大的正则中：

```text
标题/近音：天气之子、天气滋滋、炎热之情
角色/剧情：阳菜、洋菜、帆高、翻高、晴女、放晴、献祭、水淹东京
观看动作：看电影、开始播放、看完、片尾、打多少分
```

候选日期必须同时满足：

- 开始前有选片、找资源、戴耳机或“开始播放”等语句。
- 中间约 100 至 120 分钟持续出现该作品独有的角色和剧情讨论。
- 结尾有片尾、看完、评价或评分等语句。

## 2025-09-25《天气之子》案例

目录：

```text
E:\EFiles\Evideo\DDTV录播-E\25788785_岁己SUI\2025_09_25
```

关键证据：

- `03:09:55` 明确说“天气之子还有粤语版吗”。
- `03:11:44` 开始进入电影内容。
- 中途连续讨论阳菜、帆高、晴女、献祭和水淹东京。
- `05:13:06` 给电影打 7.8 分，随后改为 7.2 分。
- `05:15:50` 音乐讨论结束并说“我走了，拜拜”。

适合分享的截取范围为源录播 `03:08:10` 至 `05:16:20`，包含选片、完整电影和观后感。

## 本次漏搜原因

第一次搜索把准确片名、`新海诚`、`阳菜`、`帆高`等词放进了同一个递归正则，并直接打印所有匹配行。弹幕用户名“青木阳菜丶”和大量无关提及制造了数百条结果，工具输出被截断，`2025_09_25` 的真实命中实际位于被省略部分。随后又过早关注可见的 2024 年“明天天气之子”预告，没有先按日期汇总命中数。

此外，这场的目录名和录播文件名完全不含电影名，ASR 还把“天气之子、阳菜、帆高”识别成“天气滋滋、洋菜、翻高”等近音词。只查文件名、只查准确转写或只看单条片名弹幕都不可靠。

以后应先用准确片名生成候选文件清单并按日期聚合，再对少量候选日期做模糊词和连续时间窗口验证。任何可能产生海量结果的搜索都先使用 `rg -l`、`rg --count-matches` 或按日期逐目录运行，避免重要结果再次因输出截断而丢失。
