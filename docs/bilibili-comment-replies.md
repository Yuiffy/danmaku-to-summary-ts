# 鹿饼 B 站评论回复

B 站调用归属、活跃上游索引、依赖接入策略和只读诊断命令见
[B 站接口上游与排查入口](bilibili-api-upstreams.md)。

`services/bilibili/comment-replies` 是独立的账号通知消费者；
`tools/bilibili/commentReplies.ts` 负责单进程装配，不启动 webhook、直播投票或媒体队列。
修改这些模块后先运行相邻 Jest 测试及 `tests/integration/comment-replies.test.ts`，
再运行 `verify:quick`、`verify:all`。验证全部使用注入的 HTTP/model/send 适配器，
不会真实生成或发评论。

## 触发与发送目标

通过账号 Cookie 读取 `/x/msgfeed/reply`、`/x/msgfeed/at`，每 30 秒轮询一次。
接受通知中指向鹿饼的评论回复、鹿饼动态下的直接评论，以及真实 @ 账号通知；
不通过昵称文本猜身份，忽略自身发言、隐藏回复按钮及不支持的业务类型。
支持视频、图文动态、专栏、文字动态评论区（业务类型 1/11/12/17）。
视频评论区仅处理明确 @ 鹿饼的评论；包括回复鹿饼旧留言在内，未 @ 时均不触发。
使用认证 @ feed 或 `at_details.mid` 核对账号，不通过昵称字符串猜测。
动态中的 @ 可生成顶层评论；评论中的 @ 回复原评论。
无通知、已删除或被 B 站过滤的互动无法触发。

`subject_id` 决定评论区，`source_id` 决定回复的原评论，`root_id` 决定根评论。
回复通知中 `target_id` 是被用户回复的旧评论，不能拿来替代 `source_id`。
@ 通知的楼中楼在 `root_id=0` 时使用 `target_id` 作为根评论，`source_id` 仍是回复目标。
模型不接收这些定位字段，也不能改目标。通知/回执的 64 位数字 ID 在解析前转为字符串，
避免 JavaScript 精度丢失。评论的 @ 与回复双重通知按评论区类型、主体、原评论去重。
协议参考：[通知消息](https://github.com/huang3292/bilibili-API-collect-save/blob/master/docs/message/msg.md)；
SDK 的 `session.get_replies/get_at` 定义分页参数。账号只读探测已核对两类 feed 的字段；
真实发送及平台风控行为须在单独启用验收时确认。

首次启动每种 feed 只建立基线，不回应历史通知。之后将逐页检查到上次基线，
每轮每类至多读两页，并持久化分页位置；不会因为分页上限直接跳过中间通知。
通知按 ID 高水位停止，基线对应通知被删除时也不会回退游标、重放历史互动。
队列满时保留该页以便下次重放，仍检查同页其他用户；重放不重复生成或发送。

## 公平性、额度与资源限制

- 所有回复（含固定安全/额度提示）共享发送门，任意两次 POST 开始至少间隔 5 秒。
- 开始一次合规的模型回复前给原评论点赞，先持久化意图，再调用固定的评论点赞接口。
  点赞与回复共用 5 秒写入间隔；点赞一次后生成、等待发送，不重复点赞。
  点赞失败或结果不明暂停消费者，不继续调用模型或自动重试；崩溃时未完成的点赞同样暂停。
  安全提示、额度提示、已过期请求及动态正文 @（没有原评论 ID）不点赞。
- 滑动 60 秒内最多启动 5 次模型生成；超额请求留在队列，不立即调用模型。
  为保守覆盖慢磁盘和慢响应，窗口按模型调用完成时间维持，重启时中断调用另加冷却。
- 按 UID 轮转，每人每轮处理一条，同一人的已接收请求按入队顺序处理。
- 示例配置启用 `fanQuota`，按当前佩戴粉丝牌对应的主播 UID 分层，不能用评论自报、
  昵称、仅拥有的牌子或牌子名称冒充。`suiUid` 对应饼干岁，`relatedUids` 是可信的已知主播
  名单，示例含栞栞、弥月、犬绒、米汀（旁汀生）；其余和无牌按基础档。接口不可用或牌墙隐藏
  标记未知，暂用基础档，不宣称对方没戴牌。
  三档每滚动 60 分钟分别为 20 / 6 / 2 次，每个北京时间自然日分别为 100 / 15 / 5 次。
  每个 UID 跨评论区、跨牌子共享实际计数；更换牌子只改变上限，不清零用量。
  小时窗口跨午夜继续有效，每次使用满 60 分钟才释放对应位置。
- 达到小时或每日上限后只给一次固定软提示，例如“哎呀人家鹿饼有点困困了的说，先眯
  一小会儿～戴着饼干岁牌子来叫我，会更有精神陪你聊哦。”同一人同一耗尽窗口后续
  触发静默，不点赞、不调用模型；提示占用标记在发送前持久化，重启不重复。
  小时提示在恢复可用额度后重新可用，每日提示到北京时间次日重置；过期未发提示
  重新评估，不跨窗口发送旧提示。饼干岁档使用专门的同担休息文案，不再邀请已戴牌者戴牌。
- 额度在处理前预留，失败/超时也消耗本次额度，防止反复失败刷模型费用。
  已生成回复跨日或跨小时发送时重新检查并预留发送窗口额度。状态新增可选 `userWindows`
  和任务的 `quotaAt`、`noticeUntil`、`audience`；兼容原 version 1 文件，不清空旧每日计数。
  缺省 `fanQuota` 的旧配置保留每日 10 次及原固定日限额提示，不启用小时分层。
- `unlimitedUids` 显式豁免个人每日及小时额度，示例保留带鱼 UID `14279`，不依赖佩戴牌读取；
  仍受公平轮转、发送间隔、全局模型限流、队列容量和全局 token 预算限制。
  已就绪但尚未发送的旧额度提示遇到新增豁免时重新评估，已发历史不重放。
- 默认最多排队 200 条、每人 10 条，容量满后不扩大内存/磁盘队列；通知页留待重试。
  请求有效期 24 小时，过期静默丢弃，避免高峰积压后隔几天刷旧评论。
  去重记录保留 7 天，最多 20,000 条；容量不足时同样保留入口游标。

5 秒是发送上限，不代表 B 站保证安全的频率。登录失败、风控、写请求的 HTTP/网络错误及
无明确回执的发送都会暂停整个消费者并退出，不自动重试 POST、不切 Cookie 绕过限制。
与其他进程的总结评论/投稿留言没有共同发送锁；单独启用时应检查账号整体发言量。

通知 GET 的连接重置、超时、暂时的 DNS/网络故障，以及 HTTP 408/500/502/503/504
只进入读取退避，不写永久暂停标志。`CommentPoller` 按 30/60/120/240/300 秒退避，
且不短于配置的正常轮询间隔；读取恢复后重置退避。已落盘的通知高水位、分页位置和
任务去重仍有效，已有队列可以继续处理。HTTP 401/403/412/429、非零平台码、损坏响应、
凭据或落盘异常仍暂停，不把安全阻断当作网络波动。日志只记录 feed、固定原因、
HTTP/平台码、允许的网络错误码与重试间隔，不记录原错误消息、响应正文或凭据。

## Token 与安全边界

复用 daiYu provider 的可信配置和固定小模型 `gpt-6-luna`，使用专用单轮聊天 agent。
鹿饼以热爱岁己的 AI 饼干岁身份聊天，先回答问题，再接具体内容的梗或感受。
`CommentReplyStyle` 按本次诉求选择闲聊、功能说明、纠错、应援、定位、历史、项目对照、
解释或评价，不把所有问题压成一至三句弹幕。闲聊一至两句、应援最多 150 字，评价最多
180 字、定位最多 240 字、解释/历史/项目对照最多 260 字；协议仍限 300 字、384 output token。
不每条自称鹿饼、套话夸可爱或收尾喊应援。视频主角按证据识别，不能都当成小岁。
AI 饼干岁人设不证明小岁参与视频，宠物归属与说话人不明时用中性称呼。
视频事实回复若出现“小岁／岁己／SUI”，发送前要求实际模型输入中的评论或目标视频
标题、简介、字幕有对应姓名依据；非目标视频专属的本地问题也可用保留的线索原句。
评论者身份、粉丝牌、热评及预算裁掉的资料均不能作为依据；校验失败按生成失败终止，
不发出该候选、不追加模型重写，也不自动重试。
“小岁是吧／对吧／吗”这类观众猜测会触发目标视频取证，本身不能证明视频主角身份。
用户明确要求“帮小岁加油／打气”时，直接面向所指对象写应援，优先接当前动态的游戏或活动，
不能用“谢谢留言”“她看到会开心”等代收式客套替代诉求；鹿饼是粉丝，不冒充主播或运营。
语气参考晚安回复的具体原话切入、接梗和按情绪给予支持，保持短评长度，不照搬下播回顾。
先理解原话的反差再应援：人数明确时结合当前动态及转发原文，将倒数名次换成正数名次
自然接话，不讲计算过程；人数不明则不猜。自嘲应温柔撑腰，不顺着唱衰或断言心理状态。
完整短动态另保留富文本中按 UID 去重的 `mentionedUsers` 数量，不将昵称或熟悉主播名单
当作人数；它仅表示被 @ 的人数，须结合原文判断是否为参赛者，不证明实际到场。
知识类给要点，搞笑二创接具体笑点，沉重内容收住玩笑；被吐槽或没被看到仍支持小岁，
不卖惨索取关注、不冒充真人。观众转述不当作已核实原话，CP 玩笑不能推断现实关系。
每次接收最多 600 字的评论，不带全量线程或聊天历史。
`currentSpeaker` 明确区分本次评论者、视频主角和热评作者。可信 `speakerNames` 由本地配置
按 UID 映射，示例含带鱼与岁己；通知昵称只作不可信显示名，无映射时不据此确认主播身份。
粉丝牌仅说明观众偏好，不证明是主播本人；同担可更亲切，也保持对基础档观众的友善。
模型不接收作者 UID、牌子等级或整个牌墙，不会默认把每次点名称为“小岁的点名”。
固定 system 前缀便于 provider 自身前缀缓存；应用不依赖缓存命中计算额度。
输出最多 384 token、300 字；截断、非法或工具调用输出直接丢弃，不追加修复请求。
模型没有 tools、shell、文件、浏览器、录播检索工具、发送接口或本机 agent 会话。
它只能通过固定 endpoint 返回候选文本，所有副作用在应用固定路径执行。
“这套方式我们能用不”也会触发目标视频字幕，并通过可选 `projectSources` 对照公开项目
流程，跳过无关录播。管理员仅配置已审阅的公开 `.md/.ts/.py` 文件、关键词和可选原文
小节标题；评论不能选择路径。最多 8 个来源、命中后读 3 个，各文件 128 KiB、各摘录
280 字；拒绝符号链接与路径重定向，敏感行过滤，模型仅获公开标签、类型、内容版本摘要
和摘录，不获本机路径。小节不存在、文件缺失或读取失败不作为能力证据。
资料按不可信引用处理，不作为系统指令；code 证明实现，skill/guide 证明流程文档，
不能据此自称已安装、已实测或已部署。保持单次模型调用和原 4096 token 预算，
预算不足先删热评、简介及无关线索，再减少项目来源和字幕整句。
Cookie、密钥、本机路径和通知 URL 不进入模型上下文；评论、简介或模型提供的 URL 永不访问。
平台签发字幕 CDN 的受限读取见下文。
明显的命令/凭据/提示词窃取请求本地返回固定安全提示，不调用模型；所有模型输出再次校验。

每次生成前预留 4096 token，失败/取消不退款。文字预算用 UTF-8 输入字节上界、协议余量及
输出上限校验；附图另预留 1024 token，并相应压缩文字，仍共用 4096 总预留，默认 `dailyTokenBudget: 4096000`，即每天最多 1000 次付费模型请求。
这是一种保守的应用准入预算，不是 provider 实际账单统计；其他功能的 token 消耗独立。
预算耗尽时排队等待下一自然日，仍遵循 24 小时有效期。额度、安全提示不用模型。
不得将这里的 adapter 换成可以执行命令或读任意文件的桌面 Codex 会话。

### 视频上下文与事实检索

每个新请求通过固定 WBI 签名的用户资料 GET 查佩戴牌，核对 `mid` 与评论者 UID，
仅接受 `fans_medal.show=true/wear=true` 的佩戴快照。无直接主播 UID 时，以绑定目标用户
的数字 `detail.medal_id` 精确对照本账号牌墙目录中的 `medal_id → target_id`。
目录只解析主播，不借用本账号的佩戴状态；牌名只作一致性核对。
WBI key 缓存 5 分钟，牌子目录缓存 1 小时，目标用户佩戴每个新请求读取；
不遍历动态，隐藏、错 UID、目录缺少匹配或歧义按未知降级。
身份检查到点赞／生成之间保存快照，同一任务恢复时不重新抓取；以后新请求会重新读取，
因此换牌影响后续请求，不追溯修改已预留的用量。

正常模型回复另读固定 `/x/v2/reply?type=...&oid=...&sort=2&pn=1&ps=5` 的一页热评，
从 `hots/replies` 去重、排除鹿饼自身和本次原评论，按点赞数保留最多三条、每条最多 90 字。
只传正文与点赞数，不传热评作者资料或楼中楼；不访问其中链接。全部放在不可信 JSON，
仅帮助把握少量观众反应，不能当作共识、事实或指令，沉重氛围也不跟风攻击。
牌墙／热评单次响应最多 1 MiB、三秒、不重试、不跟重定向；普通失败降级，明确登录失效、
风控码或 HTTP 403/412/429 暂停整个消费者。热评与资料仍共用原 4096 token 预留，
预算紧时先移除热评，保留评论者信息及现有事实证据预算规则，不增加模型调用。

文字／转发动态评论区（业务类型 17）的每次正常模型回复，另通过固定
`/x/polymer/web-dynamic/v1/detail?id=<oid>&features=itemOpusStyle` 读取所属动态。
核对 `item.id_str` 与通知主体一致，只取作者显示名、发布日期、正文和内嵌的一层转发原文，
每段文字最多 400 字；优先 `module_dynamic.desc.text`，其次 `major.opus.summary.text`。
`itemOpusStyle` 于 2026-10-22 只读核对：缺少该参数时，图文转发原文可能只有图片而没有文字。
不读图片、不跟转发链接、不递归查更多动态，业务类型 1/11/12 不以主体 ID 猜动态 ID。
动态读取独立于录播检索，普通应援也能拿到当帖安排；传为不可信 `untrustedPost`，
`publishedDay` 只锚定该段原文的“今晚”等相对日期，不把旧安排自动认作处理当天的活动。
同样受三秒、1 MiB、无重试和平台阻断规则约束，普通失败降级为仅依据评论的回复。
动态与转发原文共用原 token 预留；预算不足先移除热评与相关资料，再整段移除转发原文，
必要时清除动态正文并标记 `partial`，不为了上下文扩大模型预算或拆造新原话。

可选的 `knowledge` 由本地可信配置指定录播问答配置、默认房间和最多三个联动关联房间。
示例启用岁己、弥月、犬绒、栞栞；名单是可检索的资料范围，不是任何一场活动的参与名单。
启用时要求共享只读 FTS 索引配置及房间均存在，启动检查不调用模型或平台接口。
`CommentKnowledge` 负责受限读取，`CommentContext` 负责日期、关键词和提示预算。

“总结/评价/回复一下这个视频”、事实问题、回忆与找梗请求先补证据；普通问好、应援等闲聊跳过检索。
视频评论中的纯艾特、“来看看”“你也过来”等简短召唤也读取目标字幕后给具体短评，
不要求用户先学会命令；同样的邀请在动态评论区不触发录播检索，也不扩大通知触发范围。
视频评论中“这个插件耗 token 多吗／这套技能费用高吗”同样先取目标字幕，
不以默认房间的录播替代插件说明。动态中的同一句话及询问鹿饼自身 token 用量不因此触发视频读取。
“回复一下这个视频”只取目标视频，不混入默认房间的无关录播。
视频按通知已验证的 aid 读取固定 `/x/web-interface/view`，验证回传 aid，拒绝重定向；
平台响应有 4 MiB 上限（可能包含整个合集），只保留标题、简介和首 P 的 cid/时长信息。
`CommentVideoText` 用固定 `/x/player/v2?aid=...&cid=...` 获取字幕，核对返回 aid/cid，
优先人工中文字幕，再自动中文，再单个其他语种；地址兼容 `subtitle_url` 和 `subtitle_url_v2`。
视频资料与字幕目录都使用完整浏览器 UA 和由可信 aid 构造的视频 Referer。
列出字幕但地址为空、普通网络失败或 CDN 地址失效时，按 v2 → wbi/v2 → v2
最多读取三次目录、最多下载两次字幕正文；字幕获取总时限九秒，单次请求仍限三秒。
不把空地址视为已读内容；若目录中的 AI 地址属于其他 aid/cid，跳过下载并在上述上限内重取目录。
返回身份不符、非法 CDN URL、错配时间轴立即弃用，登录／风控阻断不重试。
字幕目录响应限 512 KiB，正文限 1 MiB。
只允许平台返回的 HTTPS `aisubtitle.hdslb.com`、`i0/i1/i2.hdslb.com` 的
`/bfs/ai_subtitle/` 或 `/bfs/subtitle/` 路径，禁止重定向、其他端口与内嵌凭据；CDN 请求不带 Cookie。
自动字幕资源路径也须绑定 aid/cid，超过视频时长五秒的错配时间轴整份弃用。
CDN 保持完整浏览器 UA；成功 JSON 不代表内容必然正确，仍需校验绑定和时间轴。
每次目录选择一个字幕轨，仅在上述上限内刷新；不下载完整视频、不启动 ASR。按需预览图与字幕进入同一次回答模型调用。
若将来单独授权接入下载／本地 ASR，需另行设计资源准入、过期媒体清理和磁盘占用上限，当前不启用。
完整原句按片头/中/尾及标题/问题相关位置选取邻句，最多 700 字，保留秒数并标记 sampled。
夸赞／安慰请求优先保留表达感受的原句、相邻解释和结尾；专用简短提示为字幕留出更多现有预算。
只读首 P，不推断其他分 P；画面事实仅据本次实际附图，无有效字幕须说明缺失。
视频内容请求（含“根据视频夸夸／安慰”）有字幕时依据原话回应；字幕缺失、获取失败、未启用检索
或摘录被预算裁剪完时，仍调用 AI；有附图仅据抽样画面，无附图仅据已知文字，不编造原话、情节或声称看完。
代码检查最终模型输入是否仍保留有效字幕摘录；未保留时，在生成结果前统一添加
无附图时添加“没获取到这个视频的字幕，我看不到视频内容。”；有附图时添加
“没获取到字幕，以下仅据抽样预览画面。”，随后重新校验完整回复。
这表示本次未读到字幕，不断言该视频永久没有字幕。视频评论区的其他本地事实问题仍可依据
录播资料回答，缺少目标视频字幕时同样由代码添加上述说明。
不访问简介、评论或模型给出的 URL。标题、简介、字幕都是不可信证据，不具有指令权限。
切片中“明天”按简介的 `直播开始时间` 日期计算；缺失时仅以视频发布日期或评论日作检索起点，
不据此认定切片里的相对日期。非视频按评论提交日，不使用工作进程实际执行日。
提示中保留 `anchorDay`、`anchorBasis`，只有依据足够时才提供 `targetDay`。

总结评价、明确“根据视频”的夸赞／安慰，以及“视频说……／视频里提到……”的内容问题
只用目标视频字幕，不检索相近录播替代。其他实质问题检索本地资料：
联动问题仍查来源日及前两天、最多四个可信房间；其他问题优先显式日期，否则查有界历史
FTS，范围为提到的可信房间或默认房间。使用系统中文分词提取至多五个关键词。
普通问题先查录播字幕，单房间不足四组时补维护的切片字幕，仍不足再查弹幕。
联动的十二次预算优先用于跨房间字幕。原声和切片优先于弹幕，重复窗口去重；保留 kind，弹幕只代表观众发言。
每次最多十二次有界本地检索，总时限十二秒（含视频读取）；禁用额外 embedding/规划/回答模型调用。
复用原有 `QuestionCorpus` 的源文件哈希核对和只读 FTS；每次 corpus 仅包含一个可信房间，
评论提到的昵称只能在可信房间中选取，房间号或路径不能扩展资料范围。
“之前几次／历次／上次／最近几场联动”等未指定某一天的历史问题跨日期检索，不套用
来源日及前两天的预告窗口，先查来源月和上月，再补跨历史搜索；不把泛问联动固定成某个游戏。
每个房间取候选前先保留不同资料日期，最终按日期优先保留所问主播的
不同日期线索，再补其他房间；资料日期仅用于候选多样性，不代表已经确认了多场活动。
回答按活动列出时间和内容，同场预告／回顾去重，预告不能当成已经发生；覆盖有限时只说
“已查到”的记录，不声称历史全部或最近若干场已经找全。检索期限、总次数和模型预算不变。
视频及检索缓存分别最多 64 项、有效期 60 秒，后续更正不会无限缓存旧事实。
视频缓存只保留已读到有效字幕的结果，缺失或失败的字幕不会缓存六十秒阻碍后续获取。

候选按问题关键词排序，联动额外考虑人名与日期；保留跨房间原句与日期/时间，最多八组、每组最多 180 字。
带引号原话的定位请求优先用原话检索；例如“联动里说‘冰上’是啥时间点”不能退化为只搜
“联动/连麦”。未指定日期时检索有界历史 FTS，不只查来源日前三天；显式要求分析或定位
当前视频时，即使包含“联动”也只取目标字幕。命中片段优先保留原话及邻句，位置取最相关
字幕行附近；回复区分目标视频进度、带房间/日期的录播位置、切片内部位置和观众弹幕。
同音 ASR 只作为线索，不能单凭录播所属房间确认发言人；不同日期的联动不能强行合并。
较新的取消/改期优先，计划不代表实际到场；覆盖不全或无命中不等于“还没公布”。
明确的命令/路径/凭据文本不进入证据。模型仍仅收到一轮不可信 JSON 资料。
目标字幕先按问题相关性选原话及邻句，再补全片位置，最后恢复原顺序；避免先按时间顺序
装满 700 字而漏掉结尾的答案。单句超过 180 字则不截成半句证据。总预算不足时先移除简介，
再整组移除本地线索，最后按相关性减少目标视频原句并标为 partial/sampled，不任意删中间句。
若问题查的是历史录播而非当前视频内容，则优先减少目标视频字幕，尽量保留相关本地原话，
不让当前视频的旁支内容挤掉已找到的答案。
输入与输出仍受同一个 4096 token 预留约束，默认每日最多 1000 次调用不变。
检索失败或超时保留 coverage，允许依据已有资料回答，缺失部分明确说明。
视频读取返回明确登录失效/风控码或 HTTP 403/412/429 时暂停整个消费者，不继续调用模型或重试；
字幕目录及 CDN 的 HTTP 401 同样作为阻断。

内容获取和语气设计参考 [dsh-bilibili-reply 的 SKILL.md](https://github.com/bronyacccxz/dsh-bilibili-reply/blob/85a92410e41b2110920f7510446b79a9106b985b/SKILL.md)
及 `tools/bili-context.ps1`：免费文字资料优先，按视频类型组织回复。该外部 skill 是协议/设计参考，
未安装其浏览器控制、下载转写或 headless agent 流程；现有模型的权限、调用次数和预算不扩展。

视频图版另可参考 [dsh-video-storyboard](https://github.com/SAOS-3624/dsh-video-storyboard)：
场景检测后将带编号的帧拼成一张图，并保留逐格时间清单；局部放大单独取图。
它是资料组织工具，不是新的理解或 ASR 模型。本项目借鉴单图拼帧方式，使用原生
`CommentVisual` 适配器，不执行外部插件。已有目标字幕足以回答的问题先用字幕；显式画面问题，
以及缺字幕的当前视频概述、纯艾特等请求才补图。问候、功能说明、历史录播检索不补图。
不能让回复模型执行插件、下载任意链接或读任意路径。字幕中的费用是作者陈述，
不当成本项目的实测；DSH 的每图计费也不能直接套用当前 provider。
离线对照方法与图版限制见 [精剪指南](clip-precision-experiment.md#视频图版辅助取证)。

### 低 token 画面补证

`videoVision` 默认启用；设为 `false` 可关闭。固定 `/x/player/videoshot?aid=...&cid=...&index=1`
仅接受已验证目标视频首 P 的 cid/时长，目录限 1 MiB；索引必须有序且位于视频时长内。
最多选六格，包含首尾可用预览。跨超过两张大图的长视频改从首尾两张大图抽样，中间可能未覆盖。
仅下载目录签发、路径绑定 cid 的 HTTPS `bimp/i0/i1/i2.hdslb.com` JPEG；不带 Cookie，
拒绝重定向、内嵌凭据、端口和其他主机。每张限 2 MiB、解码限 2400 万像素、总时限五秒。
不读取 pvdata、不拉视频流、不做 ASR；内存合成 ≤504×220、≤96 KiB 的一张编号 JPEG，
最多缓存十六个结果六十秒，无文件写入。预览失败回退已有文字；平台登录/风控阻断仍暂停消费者。

模型仅收到一张 `detail: low` 的内联图片及 `visualPreviewSeconds` 近似秒数清单，仍是原来的
单次 `gpt-6-luna` 请求，不追加规划、放大或重试请求。图片单独预留 1024 token，文字预算扣除该值
和时间清单；base64 不作为文字计算。该预留是本地准入余量，不声称 provider 固定收取 1024，
也不采用 DSH 的每图计费。总预留仍为 4096，输出仍限 384 token / 300 字。
预览不是逐帧观看，首尾格不保证真实首尾，小字、快速动作、声音和人物身份不能凭预览确认。
图片文字也只是不可信证据，不能发出工具指令。没有保留字幕时由程序添加抽样画面说明。

### 回复的实用性与验收

参考上述 skill 的“知识类给信息、娱乐类接具体情绪”，以及
[Google Conversation Design 的错误恢复指南](https://developers.google.com/assistant/conversation-design/errors)
的具体说明缺口、给可行动下一步、避免重复和虚假承诺。外部材料仅作为设计参考。

- 解释先给结论，再给两三个依据；多问逐项回应，不能只有“好有意思”“很有节目效果”。
  评价说明哪句台词或哪处反差支持看法，常识解释与视频中已证实的事实分开。
- 找原话给可核对的位置和上下文；没命中先说明未定位，提供已有线索，只问一个必要缺口。
  不把其他录播时间写成当前视频跳转点，不把弹幕或 ASR 混声当本人原话。
- 项目比较给适用环节、条件、局限和一个验证建议，不能把文档描述说成已实测部署。
- 遇到“鹿饼有点……”“答非所问”，先接住质疑，不能用逗用户、卖萌或辩解代替修正。
  当前没有线程历史，必须依据本条明确更正或已有资料，不能假装记得之前的回复。
- 用户询问能力时，按启用的资料适配器说明能力并给两个提问例子；普通闲聊不附赠功能菜单。
  不承诺完整转写、看完整视频、记住上文或主动通知，也不机械索求关注或更多艾特。
- 仅应援分支携带名次反差规则，避免事实查询被无关人设细则干扰；沉重内容收住玩笑。

相邻回归测试覆盖分流、精确找句、晚段答案在两级预算裁剪后保留、来源时间分离、完整输入
预算和单次请求协议。注入模型的测试验证输入与协议，不证明模型实际文风；上线前的真人
评价或另行授权的离线模型评测仍需检查答题完整性、事实支撑、语气、下一步是否有帮助，
不能只用测试通过率或回复长度衡量改善。既有发布幂等、额度和风控门保持独立。

## 状态、恢复与启用

配置范例在 `config/comment-replies.example.json`，账号 UID 为鹿饼 `412141275`。
凭据与 provider 路径按仓库根目录解析，并使用统一的 `loadConfigLayers`。
Cookie 必须包含与 `botUid` 一致的 `DedeUserID`、`SESSDATA`、`bili_jct`；每次请求重读，
账号不符立即失败。配置路径、UID 豁免及预算只能由本地可信配置决定。

```powershell
# 默认命令仅离线检查配置，不轮询、不调用模型、不发评论
npm run bilibili:comment-replies -- --check

# 读取真实通知，在独立 preview 状态中演练队列；不用模型、不发评论
npm run bilibili:comment-replies -- --config config/comment-replies.example.json --dry-run

# 仅在获得账号自动回复启用授权后运行；这是持续的真实外部发言入口
npm run bilibili:comment-replies -- --config config/comment-replies.example.json --live

npm run bilibili:comment-replies -- --status
# 检查登录/平台限制并核实不明回执后，由操作员显式恢复；随后重新启动 --live
npm run bilibili:comment-replies -- --resume
```

`ecosystem.config.js` 中的 `shikamochi-comment-replies` 是独立、单实例的正式入口。
部署仍须获得自动回复启用授权：先通过 `verify:all`，将其 `build/service` 候选复制到
独立的 `dist/comment-replies/`，再执行下面命令；不要覆盖 webhook 的生产文件。
更新已有版本时先停止该消费者，确认锁释放，将旧目录备份到本次任务的忽略目录后再复制。
只启动指定进程，不运行整个 ecosystem，也不激活媒体 workflows。

```powershell
New-Item -ItemType Directory -Force -Path dist/comment-replies | Out-Null
Copy-Item -Path build/service/* -Destination dist/comment-replies -Recurse
node dist/comment-replies/tools/bilibili/commentReplies.js --check
pm2 start ecosystem.config.js --only shikamochi-comment-replies
```

PM2 对异常退出延迟十秒自动重启；正常退出使用 0，风控/未知回执/状态或配置异常使用 2，
两种退出码均不自动重启，不清除持久化暂停。通知读取退避在进程内进行。
Windows 停止使用 shutdown 消息，等待循环退出释放锁。首次启动后检查两类通知基线、
暂停状态及日志；确认健康后可用 `pm2 save` 保存进程清单。
`--check` 默认退出；`--live` 是持续发言开关。

Windows 登录自启可为当前用户创建独立任务 `Danmaku-Shikamochi-Comment-Replies`，
延迟三十秒执行当前 PowerShell 下的 `pm2.ps1 start <仓库>/ecosystem.config.js --only
shikamochi-comment-replies`。任务只启动该消费者，不复活整份 PM2 清单；暂停状态仍需
显式 `--resume`。创建该任务同样需要自动回复启用授权，不属于验证命令。

状态位于 `data/runtime/comment-replies/<botUid>.json`，演练使用 `<botUid>.preview.json`。
两者完全分开；演练不会消费正式队列、改变正式基线或扣正式额度。
状态包含待回复文本、每日计数、发送间隔及模型启动时间；日志不打印 Cookie、密钥或原评论。
不要公开状态文件。文件每次原子替换前 sync，持有独占 `.lock`，禁止第二个进程接管。
重启时仅在锁内账号吻合、PID 有效且操作系统明确确认该进程已结束时自动回收旧锁。
独占 `.lock.recovery` 串行化回收，并在持有该锁后重读当前所有者，防止并发启动删除新锁。
存活、无法检查、损坏或账号不符的锁均拒绝接管；残留的恢复锁仍需人工核实。
不能在运行中删锁或复制状态启动第二实例；回收旧锁不改变任务或暂停恢复规则。

发布前必须保存 `sending` 意图。进程崩溃或请求无明确回执时标为 `unknown`，保持终态，
不因重启或 `--resume` 再发；这种保守去重可能漏回一条，但不会因自动重试重复刷评论。
崩溃时处于 `generating` 的任务标为失败，不重复付费。已完成生成但未发送的 `ready`
回复可以重启继续发送，仍经过持久化的 5 秒门。损坏状态或账号不符会拒绝启动，
不会用空文件覆盖旧额度。

`--status` 只输出状态计数与每日预留预算。`--resume` 必须在消费者停止后使用，
它只清除暂停标志，不能重试 `unknown` 或失败任务。不要在未核实 B 站限制时反复恢复。

## Web 处理进度与记录

### 投稿视频反馈

视频评论继续只接受认证通知中的明确 @（`trigger=mention`）；普通点评既不回复，也不逐条交给模型分类。
可选 `feedbackOwnerUids` 指定我们的投稿账号 UID，省略或空数组关闭反馈收集。
固定视频接口核实 aid 与 owner UID；优先复用已获取的视频证据，仅缺少所有者时读取一次元数据，
该补充读取不取字幕。昵称、评论自称和模型返回值不能决定视频所有权。

自己的视频被 @ 时，在原有一次回答请求中同时输出公开回复和可选反馈。只收集评论者针对
选材、剪辑、字幕、声音、画面、标题封面等具体制作意见；正面意见也可收集，单纯评价主播、
游戏、剧情或泛泛夸赞不算。每条最多记录一个主要类别及不超过 60 字的连续原话，必须出现在
本次评论中；热评和字幕不得充当反馈。保留完整评论，后续复盘可重新分析多方面意见。
结构化元数据不公开发布；无效元数据丢弃，合法回复可继续。仍使用 4096 token 预留与
384 输出 token 上限，不增加分类调用、不自动总结或改动剪辑流程。
已经校验的纯制作反馈按用户描述回应，不机械添加缺字幕前缀，也不声称核实了画面或声音。
