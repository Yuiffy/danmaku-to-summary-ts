# `src/scripts` 目录约定

`src/scripts` 同时承载长期复用的工具、历史工作流和本地集成入口。为了避免目录继续
膨胀，新增脚本按下面的边界放置：

- `asr/`：ASR backend、队列、speaker 识别和字幕重处理。
- `clipping/`：跨工作流复用的切片能力、事件契约、资源调度和输出路径。
- `text/`：文本请求的共享传输适配器，重试与 JSON 规则由编译后的 `src/workflows/text/` 提供。
- `python/`：被 Node 工作流调用的 Python ASR/runtime 实现及其依赖文件。
- `reference_images/`、`test_data/`：测试或运行时需要随代码分发的静态素材。
- 根目录：稳定的历史 CLI、服务入口或仍被外部脚本直接引用的兼容入口。

新代码优先放进已有的职责子目录。只有在一个工作流已经有明确的 `main()`、测试和
迁移清单后，才把它迁入新的 `workflows/` 子目录；旧路径应保留薄包装，避免文档、任务
计划和外部调用突然失效。日期、机器路径、特定录音、一次性 benchmark 和专题素材统一
放在被 Git 忽略的 `temp/` 或 `local-scripts/`，不要混入公共模块。

同一任务的 Markdown 计划、实验/验收报告、交接记录、JSON 响应和截图也遵循这个规则，
统一放在 `temp/<日期>-<任务>/`。`docs/` 只维护通用说明，不归档单次任务过程；详细约定
见仓库根目录 `AGENTS.md`。可复用测试及其最小 fixture 继续随代码提交。

测试文件默认与被测模块相邻。跨模块的集成测试放在仓库的 `tests/`，而不是为了分类
把所有测试集中堆回 `src/scripts` 根目录。
